## 二、流程模型配置操作

### 1. 新增流程模型

进入“流程模型 → 新增模型”，填写流程模式、模型名称、模型 Key、流程分类和描述。

模型 Key 后端校验规则：

    ^[A-Za-z][A-Za-z0-9_-]{1,63}$

含义：

- 必须以英文字母开头
- 只能包含字母、数字、下划线和短横线
- 长度为 2～64 个字符
- 已发布或已挂起模型不允许修改 Key

实现位置：

    forge-server/forge-framework/forge-plugin-parent/forge-plugin-flow/
      src/main/java/com/mdframe/forge/starter/flow/service/impl/FlowModelServiceImpl.java

模型状态：

    0 - 设计中
    1 - 已发布
    2 - 已挂起
    3 - 已禁用

### 2. 业务流程表单配置

业务流程表单采用级联模式：

1. 选择业务应用
2. 选择该应用下的业务对象
3. 选择应用中实际配置的表单资产

前端调用链：

    businessApplicationList()
            ↓
    businessApplicationObjects(applicationId)
            ↓
    businessFlowFormAssets(objectCode, {
        includeInternal: true,
        applicationId
    })

接口：

    GET /ai/business/application/list
    GET /ai/business/application/{applicationId}/objects
    GET /ai/business/flow/form-assets/{objectCode}?applicationId=xxx&includeInternal=true

选择应用时会清空旧的业务对象和表单，避免出现“应用 A 的对象 + 应用 B 的表单”。

保存时，formJson 会保存完整表单引用：

    {
      "type": "BUSINESS_OBJECT_FORM",
      "formMode": "BUSINESS_OBJECT_FORM",
      "objectCode": "sample_purchase_order",
      "objectName": "采购单",
      "formKey": "app_1001_page_2001_form_3001",
      "formName": "采购单审批表单",
      "applicationId": "1001",
      "applicationName": "采购管理应用",
      "pageId": "2001",
      "pageCode": "purchase_apply",
      "pageName": "采购申请",
      "pageType": "FORM",
      "sourceFormKey": "purchase_apply_form",
      "viewKey": "default",
      "formRef": {
        "objectCode": "sample_purchase_order",
        "applicationId": "1001",
        "formKey": "app_1001_page_2001_form_3001"
      }
    }

保存前会执行：

- 自动补齐历史数据缺失的应用信息
- 检查是否选择了应用
- 检查是否选择了业务对象
- 检查是否选择了具体表单资产
- 不满足条件时阻止保存

相关方法：

    handleBusinessApplicationChange
    handleBusinessObjectChange
    handleBusinessGlobalFormUpdate
    normalizeBusinessGlobalFormBeforeSave
    validateBusinessGlobalFormBeforeSave

### 3. 节点表单与字段权限

流程全局表单用于发起流程，节点表单用于审批办理。

节点表单配置位于：

    forge-admin-ui/src/components/flow-designer/panel/ApproverConfig.vue
    forge-admin-ui/src/components/flow-designer/panel/PermissionConfig.vue

表单来源优先级：

    BPMN 用户任务节点配置
      formKey/formUrl/formJson/formFieldPermissions
    >
    ai_business_binding.binding_config.nodeForms
    >
    流程模型默认表单

新流程应优先在流程设计器节点抽屉中配置表单和字段权限。nodeForms 仅用于兼容历史配置。

字段权限包括是否可见、是否可编辑、是否必填和是否只读。业务表单保存时后端会再次根据节点权限过滤字段，不能只依赖前端隐藏字段。

## 三、审批人、审批动作与更多配置

### 1. 审批人类型

流程设计器支持：

- 固定用户
- 用户变量
- 发起人自选审批人
- 候选用户
- 候选组
- 多实例会签

发起人自选审批人的启动变量协议：

    {
      "PROCESS_START_USER": {
        "deptLeader": ["10001"],
        "financeApprove": ["10002", "10003"]
      }
    }

后端 InitiatorSelectedApproverSupport 负责从 BPMN 识别节点、校验审批人、生成单人节点变量 INITIATOR_SELECT_节点Key，并统一将审批人 ID 按字符串处理。

前端不得把雪花 ID 转成 JavaScript Number，应始终使用字符串。

### 2. 审批动作

    approve          审批通过
    reject           普通驳回
    rejectToStart    驳回至发起人修改路径
    return           退回上一审批节点或指定历史节点
    delegate         委派
    reassign         改派
    terminate        终结流程
    withdraw         发起人撤回
    claim            签收

主要实现：

    forge-server/forge-framework/forge-plugin-parent/forge-plugin-flow/
      src/main/java/com/mdframe/forge/starter/flow/service/impl/FlowTaskServiceImpl.java

### 3. “审批与待办”更多配置

原来放在模型基础弹窗中的审批退回和待办跳转，现统一移动到流程设计器右侧“更多配置 → 审批与待办”。

当前配置包括：

- 提交人是否允许撤回
- 是否允许指定节点驳回
- 待办跳转地址
- 自动审批模式

指定节点驳回由流程级配置 allowMultiReturn 控制，不再要求每个节点单独配置“允许退回”。

待办跳转支持：

    {taskId}
    {businessKey}
    {processInstanceId}

默认地址：

    /#/pages/todo-detail?taskId={taskId}

相对路径会自动拼接企业协同连接配置中的 H5 域名，完整 http/https 地址可直接使用。

数据库字段：

    sys_flow_model.todo_detail_url_template
    sys_flow_model.allow_multi_return

多级退回字段由 forge-server/db/mysql/migration/V1.0.134__flow_model_multi_return.sql 增加。

## 五、流程状态和回调

任务状态：

    0 PENDING    待办
    1 CLAIMED    已签收
    2 APPROVED   已通过
    3 REJECTED   已驳回
    4 DELEGATED  已转办
    5 CANCELED   已取消
    6 WITHDRAWN  已撤回
    7 RETURNED   已退回
    8 TERMINATED 已终结

业务单据状态：

    NOT_STARTED
    RUNNING
    IN_PROCESS
    APPROVED
    REJECTED
    CANCELED

状态同步不再只依赖 PROCESS_COMPLETED：

- TASK_CREATED：创建待办并修复业务状态
- TASK_COMPLETED：处理节点完成、驳回、审批结果
- ON_COMPLETED：业务单据标记已通过
- ON_REJECTED：业务单据标记已驳回
- ON_CANCELED：业务单据标记已取消

流程实例关联表会保存 business_key、process_instance_id、flow_model_key、flow_status、variables_snapshot。

驳回至发起人时会保存：

    FLOW_RETURN_SOURCE_ACTIVITY_ID
    FLOW_RETURN_TARGET_ACTIVITY_ID
    FLOW_RETURN_TO_START_PENDING

发起人修改后可以正常继续流程，也可以直接送回原驳回节点。

## 六、待办、已办列表性能优化

### 1. 原来的主要问题

    分页查任务
      ↓
    循环查用户姓名
      ↓
    循环查组织/角色
      ↓
    循环读取 Flowable 流程变量
      ↓
    循环查业务单据

任务数量一多，就会产生大量 N+1 查询。

### 2. 当前实现

FlowTaskMapper.xml 增加：

- TaskListColumns
- TaskListUserJoins
- TodoCandidateCondition

列表查询直接关联：

    sys_user
    sys_user_tenant
    sys_flow_model
    sys_flow_category

一次返回 assignee_name、start_user_name、process_name、process_definition_name、category_name。

待办、已办、我发起的查询都明确带：

    t.tenant_id = #{tenantId}

候选组匹配规则：

1. 当前用户是直接处理人
2. candidate_users 包含当前用户
3. candidate_groups 匹配当前用户有效角色 ID
4. candidate_groups 匹配当前用户角色编码
5. candidate_groups 匹配当前用户当前组织 ID

同时增加当前租户、有效用户、有效角色、角色组织范围限制；没有 activeOrgId 时不匹配候选组。

列表页不再对每条任务调用 runtimeService.getVariable(processInstanceId, "businessParams")，而是从 ai_business_flow_instance_link.variables_snapshot 批量恢复业务参数。

低代码场景使用 dynamicCrudService.selectByIds(configKey, recordIds)，代码表单场景使用 provider.buildSummaries(objectCode, recordIds)，查询粒度从“每条任务一次”变成“每个业务对象一批”。

### 3. 新增联合索引

迁移脚本：

    forge-server/db/mysql/migration/V1.0.135__optimize_flow_task_list_queries.sql

索引：

    idx_flow_task_tenant_assignee_status_create
    (tenant_id, assignee, status, create_time)

    idx_flow_task_tenant_assignee_status_complete
    (tenant_id, assignee, status, complete_time)

    idx_flow_task_tenant_start_user_create
    (tenant_id, start_user_id, create_time)

脚本通过 information_schema.STATISTICS 判断，支持重复执行。

### 4. JSqlParser COUNT 异常

报错：

    net.sf.jsqlparser.parser.ParseException:
    Encountered unexpected token: "("
    at line 1, column 13

根因是复杂待办 SQL 经过分页插件、租户拦截器和数据权限拦截器后，自动生成的 SELECT COUNT(*) 无法被当前 JSqlParser 稳定解析。

CountOnePaginationInnerInterceptor 统一转换为 SELECT COUNT(1)，不需要在每个 Mapper 中手工修改分页 COUNT。

本轮主要优化了 /todo、/done、/started。/candidate 仍保留 Flowable 查询后再按任务 ID 回查的兼容逻辑，如果候选任务量很大，可以作为下一轮优化对象。

## 七、待办列表如何扩展

### 1. 增加业务摘要和展示字段

推荐使用 FlowBusinessListDisplayAdapter，不要在流程核心模块中硬编码采购单、合同、请假单等业务。

接口位置：

    forge-server/forge-flow/forge-flow-client/
      src/main/java/com/mdframe/forge/flow/client/spi/FlowBusinessListDisplayAdapter.java

展示对象：

    forge-server/forge-flow/forge-flow-client/
      src/main/java/com/mdframe/forge/flow/client/spi/FlowBusinessListDisplayItem.java

扩展示例：

    @Component
    @RequiredArgsConstructor
    public class ContractFlowListDisplayAdapter
            implements FlowBusinessListDisplayAdapter {

        private final ContractMapper contractMapper;

        @Override
        public void enrich(List<FlowBusinessListDisplayItem> items) {
            List<Long> recordIds = items.stream()
                    .map(FlowBusinessListDisplayItem::getRecordId)
                    .filter(Objects::nonNull)
                    .distinct()
                    .toList();

            Map<Long, Contract> records = contractMapper.selectMapByIds(recordIds);

            for (FlowBusinessListDisplayItem item : items) {
                Contract contract = records.get(item.getRecordId());
                if (contract == null) {
                    continue;
                }

                item.setBusinessObjectName("合同");
                item.setBusinessSummary(contract.getContractName());
                item.setDisplayExtensions(Map.of(
                        "fields", List.of(
                                Map.of("label", "合同编号", "value", contract.getContractNo()),
                                Map.of("label", "金额", "value", contract.getAmount())
                        )
                ));
            }
        }
    }

推荐展示协议：

    {
      "fields": [
        { "label": "合同编号", "value": "HT20260001" },
        { "label": "金额", "value": "120000" }
      ]
    }

前端统一由 FlowTaskCardList.vue、FlowTaskBusinessSummary.vue 和 views/flow/utils/processDisplay.js 渲染。

列表页使用插槽：

    <template #summary="{ row }">
      <FlowTaskBusinessSummary :row="row" />
    </template>

不要在 Vue 的 v-for 中逐条请求业务详情。

### 2. 增加待办筛选条件

## 八、代码优先业务流程二开

适用于采购、合同、付款、请假等需要自定义 Service、状态机和业务副作用的复杂业务。

推荐目录：

    业务模块
    ├── domain/Xxx.java
    ├── dto/XxxDTO.java
    ├── dto/XxxTaskSaveDTO.java
    ├── vo/XxxVO.java
    ├── mapper/XxxMapper.java
    ├── resources/mapper/business/XxxMapper.xml
    ├── service/XxxService.java
    ├── service/impl/XxxServiceImpl.java
    ├── provider/XxxCodeFormProvider.java
    ├── support/XxxFlowDefinition.java
    └── support/XxxFlowBpmn.java

实现 BusinessCodeFormProvider 的核心方法：

    String providerKey();
    String providerName();
    List<Map<String, Object>> formAssets(String objectCode);
    BusinessTaskFormContextVO buildContext(...);
    BusinessTaskFormContextVO saveContext(...);
    Map<Long, String> buildSummaries(String objectCode, Collection<Long> recordIds);

Provider 负责注册表单资产、提供字段目录、构建待办/只读上下文、保存节点允许编辑的字段、批量构建列表摘要和校验业务状态。

业务 Service 负责创建单据、发起流程、保存节点字段、接收回调、修复状态和执行幂等副作用。

流程业务 Key 统一使用：

    <objectCode>:<recordId>

例如：

    sample_purchase_order:10001

## 十、审批动作二开
