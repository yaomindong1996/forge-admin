# 系统导航与菜单管理易用性优化

## 范围与基线

- 用户要求去掉业务工作台父菜单灰底、更换多个系统页组织树图标、取消公共表格主值加粗，并简化菜单管理。
- 基线 `92997659`，当前分支 `codex/workbench-illustrations`；只改前端，保留用户 `.DS_Store`。
- 复用已归档 system-management-ui-interaction-fixes 与 layout-theme-consistency 测试，不重建已有验证。

## 设计与行为

1. 工作台父菜单的选中、打开、悬停保持透明背景，靠文字与可配置横条反馈；统一基础与覆盖样式，
   不改租户保存的其它控件背景，不影响下拉菜单项的交互底色。
2. 组织树统一线性语义图标：顶层组织、分支组织、叶子组织分别可辨；用户/组织/岗位/角色/人员选择复用解析，
   公共树的展开箭头和默认图标同步线性化，保留用户自定义图标与原选择/勾选/展开协议。
3. SystemTableCell 主文字改为常规字重，保留主辅文本层级、详情点击、头像和 +N 关联浮层。
4. 菜单管理默认两栏，左侧结构、右侧当前层列表；详情用按需 Naive UI 抽屉，不再持续占第三栏。
   名称可进入下级，面包屑可回上级；编辑和详情直达，原删除/迁移/复制等能力保留。
5. 搜索保持直显，类型/状态筛选收进可重置浮层；勾选后才显示批量动作，并允许清除选择。
   保留默认直属子项、筛选当前范围递归、跨层选择/刷新回绑、删除拦截与确认等旧规则。
6. 多面板 UI 状态使用领域 Pinia store，新增导航编排用独立 composable；详情抽为同域组件，
   不继续往 1227 行历史 composable 堆新逻辑，必要局部提取使其缩短。
7. 动态组织/资源图标进入既有构建 safelist，懒加载组织分支按 hasChildren 保持语义；
   菜单列表文字操作遵循项目轻量操作区规范，浅/深色表面统一读取 Token。
8. 新增顶级菜单显式使用 parentId=0，不误继承当前目录；原新增子项、编辑和提交协议不变。
   清理历史拆分残留的未用依赖与重复私有方法注册，保留跨 part 延迟转发和顶层公开接口。

## 边界、风险与回滚

- 不改后端接口、权限、字典或资源存储码，不新增依赖、SQL；不执行线上菜单写入或真实身份操作。
- 详情抽屉编辑/新增/删除沿用旧处理函数；批量迁移/删除保留原确认与校验，测试只用模拟请求。
- 旧 giant composable 本轮只收敛本次触及的树展示职责，其余 CRUD/表单职责后续渐进拆分，不能宣称整文件达标。
- 回滚本提交即可恢复原界面，不涉及数据迁移。
- 完成后自动本地提交；不自动合并 main 或 push，新请求另行授权。
