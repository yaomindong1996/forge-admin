# 企业协同连接配置体验优化

## 背景

`/collaboration/connections` 将连接基础信息、平台应用、能力绑定拆成多个技术弹窗，用户难以判断配置顺序、完成状态和下一步操作。列表同时平铺大量技术字段和操作，编辑表单还要求用户直接理解组织 ID、连接编码、目录权威等概念。

## 目标

- 让用户按“连接基础信息 → 平台应用 → 启用能力”的顺序完成配置。
- 在列表中优先展示连接、主要用途、配置状态、运行状态和最近更新时间。
- 用业务文案和依赖显示降低理解成本，避免输入组织 ID 等技术值。
- 保持现有后端接口和数据结构兼容。

## 功能要求

### 连接列表

- 平台、连接名称、连接标识合并为一个连接信息列。
- 展示主要用途和保守的基础信息状态，不把列表摘要误报为完整可用状态。
- 直显“配置、测试”两个高频动作，其余操作进入更多菜单。
- 连接名称可直接打开配置。

### 连接编辑

- “连接编码”改称“连接标识”，已有连接不可修改。
- “企业 ID”“连接类型”“身份匹配策略”“目录权威来源”改为业务可读文案。
- 同步目标使用组织树选择器，雪花 ID 保持字符串传输以避免精度丢失。
- 默认角色只在自动创建用户时显示。
- 待办地址只在待办推送开启时显示。
- 自动同步和同步频率只在外部通讯录同步场景显示，频率只在自动同步开启后显示。

### 连接配置

- 使用统一配置面板展示平台应用和已启用能力。
- 明确显示当前配置阶段和下一步提示。
- 平台应用支持新增、编辑和删除；敏感凭据不回显，编辑留空保留原值。
- 能力支持选择平台应用后启用，以及停用已有能力。
- 平台应用和能力为空时显示明确空状态。

## 非目标

- 不修改后端 API、数据库结构或凭据存储策略。
- 不改变同步、消息投递、OAuth 和能力绑定的业务语义。
- 不在本轮实现 Cron 图形化编辑器。

## 验收标准

- 新建或编辑连接时，依赖字段按当前选择正确显示。
- 配置入口可以完成平台应用和能力的全部既有操作。
- 停用、缺少企业标识、基础信息完整等列表状态可区分。
- 页面主文件不超过 800 行，复杂弹窗拆为领域组件。
- 目标 ESLint、Vitest、前端构建和 `git diff --check` 通过。
