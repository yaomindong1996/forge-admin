# 移动端低代码多端运行时与视觉重构 Spec

> 变更名：`mobile-lowcode-multiplatform-runtime`
> 分支：`codex/mobile-lowcode-runtime-refactor`
> 状态：`implemented-awaiting-real-e2e`
> 创建日期：2026-09-20

## 实施状态

当前实现已落地统一组件注册表、Wot Design Uni 适配层、共享字段/布局渲染器、远程选择器、复杂表格/树的移动卡片交互、日历、水印、真实条码/二维码、审批主子表权限、动态数组、独立入口参数透传，以及 H5/小程序网络与上传适配。普通运行页和审批页均已拆到 800 行以内，并通过定向单测与双端生产构建。

代码阶段已完成，状态保留为等待真实环境 E2E：仍需使用已发布低代码配置、真实流程任务、文件服务和小程序合法域名验证完整业务链路。动态 Vue/脚本和不可信 iframe 继续按安全策略明确阻断，不会降级成可编辑文本框，也不会改变后端协议。

## 1. 背景与问题

Forge 已经具备管理端低代码设计器、发布态动态 CRUD、业务对象流程绑定、任务表单上下文和 H5 低代码运行页，但移动端仍存在以下问题：

1. `forge-h5-ui` 页面视觉与基础控件由原生 uni-app、uview-plus 和自研 `Ai*` 混合实现，主题变量不统一。
2. 管理端组件协议覆盖字段、布局、业务组件、页面挂件、媒体和动作组件，移动端只实现少量字段类型；未知字段会回退为普通输入框，存在错误编辑和错误提交风险。
3. `lowcode-runtime.vue` 和 `todo-detail.vue` 分别维护运行页与审批页逻辑，组件解析、权限、只读态和校验能力容易漂移。
4. 已发布低代码应用既可能通过应用门户进入，也可能以独立页面直接挂载；移动端需要共享同一运行内核，不能复制一套协议。
5. 审批动态表单需要同时遵守 BPMN 节点字段权限、业务对象主子表权限、动态数组权限和已办/历史只读规则。

## 2. 目标

1. 后端继续返回现有 `modelSchema/pageSchema/editSchema/options/formDesignerSchema` 协议，不增加移动端专用业务协议。
2. 建立移动端组件注册器和能力清单，按同一个 `componentKey/type` 映射到移动渲染实现。
3. 采用 `Wot Design Uni` 作为新的移动视觉基础库，保留 `Ai*` 作为 Forge 稳定适配层，页面和协议不得直接耦合第三方组件属性。
4. 低代码普通运行页、审批任务动态表单、已办/历史表单和独立挂载页面共享字段解析、权限、校验和渲染内核。
5. 覆盖设计器登记的全部组件键：支持完整交互的组件正常编辑；受移动平台限制的组件必须安全降级并明确提示，禁止错误回退成文本输入框。
6. H5 与微信小程序作为首批强制构建目标；其他已配置小程序平台按能力矩阵逐步验证。
7. Snowflake ID、业务 Key、任务 ID 和用户 ID 在前端始终按字符串处理。

## 3. 非目标

1. 不修改后端动态 CRUD、流程启动、任务保存和审批动作的 URL 或 payload 结构。
2. 不建立第二套流程节点表单配置 UI；字段权限仍由真实流程设计器写入 BPMN。
3. 不允许移动端执行低代码配置中的任意 JavaScript、Vue SFC、脚本 URL 或未受信 HTML。
4. 不承诺 iframe/web-view 在所有小程序平台无条件可用；它受平台域名白名单和审核规则限制。
5. 本变更不重做管理端设计器视觉。

## 4. 总体架构

```text
发布态统一协议
  modelSchema / pageSchema / editSchema / options
                      │
                      ▼
          Mobile Schema Normalizer
  类型别名、默认值、权限、联动、数据源、字符串 ID
                      │
                      ▼
          Mobile Component Registry
  字段 / 布局 / 业务 / 页面挂件 / 媒体 / 动作
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
 普通低代码运行页             审批任务表单
 列表/新建/编辑/详情       待办/已办/历史/动态数组
          └───────────┬───────────┘
                      ▼
             Forge `Ai*` 适配层
                      ▼
              Wot Design Uni
                      ▼
               H5 / 小程序
```

协议只描述语义，不描述 `wd-*`、DOM 或小程序私有属性。第三方组件的差异全部收口在 `Ai*` 和移动渲染器中。

## 5. 组件支持策略

每个组件键必须注册明确能力等级：

| 等级 | 含义 | 运行时行为 |
|---|---|---|
| `interactive` | 移动端完整交互 | 可编辑、校验、提交 |
| `adapted` | 按移动交互重新编排 | 例如 PC 表格转卡片列表、抽屉转底部弹层 |
| `readonly` | 可安全展示但不编辑 | 展示格式化值并说明限制 |
| `blocked` | 移动端禁止执行 | 显示明确的“不支持”占位，不执行脚本或不可信内容 |

### 5.1 字段组件

- 第一优先级完整交互：`input`、`textarea`、`number`、`money`、`select`、`dictSelect`、`radio`、`radioButton`、`checkbox`、`switch`、`date`、`datetime`、`month`、`year`、`daterange`、`datetimerange`、`timerange`、`fileUpload`、`imageUpload`、`barcodeScanner`、`signature-pad`。
- 第二优先级移动适配：`slider`、`rate`、`color`、`transfer`、`cascader`、`treeSelect`、`customSelect`、`userSelect`、`orgTreeSelect`、`regionTreeSelect`、`objectReference`、`recordSelector`、`array/subTable`。
- `text` 只读展示，不允许伪装成可编辑输入框。

### 5.2 布局与业务组件

- `grid/col/space/box/card/tabs/collapse/divider/spacer/groupTitle/formSectionTitle` 在窄屏自动单列或横向滚动。
- `table/AiTable/data-table` 在手机端默认适配为卡片列表；只有字段很少时才使用横向表格。
- `AiCrudPage` 映射为移动列表、筛选、卡片、分页和表单页面状态机。
- `subTable/sub-table-tabs` 映射为明细卡片列表和底部弹层。
- `tree-panel` 映射为全屏/底部树选择器，不与右侧表格并排。
- `step-form` 映射为纵向步骤表单。

### 5.3 页面挂件、媒体与动作

- 标题、段落、提示、标签、统计、公告、描述列表、时间线、步骤、空态等采用移动原生布局。
- 音频、视频、头像、条码、二维码采用 uni-app 对应能力；缺少资源时显示空态。
- `html-tag/custom-html/rich-text/markdown` 只渲染经过安全处理的内容，禁止脚本和事件属性。
- `vue-component` 和任意脚本组件为 `blocked`，不得在移动端动态编译或执行。
- `iframe` 在 H5 可按白名单策略展示；小程序降级为 `web-view` 或外链提示。
- 查询、重置、新增、导入、导出和业务动作通过统一动作分发器执行，并继续校验权限。

完整清单见 `component-matrix.md`。

## 6. 审批动态表单

1. 待办加载继续使用 `GET /ai/business/flow/task-form-context`；已办/历史继续使用只读上下文接口。
2. 表单资产解析优先级保持：BPMN 节点配置 > 业务绑定兼容配置 > 流程默认表单。
3. 移动端只渲染节点 `readable=true` 字段；仅允许 `writable=true` 且当前任务可办理的字段编辑。
4. 主子表和动态数组继续使用现有 v2/v3 权限协议；新增、修改、删除权限分别判断。
5. 手工暂存继续调用现有任务表单保存接口；最终办理通过业务任务动作接口原子提交表单数据和流程动作，服务端重新校验权限，前端不提交权限声明。
6. 审批按钮、必填意见、退回、驳回、委派等能力来自现有 `flowInteraction` 和任务动作配置。
7. 已办、历史和终态记录强制只读，仍完整展示附件、签名、主子表和流程时间线。

## 7. 独立挂载页面

1. `app-entry`、应用门户菜单和直接 URL 最终都进入同一个移动运行时路由。
2. 页面通过 `configKey/objectCode/pageKey/recordId/mode` 确定运行上下文，不复制页面实现。
3. 独立页面可配置是否显示 Forge 导航栏、返回按钮、标题和底部安全区。
4. 页面模式覆盖 `list`、`form`、`list-form`、`detail`，并兼容旧配置未声明模式的情况。
5. 页面卸载时取消字段事件请求、定时器和媒体资源，避免返回页面后重复执行。

## 8. 视觉与组件库迁移

1. 新增统一 Design Tokens，覆盖主色、语义色、文字、表面、边框、圆角、间距、阴影和安全区。
2. `Wot Design Uni` 仅在适配组件内部使用；现有页面优先保持 `Ai*` API。
3. 先迁移按钮、输入、选择、弹层、卡片、空态、上传和签名，再迁移页面。
4. 迁移期间允许 uview-plus 与 Wot 并存；完成所有适配和双端构建后再删除 uview-plus。
5. Wot 官方建议 Sass `<=1.78.0`，因此依赖变更必须在本分支固定兼容版本并执行 H5/微信小程序构建。

## 9. 安全和兼容性

- 未注册组件不允许回退成可编辑输入框，默认 `blocked/readonly`。
- HTML、Markdown、外链、媒体 URL 必须经过协议白名单和安全处理。
- 动态组件不得使用 `eval`、`new Function`、运行时模板编译或远程脚本。
- 所有动作继续经过权限检查；导入、导出和流程动作不得仅靠按钮隐藏控制。
- 流程写操作携带与管理端一致的 `idempotencyKey` 和 `requestDigest`，防止认证刷新或网络重试导致重复办理。
- 字段联动只允许声明式规则和已登记数据源，不执行配置中的表达式脚本。
- H5 和小程序差异通过条件编译与能力注册处理，不污染后端协议。

## 10. 验收标准

1. 同一发布态配置可在管理端和移动端加载，不新增移动专用业务协议。
2. 移动端组件清单覆盖设计器登记的全部组件键；未知组件有明确占位，不误编辑、不误提交。
3. 普通低代码列表、新建、编辑、详情和主子表可在 H5、微信小程序构建通过。
4. 待办动态表单遵守字段和行权限；已办/历史强制只读。
5. 签名、附件、图片、扫码、日期、人员/组织、区域、关联记录和动态数组具备移动实现或明确安全降级。
6. 独立挂载页面、应用门户入口和流程任务页复用同一渲染内核。
7. 主题、按钮、表单、卡片、弹层、空态和底部操作区视觉统一。
8. `lowcode-runtime.vue` 与 `todo-detail.vue` 的共享解析/渲染逻辑下沉，文件规模逐步降至 800 行以内。
9. 定向单测、`pnpm build:h5`、`pnpm build:mp-weixin` 和 `git diff --check` 通过；真实服务 E2E 若环境不具备必须如实记录。

## 11. 发布与回滚

- 分阶段发布：注册器与兼容层 → 核心字段 → 审批表单 → 页面挂件 → 全站视觉。
- 每一阶段均保留旧 `Ai*` API；出现平台兼容问题时可按组件回退，不回滚后端协议。
- Wot 与 uview-plus 并存期间不得在业务页直接新增第三方组件引用。
- 最终移除 uview-plus 必须单独执行全量页面回归，不与首批渲染器改造同批删除。

## 12. 全站商务视觉改造

1. `forge-h5-ui` 全部生产页面统一使用蓝、白、黑、灰色系；成功、警告、危险色只用于真实业务状态，不作为装饰色。
2. 页面采用“灰色工作区背景 + 白色业务面板 + 浅灰边框 + 蓝色主操作”的企业移动工作台结构，禁止渐变、霓虹光斑、毛玻璃、持续漂浮动画和重阴影。
3. 顶部栏、页面标题、搜索筛选、数据列表、表单区块、弹层和底部导航统一密度、边界及安全区；一个区域只保留一个主操作。
4. 首页保留真实待办、未读消息、授权应用和最新提醒，不增加营销文案或虚假指标；应用入口统一为中性色图标容器。
5. 登录页改为企业账号入口：品牌信息克制，表单居中，控件和按钮使用标准矩形小圆角，不使用扫光、漂浮背景或装饰网格。
6. “我的”页面使用紧凑账户摘要和分组设置列表；头像、租户、安全、设置等入口不再使用随机彩色块或渐变背景。
7. 消息、待办、审批详情和低代码运行页使用相同的顶部栏、筛选控件、卡片、状态标签与底部动作规范。
8. 公共页面组件负责全站视觉规则，业务页不再各自复制背景特效；生产页面单文件继续遵守 800 行限制。
