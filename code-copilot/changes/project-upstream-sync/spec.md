# 改名工程的社区基线同步

状态：实施中；2026-10-11。日常开发，不正式发版，社区 revision 保持不变。

## 授权与范围

用户确认初始化独立的完整底座工程，包名与 Maven 坐标改名，建立源码增量同步及版本基线。
社区仓库仅增加通用生成/同步工具；新产品身份、私有代码和环境配置仅留在独立工程。
不提交或推送社区改动，不部署服务，不操作现有业务库。

## 设计

- 生成源必须为准确的社区 Git 提交；不携带社区工作区的未提交文件、旧部署配置、历史变更或密钥。
- 复用现有生成器；精简交付模式去除无关文档/运维脚本，保留源码、测试、许可证、必要开发规范、
  数据库初始化/迁移、版本和插件工具。不得删除功能运行所需资源。
- 记录社区 commit/version、完整生成选项、冻结的命名转换工具及其摘要。
- 将规范化社区输出作为独立 Git 基线提交；初始产品提交以它为祖先。
- 升级先 plan：从指定本地社区仓库的提交导出干净源码，使用冻结映射生成候选基线，报告文件差异。
- apply 仅允许干净的非 main/master 升级分支，执行 Git 三方合并并停在待审查/待提交状态。
  无论有无冲突均不自动推送；merge commit 使后续克隆能恢复社区基线历史。
- 数据库已存在的 migration SQL 若变更或删除，拒绝同步；不运行 repair、不自动执行数据库更新。
- 企业专属目录、环境配置和同步元数据不由上游生成物覆盖；公共文件的本地修改参与三方合并。
- 产品版本与社区版本分别记录，不能因产品升版而覆盖社区 commit/version。
- 修复旧包名替换误命中新包名前缀；POM groupId 与 mainClass 分别按坐标与 Java 包名处理。

## 新工程与新数据库安全

- 新目录必须不存在或为空，不覆盖已有项目。
- 明确目标为用户确认的新库；先只读检查不存在，再创建。禁止 --recreate、DROP DATABASE 或清空旧库。
- 初始化与清理只作用于本轮新建库；保留默认租户/管理员及必需菜单字典，清除导入演示和运行数据。
- 初始化属于新库的权限/身份种子写入，用户已确认新建独立库；不得扩大到原数据库或生产权限。
- Redis 使用独立逻辑库/键前缀，认证 token 与浏览器存储也隔离。
- 凭据只进入忽略的本地配置，不能写进文档、基线或提交。失败保留新库便于诊断，不自动删库。

### 2026-10-11 用户补充确认

- 新工程 Redis 使用 localhost:6379 的独立 15 号库，Spring Redis、Redisson 与 Sa-Token 保持一致；
  基础配置及 Docker 示例不得回退到社区默认 0 号库。此次仅修改配置，不连接或清空缓存。
- 用户选择先启用 MySQL TLS、暂缓真实建库；保留本地 JDBC 强制 TLS，禁止改明文连接。
  本轮不修改远端 TLS 配置、不执行 SQL、不启动可能触发迁移的服务。
  后续待 TLS 准备完成并确认继续后，再执行原新库存在性核对与初始化流程。

## 验收

- 改名后的后端编译、前端构建、版本一致性检查通过。
- 单测覆盖同步预览、三方合并、冲突、工作区保护、路径/符号链接、历史 SQL 保护及产品独立版本。
- 新库具有有效迁移记录、唯一默认身份、无演示低代码/流程数据；原库不受写操作。
- 生成工程具有独立 Git、清晰 README/开发规范及准确基线，未来无需重新生成覆盖工程。
- 真实连接或构建不可用时如实记录未完成项，不以模拟通过代替。
