# 系统版本统一与用户可见入口

## 目标

以现有根 POM `revision=1.2.0` 为版本基线，用户能在 PC/H5 查看真实运行版本。
用户已确认实现；当前 main 开发，保留 `.DS_Store`，不自动提交、推送或部署。

## 范围与协议

- 根 POM 为宿主发行版本权威源，提供前端包版本同步与校验命令；不改历史 Git 标签。
- Admin/H5/Report 构建读取同一版本，生成随产物携带的前端版本、构建时间与 Git 标识。
  同时输出前端 `version.json`，不含服务端或环境信息，避免未消费全局常量的独立端丢失元数据。
- 复用 Spring Boot Maven 插件生成服务端 build-info，不新增第三方依赖。
  服务端 Git 标识可由构建属性 `-Dforge.build.commit` 提供；未提供时明确未知，不能借前端提交号冒充。
- System 插件提供 `GET /system/version`，Admin 与 App 共用。必须登录，普通用户可读，
  仅提供发行/核心版本、产品类型、服务名、构建时间、可选提交标识；不返回主机、路径、配置、插件授权明细。
  该只读自助接口不要求插件管理权限；保留登录鉴权，不开放匿名路径。
- PC 头像菜单及无顶栏布局的账户工具增加“关于系统”，全局共享 Pinia 状态、统一 Naive UI 弹窗。
- H5 我的新增“关于系统”，使用现有 Wot 封装弹层。显示独立的前端/后端版本，错误可重试。
- 构建不一致只提示核对，不阻断业务；后端失败/旧版 404 不得用前端版本兜底为后端。
- 随前端构建携带本版本 CHANGELOG 内容，以纯文本呈现，明确其属于前端发行说明。
- 本轮不建部署历史表、不自动检查更新、不在线升级、不推测数据库版本，不把构建时间当部署时间。
- 源码工程（含改名工程）保持可构建；必要时扩展版本脚本路径识别，不重置项目/数据库。

## 验收

1. 同一版本来源用于前端构建/版本检查；版本漂移校验失败，可显式同步。
2. 普通登录用户可查，匿名拒绝；缺失 build-info 明确未生成，不影响应用启动。
3. PC 各布局与 H5 入口可打开、刷新、复制非敏感版本信息；窄屏不溢出。
4. 单测、针对性构建与页面预览验证；无需连接真实数据库或部署生产。

## 回滚

回退本次源码/产物即可，无数据库或迁移历史变更。发布标签与旧包不覆盖。
