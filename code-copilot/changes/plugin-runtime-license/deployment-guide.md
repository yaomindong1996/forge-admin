# 客户项目运行时许可证接入

本模块是 `forge-starter-plugin` 中可移植、默认关闭的离线授权扩展。
门户网站负责人工签发；客户工程持有公钥和签名文件，不应接触签发私钥。
独立 Pro 工程品牌和包名未确定，本轮不创建或重命名工程。

## 部署配置

将可信渠道交付的 Ed25519 X.509 公钥 PEM 和许可证 JSON 放入工程外部的普通文件。
文件不能是符号链接；不要将客户许可证提交到公共仓库。

```yaml
forge:
  license:
    enabled: true
    customer-id: "客户账号的数字ID"
    installation-id: "项目固定的小写UUID"
    files:
      - /opt/customer/license/license-one.json
      - /opt/customer/license/license-two.json
    public-keys:
      forge-2026-01: /opt/customer/license/forge-2026-01-public.pem
```

项目安装 UUID 只生成一次并持久化，格式为标准小写 UUID。同项目多节点共用此标识，不绑定 IP/MAC。
客户 ID 使用签发账号的数字 ID，不是用户名。不同项目需独立标识和授权；不能依赖节点启动时随机值。
`key-id` 与网站签名文件一致，公钥应固定在受信任部署配置中，不能相信签名文件指定的下载 URL。
公钥轮换保留旧 ID 映射，避免旧的永久许可证因丢失公钥无法验证。

## 功能接入

沿用现有 `FeatureGate` 和 `@RequiresFeature("ee.xxx")`。
购买插件的描述声明精确功能范围，受保护的业务入口必须使用对应的 Gate/注解。
普通 RBAC、租户鉴权、业务状态校验仍需保留；商业许可证不替代这些权限控制。
如果新插件未接入 Gate，其业务逻辑不会仅因新增一个许可证文件自动被保护。

开启时：先验原始 payload 字节签名，再解析严格 JSON 和绑定；不会用重序列化结果替代验签原文。
未知公钥/算法、篡改、重复键、未知字段、字符串冒充数字、超限文件均拒绝。
文件最多 32 KiB、载荷最多 16 KiB；最多 100 份许可证和 10 份公钥配置。
多个有效许可证按精确功能合并，不支持通配符；单份无效不会使其他有效许可或社区功能失效。

自动配置优先于社区默认 Gate，但用户自定义 `FeatureGate` 优先，不自动组合两个自定义实现。

## 插件中心授权诊断

升级客户工程后，由 Admin 的 Flyway 执行尚未执行的
`V1.0.215__add_runtime_license_diagnostics_dict.sql`，保留原迁移历史。
本迁移只增加中文诊断字典，不调整菜单位置、不自动授予角色权限。

平台超级管理员进入“插件中心 → 运行时授权”，查询当前后端实例的实际 Gate 模式。
许可证模式显示合法配置绑定、公钥加载数量、启动时间，以及按文件配置顺序排列的状态、授权范围和期限。
文件无效或绑定不符时不展示其声明的许可证 ID、范围或期限；页面不返回文件路径、签名或密钥。
接口为 `GET /system/plugin/runtime-license/status`，复用 `system:plugin:list` 并额外限制平台超级管理员。
租户管理员即使持有通配权限也不能查看全实例授权；许可证已失效仍可以查询诊断。

刷新状态只重新判断当前使用期限，不读取文件、不访问授权服务器。
修改文件、公钥、账号或项目标识后应重启对应节点，再核对启动加载时间。
“文件无效”需要在服务器按序号检查文件、公钥、格式和签名；不要将原文件或凭据粘贴到日志或公共工单。
社区模式不放行商业功能；自定义 Gate 不由此页判定文件验签结果，需核对自己的实现。
维护期限与使用期限仍独立，诊断状态不代表源码下载权益，也不取代实际业务入口的 Gate 和 RBAC 校验。
默认不开启，不读取授权文件；关闭开关会恢复社区默认 Gate。

## 期限与撤销

- 使用期限与维护/源码下载期限分离，使用截止为 null 表示永久。
- 启动加载文件，每次 Gate 查询检查当前 UTC 时间；运行中到期也会关闭相应商业功能。
- 维护到期不停止已授权永久使用，源码下载权益由网站原权益系统单独控制。
- 文件或公钥更新后需要重启。离线验证不查询授权服务器，也没有自动心跳。
- 网站撤销只停止平台再次下载并留痕，不能即时使已交付离线文件失效。
- 源码交付不能承诺不可破解，系统时间与部署环境由客户控制；签名用于防伪造授权。

## 部署验收

1. 网站管理员完成 V32 迁移和私钥配置，给指定运营人员授权后，基于真实企业 ZIP 人工签发。
2. 客户登录门户的“我的运行时许可证”，下载本人文件，不通过管理员 Token 下载。
3. 配置正确账号、项目 UUID 与公钥，验证对应 `ee.*` 功能及原 RBAC 校验。
4. 检查错账号/项目、公钥、篡改、未来开始与过期均不放行；维护到期的永久许可仍可运行。
5. 同项目两个节点使用同一绑定；新增项目独立签发，不复用另一个项目的安装标识。

本轮测试只使用临时真实 Ed25519 密钥和合成数据，不生成生产私钥、不发放实际客户授权、不执行部署。
