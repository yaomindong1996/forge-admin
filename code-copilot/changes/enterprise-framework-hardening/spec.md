# Forge 企业级框架能力加固 Spec

> 变更名：`enterprise-framework-hardening`  
> 状态：`in-progress`  
> 创建日期：2026-09-05  
> 实施方式：后续按 `tasks.md` 分阶段执行  
> 范围声明：本变更只处理企业级安全、可靠性、可观测性、数据治理、交付质量和部署能力；明确排除 `forge-plugin-generator`、`lowcode`、代码生成器、表单设计器及低代码运行时能力。

## 1. 背景

对 `forge-server`、`forge-admin-ui` 认证与请求基础设施以及两套 Docker 部署定义进行审查后，发现框架已具备 RBAC、多租户、API 加解密、幂等、文件存储、操作日志和部分持久化加密能力，但企业生产所需的安全边界、密钥治理、账号风控、服务可靠性、灾备、可观测性和质量门禁尚未形成统一闭环。

已确认的高风险问题包括：开发配置和部署脚本存在明文凭据；滑块验证码只信任客户端 `verified` 字段；Undertow 请求体大小无限制；AI prompt/completion 日志可能泄露业务数据；Actuator 缺少指标、Tracing 和告警；Maven 默认跳过编译与测试；`docker/` 与 `docker-forge-admin/` 配置漂移；API 配置刷新缓存存在失效路径；全局异常多数没有映射正确的 HTTP 状态码。

## 2. 字段级加密与脱敏现状结论

### 2.1 已有能力

1. `forge-starter-crypto` 提供 `@CryptoField`、`CryptoFieldSerializer` 和 `CryptoFieldDeserializer`，可在 Jackson JSON 边界按字段调用 `EncryptorFactory` 的 SM4、AES 或 AES-GCM 实现。
2. `CryptoProperties.enableFieldCrypto` 默认开启，并有 `enableApiCrypto`、`enableDesensitize` 等总开关。
3. `@Desensitize` 提供手机号、身份证、邮箱、银行卡、姓名、地址、密码、车牌和自定义规则，`DesensitizeSerializer` 在响应序列化时执行。
4. `@ApiEncrypt`/`@ApiDecrypt` 可对整个接口请求或响应做传输层加解密。
5. `PersistentCryptoService`/`VersionedPersistentCryptoService` 已提供 FPC1 版本化持久化密文、活动 keyId、历史密钥读取和旧格式兼容模型。

### 2.2 不能视为企业级闭环的原因

1. `@CryptoField` 只覆盖 Jackson 字符串字段的序列化/反序列化，不等于 ORM 入库加密；直接 Mapper、批量 SQL、导出、日志、消息、缓存或其他 VO 仍可能绕过它。加密字段也没有统一的查询、索引、等值检索和密文长度评估合同。
2. `CryptoFieldSerializer` 和 `CryptoFieldDeserializer` 当前在异常时记录错误后返回原值，属于失败开放，可能把明文写入响应或把密文/错误值继续向业务层传播。
3. 字段注解默认依赖全局密钥和算法，没有字段用途绑定、AAD/租户绑定、密文版本标识、按密钥用途隔离和权限条件解密。
4. `@Desensitize` 是输出序列化层的注解能力，未形成全局 PII 字段目录和默认拒绝策略；未标注的 Entity、VO、Map、Excel、日志、WebSocket、异常和审计扩展点可以直接输出原文。
5. 脱敏失败同样回退原值，没有统一的按角色/租户/场景显示策略、可审计的临时明文查看授权、策略版本和规则变更记录。
6. 现有外部接口日志已有局部 `ExternalSensitiveDataMasker`，但尚未覆盖全局日志、SQL 参数、异常链、请求体、响应体、消息和文件元数据；局部能力不能替代平台级 PII 防泄漏策略。

因此，本变更将“字段级加密”和“脱敏”定义为已有基础设施，需要补齐失败关闭、持久化接入、密钥用途隔离、全链路输出治理和审计后，才作为企业级能力对外承诺。

## 3. 目标与非目标

### 3.1 目标

1. 清除仓库和部署脚本中的明文凭据，统一由环境变量、外部 Secret Manager 或受控文件注入，并完成轮换门禁。
2. 建立服务端验证码挑战、MFA、密码策略、登录风控、会话撤销和企业目录接入能力。
3. 对字段加密和脱敏实现失败关闭、统一策略、密钥轮换、权限条件解密、全链路日志防泄漏和迁移可回滚。
4. 为普通 API 建立限流、配额、超时、重试、熔断和舱壁隔离；修复 HTTP 状态码、API 配置缓存和版本治理问题。
5. 建立 Metrics、Tracing、结构化日志、告警和 SLO；提供备份、恢复演练、PITR、文件安全和数据保留治理。
6. 默认启用编译和测试质量门禁，补充集成测试、SAST/SCA、镜像扫描，并收敛 Docker 运行模型。

### 3.2 非目标

- 不改造低代码、代码生成、表单设计器及 `forge-plugin-generator` 运行时。
- 不在本变更中执行生产密钥轮换、生产数据库迁移或删除历史密文；这些动作必须由部署人员按 Runbook 和人工审查门禁执行。
- 不改变已有公开 API 路径和兼容响应，除非任务明确标注为安全修复并提供版本化兼容策略。

## 4. 功能需求

### F1 安全基线与凭据治理（P0）

- 开发、测试、生产配置使用 `.example` 模板和 Secret 注入；仓库扫描不得出现数据库密码、Redis 密码、Token、AK/SK、RSA 私钥或外部系统真实地址凭据。
- `deploy.sh` 删除远程 root 密码和 `StrictHostKeyChecking=no`，改为密钥认证、主机指纹校验、最小权限用户和可审计部署凭据。
- 滑块验证码改为服务端生成一次性 challenge、签名/绑定会话和过期时间；客户端只提交 challenge 结果，不能自报 `verified`。
- 所有服务设置合理请求体上限、Header/参数上限、TLS、HSTS、CSP、X-Content-Type-Options、Referrer-Policy、CORS/CSRF 策略；生产禁止无限制 `max-http-post-size`。
- AI prompt/completion 默认关闭或脱敏；调试开启必须显式配置、限时、最小权限并记录审计。
- 安全配置变更失败关闭，旧配置仅在兼容窗口内可读，禁止恢复全网信任或明文降级。

### F2 身份认证与账号安全（P0/P1）

- 支持 TOTP，预留 WebAuthn/Passkey SPI；平台管理员默认强制 MFA，恢复码一次性且可撤销。
- 建立密码复杂度、历史密码、过期、重试锁定、泄露密码检查和安全重置流程；默认账号首次登录必须改密。
- 按 IP、账号、租户、设备和异常地理位置进行登录限流与风险评分；提供设备列表、单设备/全端退出、Token 撤销和刷新轮换。
- 提供 LDAP/AD、OIDC，SAML 适配 SPI；外部身份映射必须绑定租户、角色最小权限和登录审计。

### F3 字段加密、脱敏和数据防泄漏（P0/P1）

- 将持久化字段加密统一委托给 `PersistentCryptoService`；`@CryptoField` 只作为协议层兼容适配，不允许作为唯一持久化安全边界。
- 新增字段加密策略注册表：字段用途、算法、活动 keyId、历史 key、租户/AAD 绑定、密文长度、可检索方式和迁移状态均有明确配置。
- 加密/解密异常、密钥缺失、算法非法、密文损坏必须失败关闭，不得返回原文、密文或继续写库；错误日志只能包含字段名、记录 ID 摘要和策略版本，不能包含值。
- 脱敏策略集中注册并默认覆盖 API、导出、日志、异常、消息、WebSocket、缓存诊断和审计输出；敏感字段没有策略时生产默认拒绝输出或输出固定掩码。
- 支持按角色、租户、用途和审批时效控制“掩码/部分显示/可解密”，明文查看必须二次认证、最小字段范围、原因、工单/审批号和审计记录。
- 脱敏规则版本化，提供手机号、身份证、邮箱、银行卡、姓名、地址、车牌、密码和自定义策略的单元测试；策略异常必须固定掩码而非原文回退。
- 建立 PII 字段目录和扫描门禁，覆盖 Entity/VO/DTO、Mapper 返回列、日志模板、导出列和接口 schema；提供存量盘点、迁移、重试、校验和回滚。
- 密钥采用用途隔离、活动/历史双读、轮换前预检、轮换后验证和退役门禁；任何密钥不进入配置管理 API、前端或普通数据库配置。

### F4 API 与服务可靠性（P1）

- 普通业务 API 支持按用户/IP/租户/接口维度限流、配额和突发容量；超限返回标准 `429` 与 Retry-After。
- 外部调用统一设置默认 3 秒连接/读取超时，按幂等性配置重试，使用熔断、舱壁、降级和调用预算；禁止事务内长时间远程调用。
- 全局异常将校验、认证、授权、限流、资源不存在、冲突和系统错误映射到正确 HTTP 状态码，保留统一业务响应结构。
- 修复 API 配置 MODULE 刷新和全量启用缓存同步，增加版本号、发布审计、回滚和多实例一致性检查。
- API 版本、弃用、兼容窗口和错误码文档化；写接口继续使用明确 DTO、幂等键和状态机。

### F5 消息、数据与文件可靠性（P1）

- 引入 Outbox/可靠消息、重试、死信、补偿、幂等消费和消息状态可观测性；跨服务状态变更必须有一致性策略。
- 建立自动备份、加密备份、恢复验证、PITR、RPO/RTO、跨可用区保留和定期恢复演练；恢复结果进入审计。
- 文件上传执行 MIME/扩展名双校验、病毒扫描、压缩包炸弹限制、大小/数量/租户配额、隔离区和下载审计；路径解析拒绝穿越和符号链接逃逸。
- PII 全局脱敏、字段级加密、密钥轮换、访问留痕和数据保留/删除策略必须覆盖数据库、缓存、对象存储、日志和备份。

### F6 可观测性与运维（P1）

- 使用 Micrometer/Prometheus 暴露请求、JVM、数据库、Redis、队列、外部调用、认证失败、加密失败和限流指标。
- 使用 OpenTelemetry 贯通 Admin、App、Flow、Report 和外部依赖；Trace/Span 不得携带 Token、密码、PII 或完整请求体。
- 所有 HTTP 请求生成或透传受校验的 `X-Request-Id`，写入 `requestId`/`traceId` MDC 并在受控出站调用中继续传播；请求结束必须清理线程上下文，避免线程池串话。
- 日志采用结构化格式、关联 requestId/traceId、统一时区和级别；集中采集、留存、检索和脱敏，禁止 prompt、密钥和个人信息明文。
- 定义可用性、延迟、错误率、队列积压、备份成功率、密钥健康和安全事件 SLO，配置告警、值班、升级和演练流程。

### F7 交付质量与部署收敛（P1）

- Maven 默认执行 compile/test，CI 对后端、Admin UI、H5 执行构建、单元/集成测试和静态检查；禁止以默认 skip 掩盖失败。
- 增加 Testcontainers 或等价真实依赖集成测试，覆盖 MySQL、Redis、认证、租户、加密、消息和文件关键路径。
- CI 加入 SAST、SCA、Secret scan、容器镜像漏洞扫描、SBOM 和依赖升级门禁。
- 合并或生成唯一来源的 `docker/` 与 `docker-forge-admin/` 部署定义，固定模块路径、非 root 用户、健康检查、资源限制、TLS 和生产密码策略。
- 文档统一 Spring Boot/Maven/Node 版本，发布产物包含配置清单、迁移说明、回滚 Runbook 和审计证据。

## 6. 数据与接口约束

- 新增数据库字段、索引和系统字典必须使用 `forge-server/db/migration` 的 Flyway 脚本，具备防重复保护、租户值为 `1`、逻辑删除语义和回滚说明。
- 任何敏感字段返回只允许掩码或按权限解密后的临时结果；配置管理接口不得返回或接受部署密钥、私钥、密钥环。
- 认证、权限、状态流转、凭据、备份恢复和数据迁移接口必须使用明确 DTO，记录操作者、租户、原因、审计号和结果摘要，不记录秘密值。
- 兼容发布顺序固定为“兼容读取 → 新格式写入 → 盘点/迁移 → 校验 → 退役旧密钥”；未满足门禁时不得删除旧密钥或关闭 legacy read。

## 7. 风险、回滚与人工审查

1. **凭据轮换风险**：错误轮换会导致数据库、Redis、外部系统不可用。先双钥兼容和连接验证，再切换活动密钥；回滚通过恢复上一版本 Secret 和配置，不恢复 Git 中的旧明文。
2. **字段加密风险**：字段长度、查询语义和旧数据格式可能不兼容。迁移前做容量/算法/密钥预检，批量迁移使用原值比较更新；失败保留原值并可重跑。
3. **脱敏失败关闭风险**：未登记的接口可能出现响应错误。先盘点并提供显式策略，灰度开启生产拒绝；回滚只能切换到已审计的兼容策略，不允许回退原文输出。
4. **MFA/风控风险**：旧客户端或服务账号可能无法登录。提供恢复码、管理员应急流程和灰度租户，所有豁免必须限时并审计。
5. **限流/熔断风险**：阈值不当会阻断正常业务。先观测模式，再按租户和接口灰度，保留动态回滚开关。
6. **备份恢复风险**：恢复演练可能影响生产数据。使用隔离环境、脱敏副本和只读验证，恢复结果由运维与安全负责人签字。

以下事项必须人工审查后才能上线：生产 Secret 注入与轮换、管理员 MFA 强制策略、明文查看授权、字段加密迁移和旧密钥退役、租户隔离策略、备份恢复 RPO/RTO、限流阈值、TLS/Origin 白名单及 Docker 生产凭据。

## 8. 验收标准

1. Secret/依赖扫描、配置扫描和部署脚本扫描无真实凭据；所有服务在缺少必需 Secret 时启动失败并指出配置名。
2. 验证码 challenge 不能被客户端伪造或重放；MFA、密码策略、会话撤销和管理员审计测试通过。
3. `@CryptoField`、持久化密文、历史 key、轮换、损坏密文和密钥缺失均失败关闭；加密字段在 ORM、导出、日志和消息链路不出现原文泄露。
4. 未登记或脱敏失败的敏感字段在生产输出固定掩码/拒绝；明文查看具备权限、二次认证、原因和审计记录。
5. 限流、超时、熔断、HTTP 状态码、API 配置刷新和消息补偿测试通过；关键指标、Trace、日志和告警可查询且无敏感值。
6. 备份可恢复并满足约定 RPO/RTO；文件恶意内容、路径穿越、超额上传和下载审计测试通过。
7. CI 默认不跳过 compile/test，集成测试、SAST/SCA、Secret scan、镜像扫描和 SBOM 门禁有效；两套 Docker 定义不存在漂移。
8. 每项安全/权限/凭据/状态迁移任务均有人工审查记录、灰度结果、回滚演练和发布证据。

## 9. 实施门禁

- 本变更已由用户通过 `apply enterprise-framework-hardening` 授权实施代码；生产凭据轮换、生产数据库迁移、生产部署和旧密钥退役仍需对应负责人人工审查。
- 执行必须遵循 `No Spec No Code`，每个任务先补针对性测试，再实现，再按 `automated-testing-standard.md` 记录验证。
- 任一任务发现需要低代码模块才能完成时，应暂停该任务并另开变更，不得扩大本变更范围。

## 10. 本轮实施状态

### 2026-09-06 增量合同（T1.1 / T4.1 / T5.3）

- 滑块挑战签名覆盖版本、key、坐标、绑定摘要、绝对到期时间；有效期不超过 5 分钟。无 HTTP 请求上下文、损坏缓存、错误签名或过期均拒绝；验证尝试一次消费（错误答案也消耗），并发只能有一个消费者。生产与 dev 混合 Profile 不得启用临时密钥；显式密钥至少 32 字节。协议升级要求清空旧挑战或等待 5 分钟，前端无需变更。
- 普通 API 限流使用独立 MVC 拦截器，在登录上下文建立后、权限判断前运行，不依赖 API 权限开关或注解豁免路径；只针对启用的 API 配置且 needLimit=true 的 HandlerMethod，OPTIONS 不扣额度。使用匹配的配置路径模板、HTTP 方法以及可信租户/用户或容器 remoteAddr 生成摘要键，禁止使用原始动态 URI、Token 或转发头；Redis 桶空闲后过期。默认强制，超限返回 429/Retry-After=60；显式 `forge.api-config.rate-limit.mode=observe` 可用于灰度观测；强制模式 Redis 故障返回 503，观测模式记录告警并继续请求。Admin 既有 api-config.enabled=false 保持不变。阈值变化须统一实例配置，允许新桶重置一次额度。
