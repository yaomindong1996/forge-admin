# 数据权限配置易用性优化

## 目标与授权

用户已确认「列表直接启停、保存自动更新、手动刷新兜底」，并要求界面易用、美观。本变更涉及权限规则开关；本轮人工确认即采用以下行为，操作权限继续限定超级管理员。

## 交互

- 列表首屏展示适用页面、支持的限制范围、规则状态、备注和操作；编码作为名称辅助信息，Mapper/表别名移入技术配置。
- 状态列使用带字典文案的开关。启停均先确认，禁用明确提示可能扩大数据可见范围；仅成功后更新状态，取消不发请求，处理中禁止重复操作。
- 顶栏增加次要按钮「刷新数据权限」，说明保存后自动更新、异常时可手动刷新并重新查询业务页面。刷新列表与刷新权限保持不同名称和功能。
- 编辑页先呈现页面和支持的范围，再展开技术配置；新配置或缺少 Mapper 时默认展开。状态统一从列表操作，避免普通编辑覆盖并发启停。
- 复用 AiCrudPage / Naive UI / Forge 主题变量，支持亮色、暗色、窄屏；不增加装饰卡、渐变或大标题。
- 小屏默认只显示页面、状态和更多操作；筛选垂直排列、抽屉适配屏幕，支持的限制范围与备注仍可在编辑中查看。各范围的字段设置折叠展示。

## 服务端行为

- 新增具体配置 DTO 和状态 DTO；状态更新只修改 enabled，带旧状态条件防止并发覆盖，使用 EnableStatus 校验。
- 新增超级管理员权限刷新入口并保留旧入口，两个入口都校验管理员及记录操作日志。
- 配置增删改和启停在事务成功提交后刷新；回滚不刷新。提交后刷新失败明确提示「配置已保存，但数据权限刷新失败」，不能伪装成保存回滚。
- 数据权限运行快照加载所有未删除配置，保留禁用项，复用拦截器的显式禁用分支；未配置的 Mapper 继续遵守 WARN/DENY 策略。租户禁用配置优先于默认租户回退配置。
- 刷新通过 Redis Pub/Sub 通知其他实例重新加载；本实例消息不重复加载，收到通知不再次广播，重新订阅后补载。无 Redis 实例时维持本地模式。跨实例为异步传播，界面不声称已确认全部节点。
- 页面查询 SQL 移入 Mapper XML，显式过滤 del_flag；不改数据库结构和既有迁移。

## 风险与回滚

禁用规则意味着停止该规则的数据过滤，可能扩大可见范围，不代表取消菜单访问权限，也不取消独立的租户隔离。新增显式禁用加载使严格模式也遵守管理员禁用意图；保留确认提示、管理员边界和日志。恢复限制可重新启用；代码回滚需重启服务以清除本地快照。无物理数据删除或权限资源放开。
