# Forge 流程管理模块补强 Spec

> 变更名：`flow-management-hardening`  
> 状态：`in-progress-with-open-items`  
> 创建日期：2026-09-05  
> 实施方式：按 `tasks.md` 分阶段执行，完成一阶段后再进入下一阶段

## 1. 背景与问题定义

Forge 已经具备待办、已办、我发起、抄送、流程模型、版本、可视化设计器、动态表单、审批、驳回、退回、撤回、委派、转派、终结、流程监控、错误日志和通知等基础能力。

静态审查发现，当前流程模块仍存在四类问题：

1. 任务详情、流程图、表单和历史接口的租户/用户边界不统一，存在越权读取风险。
2. 撤回在无法确认发起人时放行，催办缺少明确授权，属于状态和权限安全缺陷。
3. 超时统计、超时扫描、超时通知和流程图连线高亮未形成闭环，监控页面存在伪指标或空结果。
4. 监控存在 N+1 和全量加载；批量审批、错误提示、数量统计、重复提交等前端交互不完整。
5. 对照 RuoYi BPM，缺少动态加签、临时抄送、管理员任务、下一审批节点预览、用户组和流程定义治理等企业审批能力。

## 2. 目标

### 2.1 必达目标

1. 所有流程读取和写入均在服务层完成“当前租户 + 当前用户/角色/业务关系”校验。
2. 撤回、催办、委派、转派、终止、删除等动作具备明确权限、状态机和幂等语义。
3. 超时任务从配置、扫描、提醒、升级、统计到前端筛选形成可验证闭环；未实现指标不得继续展示为有效数据。
4. 监控、历史和流程图接口在大数据量下保持分页、批量查询和稳定响应。
5. 补齐动态加签、临时抄送、管理员任务、可退回节点、下一节点预览和统一审批详情等高频能力。
6. 前端对部分成功、失败、权限不足、接口异常、空结果和重复提交提供明确反馈。
7. 流程模型部署前校验节点可执行性、审批人可解析性、表单和条件配置完整性。

### 2.2 非目标

- 不在本变更中重写 Flowable 引擎或替换 BPMN 标准。
- 不改造与流程无关的 generator、通用低代码运行时和其他业务模块。
- 不改变已有 REST 路径；兼容性破坏必须另开版本化变更。
- 不直接执行生产数据清理、历史数据物理删除或生产密钥操作。

## 4. 功能需求

### F1 流程访问控制与多租户隔离（P0）

- `FlowTaskController` 的任务详情、流程图、流程历史、任务表单和流程表单接口必须调用统一的 `FlowAccessGuard` 或等价服务。
- 查询必须同时校验当前租户、流程实例归属、当前用户任务关系或监控权限；不能依赖 `@IgnoreTenant` 之后的隐含约定。
- `FlowTaskMapper.xml`、业务关联查询和历史查询必须显式带租户条件；涉及逻辑删除的表必须过滤未删除数据。
- 任何越权访问统一返回资源不存在或无权限错误，不泄露 taskId/processInstanceId 是否存在。
- 流程变量、表单字段、业务关联数据和错误日志使用同一访问判定结果。

### F2 任务动作授权、状态机和幂等（P0）

- 撤回仅允许可信发起人或明确的管理员权限；无法确认发起人时拒绝操作并记录可修复错误。
- 催办仅允许任务处理人、流程发起人、授权管理员或配置的协同角色；未签收任务应通知候选人或返回明确“无可催办对象”。
- 委派、转派、终止、删除、挂起、激活必须在服务层校验操作者权限、租户、任务/实例当前状态和目标用户合法性。
- 审批、驳回、退回、撤回、转派、加签等写动作必须支持幂等键或稳定请求摘要，重复请求不得重复推进流程。
- 所有状态变更写入操作日志和流程事件，失败时不得出现业务表、Flowable 实例和通知状态不一致。

### F3 超时任务完整闭环（P0/P1）

- 节点超时配置必须转换为 Flowable due date 或可查询的任务截止时间，并保存时区和计算规则。
- 定时扫描必须启用，按 due date、租户和稳定游标批量扫描；支持失败重试和扫描进度指标。
- 超时通知必须通过统一消息服务发送，支持站内信、邮件、短信或 Webhook 的配置校验、幂等和失败记录。
- 支持首次逾期、重复提醒、升级提醒和已处理任务停止提醒；每次发送保存通知记录。
- 监控统计返回真实 `timeoutTasks`；前端使用 `overdue=true` 或独立超时任务接口，不把 `timeout` 当流程实例状态。
- 未实现的统计能力必须返回明确能力不可用状态，前端隐藏对应卡片或显示不可用原因。

### F4 监控、历史和流程图可靠性（P1）

- 监控实例列表一次批量返回当前节点和处理人，不允许逐行查询。
- 平均耗时、任务趋势、节点耗时、审批人效率使用数据库聚合或分页查询，不得全量加载历史实例到 JVM。
- 流程历史支持分页、时间范围和最大返回量；审批点结果、用户信息和业务摘要批量加载。
- 流程图返回已完成节点、当前节点和已执行连线；无法获取连线时明确标识能力不可用。
- 查询异常返回稳定错误码和 `degraded` 信息，禁止把后端异常伪装成空列表或零统计。
- 监控管理接口必须使用明确 VO；流程变量可以保留动态 Map 字段。

### F5 审批能力补齐（P1）

- 增加管理员任务分页、按流程实例查询全部任务、任务父子关系和可退回节点查询。
- 增加动态加签、减签、前加签、后加签；加签任务与原任务建立可审计关系。
- 增加任务级临时抄送，支持查看、撤回和已读状态。
- 增加统一审批详情聚合接口，包含流程、业务表单、历史、当前任务、候选人和可用动作。
- 增加发起前下一审批节点和候选审批人预览；解析失败必须阻断发起并返回可读原因。
- 区分发起人取消、管理员取消、流程终止和撤回，建立状态转换矩阵。

### F6 模型、节点和组织配置治理（P1/P2）

- 模型部署前检查开始/结束节点、连线、网关条件、表单引用、审批人策略、监听器和节点执行类型。
- 对 serviceTask、scriptTask、subProcess、callActivity 等节点建立执行白名单；未接入的节点不能仅通过 raw XML 部署。
- 审批人、部门、角色和用户组解析必须在部署或发起前可验证，并提供缺失人员、无效组织和空候选人的诊断信息。
- 增加流程定义查询、模型排序、历史版本清理和版本启停审计。
- 增加用户组、流程监听器和流程表达式的独立资源管理能力；普通业务人员默认使用可视化配置，SpEL 仅作为高级能力。

### F7 前端审批与监控体验（P1）

- 批量审批返回逐条成功、失败、跳过结果，并支持查看失败原因和重新处理。
- 待办紧急数、我发起待处理数、抄送未读数使用服务端总数，不按当前页估算。
- 所有列表加载失败显示错误状态、重试入口和 requestId；空数据只在接口成功时显示。
- 发布、复制、挂起、激活、删除、审批、催办等操作增加提交锁、状态刷新和重复点击保护。
- 详情页加载表单、流程图、历史和业务数据时显示独立加载/失败状态；只读和可编辑状态与后端权限一致。
- 监控删除流程数据增加影响范围预览、输入确认、二次权限和审计信息；默认不提供不可逆的无筛选全量删除。

### F8 数据、接口和迁移约束

- 新增字段、索引、关系表和字典必须通过 `forge-server/db/migration/` Flyway 脚本；脚本具备防重复保护，业务数据 `tenant_id=1`。
- 候选用户、角色、部门和用户组关系优先使用关联表，不再新增逗号字符串字段。
- 新增 Controller 写接口使用 DTO/VO；流程 variables 仍可使用 Map 字段。
- 业务主数据删除默认逻辑删除；流程运行表和清理任务如需物理删除，必须写明原因、留存和回滚方式。
- 所有新增接口记录操作者、租户、原因、幂等键和结果摘要，不记录完整表单、变量或个人敏感信息。

## 6. 风险与回滚

1. **访问控制收紧**：历史兼容调用可能被拒绝。先补齐内部调用方身份和租户上下文，再按租户灰度；回滚只能恢复兼容配置，不得关闭服务层校验。
2. **超时扫描启用**：可能产生大量通知。先以 dry-run 和单租户灰度，设置每日发送预算和总开关；异常时停止调度但保留任务数据。
3. **动态加签/回退**：Flowable 任务关系复杂。先支持单任务、单节点、可审计操作，再扩展批量和并行场景；失败通过错误日志和人工补偿恢复。
4. **候选关系表迁移**：历史逗号字段和新表可能短期并存。采用双读、回填、校验、切换、旧字段只读的顺序，迁移失败可重跑。
5. **监控统计改造**：聚合口径变化可能导致数值变化。保留旧口径对照字段，完成数据核对后再切换前端。

## 7. 验收标准

1. 使用不同租户和不同用户的 taskId、processInstanceId、businessKey 访问详情、图、历史、变量、表单和错误日志，均无法读取越权数据。
2. 无发起人信息的流程撤回被拒绝；无权限用户催办、委派、转派、终止和删除均被拒绝；重复审批请求只产生一次状态变更。
3. 构造已逾期、即将逾期、重复扫描、通知失败和任务完成场景，统计、通知记录和前端列表结果一致。
4. 监控实例分页查询的 SQL 次数不随行数线性增长；历史和平均耗时在大数据量下不发生全量 JVM 加载。
5. 动态加签、临时抄送、管理员任务、可退回节点和下一节点预览具备接口、权限、审计和前端入口。
6. 批量审批显示逐条结果；列表接口异常显示错误状态；数量卡片与服务端总数一致；所有写操作可防重复提交。
7. 部署含未支持执行节点、空审批人、无效条件或缺失表单时被阻断并返回可读诊断。
8. 迁移脚本、DTO/VO、错误码、测试和 `execution-log.md` 完整，所有生产数据变更具备回滚方案和人工审查记录。

## 8. 人工审查门禁

- 访问控制和租户隔离：安全负责人审查。
- 状态机、撤回、终止、取消、动态加签：流程产品负责人审查。
- 超时通知、短信费用和升级策略：运维/消息负责人审查。
- 关系表迁移、逻辑删除和历史清理：数据负责人审查。
- 生产灰度、监控阈值和回滚：发布负责人审查。

## 本轮追加实现说明（2026-09-05）

- 人工抄送发送与流程内部回调分离授权入口：人工请求必须绑定当前会话用户并验证流程实例、任务参与关系、业务键/流程定义和目标用户租户可用性；内部 serviceTask/结果通知回调保留无 HTTP 会话的受控发送路径。
- 发起前启动配置接口新增 `nextNodes` 只读预览，提供从开始事件首批可达用户任务的审批策略元数据；不把预览结果当作运行时授权结果。
