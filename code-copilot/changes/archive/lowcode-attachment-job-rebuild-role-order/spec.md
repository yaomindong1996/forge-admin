# 低代码附件、定时任务重建与用户角色排序 Spec

## 目标

1. 低代码应用配置附件组件后，列表中如果附件是图片，应展示鉴权图片缩略图，而不是只展示类似 `1784902600090_download.png` 的文件名；非图片附件继续展示文件名。
2. 定时任务提供明确的 Quartz 重建能力，用于数据库任务配置存在但 Quartz Job/Trigger 缺失或残缺的情况。
3. 用户列表的“关联管理→角色授权”页把当前用户在当前组织已有的角色排在当前列表前面。

## 约束

- 不改变附件字段的持久化协议；上传组件仍保存 fileId/filePath，翻译字段仅用于显示名称。
- 图片预览必须使用 `AuthImage`，不能使用无鉴权的直接 `<img src>`。
- Quartz 重建必须经过已有同步锁、版本收敛和状态记录；不能删除其他任务，也不能绕过权限/审计。
- 一次性任务已过期且 misfire 为 `DO_NOTHING` 时，重建不能补偿执行，沿用现有完成态处理。
- 角色排序只改变当前授权页呈现顺序，不改变角色选中值、查询条件、后端分页总数或其他角色管理页面。

## 验收标准

- `fileUpload` 列：图片扩展名使用 `AuthImage`，普通扩展名和没有扩展名的附件显示名称；多文件逐项处理。
- 点击“重建调度”后，即使 Quartz 原有 Job 不完整，也会删除同名同组 Job 并创建最新 Job 与 Trigger，随后记录同步成功/失败状态。
- 重建接口在前端任务列表可见且受 `system:jobConfig:sync` 权限控制。
- 授权列表中已拥有角色位于未拥有角色之前，原有排序作为组内次序。
