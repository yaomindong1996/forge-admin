# 应用入口移动端与对象设计体验优化

## 背景

应用工作台的访问入口仍暴露“可见范围”和“移动场景”两个配置项，但前者没有运行时鉴权实现，后者只用于移动入口统计，不会改变入口实际打开的页面。移动入口也不能同步到已经按客户端区分的系统菜单。业务对象基本信息仍要求手输图标编码，数据关系内容紧贴左侧导航。

## 目标

1. 移除访问入口中的“可见范围”配置，页面入口访问统一由应用权限工作台的角色授权控制；编辑存量入口时保留已有 JSON 字段，不做破坏性清理。
2. 移除没有运行行为的“移动场景”配置，移动入口实际行为统一由“打开内容”决定；存量 `mobileScene` 继续兼容读取但不再作为新配置写入。
3. 用户界面将 H5 入口和 `h5` 客户端统一称为“移动端”，保留既有 `H5`/`h5` 技术编码与接口兼容。
4. 移动入口可直接同步到系统菜单的移动端客户端。同步资源使用 `client_code=h5`，在菜单管理和角色授权的移动端页签出现；管理端入口继续使用 `client_code=pc`。
5. 业务对象基本信息使用通用 `IconSelector` 选择对象图标，并保持原有 `icon` 字段保存协议。
6. 数据关系工作区与对象设计器左侧导航之间增加稳定留白，不改变关系设计器内部结构。
7. 应用重新发布业务对象时，只刷新既有入口与对象运行配置的绑定，不得把人工配置的移动端挂载位置、菜单、状态和展示信息覆盖为管理端默认值。

## 约束与兼容

- 不新增或重命名数据库业务字段，不修改 `H5`/`h5` 存量技术值。
- 菜单同步继续复用入口 `options.adminMenu` 存量协议；移动端写入目标客户端信息并禁用业务域目录自动挂载，避免跨客户端父子资源。
- 入口角色权限仍在应用权限工作台统一配置，不用“可见范围”模拟鉴权。
- 低代码发布自动创建入口时仍使用标准管理端默认值；入口已经存在时，以入口配置为准，发布过程不得重置其 `appType` 和 `options`。
- 字典和客户端展示名称通过新的 Flyway 迁移更新，不修改已执行历史脚本。
- 按用户要求，本轮不执行自动化测试或浏览器验证，由用户自行手工验收。

## 验收标准

- 新建或编辑移动入口时不再出现“可见范围”和“移动场景”。
- 移动入口显示“同步到移动端菜单”开关及明确说明，开启保存后生成/更新 `client_code=h5` 的菜单资源。
- 管理端入口菜单仍生成到 `client_code=pc`，关闭同步或切换端时旧资源按既有规则删除/禁用。
- 页面上的 H5 产品文案改为“移动端”，技术配置和旧数据仍可正常识别。
- 对象图标可从图标选择器选择，选择后会标记草稿变更。
- “数据关系”内容与左侧导航之间有清晰间距。
- 移动入口所在业务对象或应用重新发布后，入口再次编辑仍保持“移动端”，移动菜单配置不丢失。
