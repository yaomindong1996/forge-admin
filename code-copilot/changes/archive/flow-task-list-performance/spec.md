# 流程待办/已办列表查询性能优化

## 背景

待办和已办列表查询后，`FlowTaskServiceImpl` 对分页结果逐条反查用户姓名、逐条读取 Flowable `businessParams`，导致一个页面产生大量串行数据库/Flowable 查询。

## 目标

1. 列表查询不再按任务逐条调用组织服务或 Flowable 运行时变量接口。
2. 用户名称、流程任务基础信息尽量在 Mapper SQL 中关联/批量获取。
3. 待办候选组必须只返回当前用户所属候选组的任务。
4. 待办/已办查询显式限定当前租户，避免全表扫描和跨租户数据混查。
5. 通过 Flyway 增加与实际过滤、排序条件匹配的联合索引。

## 方案约束

- 列表响应字段保持兼容，详情页继续使用原有详情接口。
- 业务参数优先使用已经持久化的业务流程实例变量快照；快照缺失时返回空，不在列表请求中逐条访问 Flowable 运行时变量。
- 复杂查询写入 Mapper XML；迁移脚本必须可重复执行并使用 `tenant_id = 1` 作为内置数据约定。
- 不启动本地 Admin/Flow 服务，由用户在真实环境执行运行态验证。

## 非目标

- 不改流程模型、节点表单、审批状态机或前端列表交互。
- 不在本次变更中重构候选人逗号字段为关系表；先修正候选组过滤并为可索引字段补齐索引。
