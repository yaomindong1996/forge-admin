# 业务域删除孤立应用入口修复
> status: completed
> created: 2026-08-05
> complexity: 中等

## 1. 背景与目标

业务应用删除时，已停用的访问入口会解除 `application_id` 绑定但保留在 `ai_business_app`，以便迁移或复用。业务域下已经没有业务应用后，`BusinessSuiteService#delete` 仍按 `suite_code` 统计这些入口并直接报错“该业务域下仍有应用入口，请先删除或迁移入口”。此时入口已不在被删除应用的管理上下文中，用户无法顺畅完成清理。

本变更目标：

- 有效业务应用仍存在时继续阻止业务域删除。
- 仅剩无有效业务应用引用的访问入口时，将其视为孤立设计资源；用户显式确认后停用相关菜单并逻辑删除入口。
- 业务对象与孤立入口使用同一次显式清理确认，在同一事务内完成。
- 防御历史脏数据：入口若仍指向任意未删除业务应用，必须失败关闭，不能误删。

## 2. 根因与证据

- `BusinessApplicationService#delete` 对停用入口调用 `detachDisabledByApplicationId`，只把 `application_id` 置空，不删除入口。
- `BusinessSuiteMapper#countAppsBySuite` 统计目标 `suite_code` 下所有未删除 `ai_business_app`，不区分是否仍绑定有效应用。
- `BusinessSuiteService#delete` 在处理显式孤立对象清理前直接阻断所有入口。
- 前端删除确认只根据 `objectCount` 决定是否传 `cleanupOrphanObjects=true`，没有消费已有的 `appCount`。

## 3. 功能范围

- [x] 业务域删除统计未删除访问入口，但不再无条件阻断。
- [x] 未显式确认且存在入口或对象时，返回包含具体数量的清理确认提示。
- [x] 显式确认后，先校验入口未绑定任何有效业务应用，再停用入口菜单并逻辑删除入口。
- [x] 入口、对象清理完成后逻辑删除业务域；任一步异常整体回滚。
- [x] 应用中心和业务域详情页同时展示入口/对象清理数量，并在任一数量大于零时传递清理确认。

## 4. 业务与安全规则

1. 存在未删除子业务域或本域业务应用时仍禁止删除。
2. 入口通过 `application_id` 关联任意未删除业务应用时禁止批量清理，即使入口与应用的 `suite_code` 因历史数据不一致。
3. 无有效应用引用的入口属于孤立设计资源；只有显式确认后才能逻辑删除。
4. 入口删除写 `del_flag = id` 并置为停用；入口管理端菜单先停用，避免残留可访问菜单。
5. 业务对象、对象关系和业务域沿用上一变更的清理规则；不删除动态业务表、发布历史或运行日志。

## 5. 数据与接口变更

- 数据库结构：无变更，无 Flyway。
- `ai_business_app`：按 `tenant_id + suite_code + del_flag=0` 批量逻辑删除，写入 `del_flag=id`、`status=0`。
- 接口路径不变：`DELETE /ai/business/suite/{id}`。
- 兼容既有查询参数 `cleanupOrphanObjects`，其语义扩展为确认清理业务域内的孤立入口与孤立对象；不破坏旧调用方。

## 6. 影响范围

- Generator：`BusinessSuiteService`、Mapper 接口/XML、服务单测。
- 前端应用中心：业务域列表与详情页删除确认。
- 不改变业务应用删除、单个访问入口删除或单个业务对象删除协议。

## 7. 风险与回滚

- 风险：批量清理入口可能涉及已有菜单，因此删除前统一停用菜单；不批量物理删除 `sys_resource` 或角色授权。
- 风险：历史数据可能存在跨域错误绑定，通过有效应用引用查询失败关闭。
- 回滚：恢复入口硬阻断和前端原判断即可；逻辑删除数据可按主键审计恢复，无数据库结构回滚。

## 8. 测试策略

- JUnit 覆盖：显式清理孤立入口、未确认阻断、有效应用引用失败关闭、入口与对象组合清理顺序、空业务域删除。
- Mapper XML 静态检查：有效应用引用 JOIN、入口 `del_flag=id`、租户与未删除条件。
- 前端执行目标 ESLint 和生产构建。
- 不启动真实服务或数据库；部署环境补充真实业务域删除冒烟。

## 10. 实施结论

- 保留 `cleanupOrphanObjects` 接口参数，将其语义扩展为“确认清理孤立入口与孤立对象”。
- 有效业务应用及入口/对象有效引用仍失败关闭；所有引用校验完成后才开始停用菜单和清理元数据。
- 入口使用 `status = 0, del_flag = id` 逻辑删除，不物理删除菜单资源、角色授权、业务数据表或历史版本。
