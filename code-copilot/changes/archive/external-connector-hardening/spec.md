# 外部连接器与数据集运行时加固
> status: completed
> created: 2026-08-10
> complexity: 🔴高

## 1. 背景与目标

低代码应用需要通过现有外部接口连接器或数据集完成企微身份映射、会员查询、商品查询、收款查询等数据获取。应用实施人员可以配置接口、参数化 SQL 或受控脚本，但业务用户不应编写 Java/Vue。

本阶段只建设通用运行基础能力，不写入任何预售、会员、商品、支付或企微专用逻辑。目标是把已经落库但尚未生效的权限、限流、缓存、重试配置真正接入调用链，并补齐密钥、日志、出站地址和只读查询安全。

完成后应满足：

- 外部 API 调用按配置执行权限、限流、缓存和安全重试；
- 外部目标必须经过统一出站策略校验，禁止绕过 SSRF/DNS 重绑定治理；
- 连接器密钥写入加密、运行解密、管理端不回传明文；
- 请求参数、URL、响应和错误日志不泄露手机号、单号、凭据等敏感信息；
- 数据集查询失败显式报错，不再伪装成空结果；
- 数据集连接以只读方式使用，并对最大行数、超时、缓存设置稳健边界；
- Java 17 缺少 JavaScript Engine 时返回明确业务错误，不出现空指针。

## 2. 现状与复用边界

### 2.1 复用能力

- `forge-plugin-external` 已有系统/API 配置、Basic/Bearer/API Key/OAuth2/自定义认证、参数映射、响应路径、错误码路径和脚本适配器。
- `forge-plugin-data` 已有 TABLE/SQL 数据集、参数 Schema、PreparedStatement 参数绑定、ACL、行权限、字段白名单和敏感字段掩码。
- `forge-starter-crypto` 已有 `PersistentCryptoService`，用于数据库持久化密文。
- `forge-starter-cache` 已有 Redisson 与统一缓存服务。
- `forge-starter-outbound` 已有出站白名单、协议/主机/IP 校验、DNS 重绑定防护、重定向治理和请求/响应大小限制。

### 2.2 不建设的能力

- 不新建第三套“数据库查询资源”；直接查询数据库继续由数据集承担。
- 不新增预售专用 Controller、表、字段名或接口枚举。
- 不在本阶段建设低代码字段事件、事务命令、子表动作或 H5 运行时；这些按后续独立变更推进。
- 不宣称任意 JavaScript 已经安全可执行；现阶段只补齐 Engine 缺失时的失败关闭，脚本沙箱作为后续脚本运行时专项能力。

## 3. 功能需求

### 3.1 外部接口运行策略

1. `permissionCheckEnabled=true` 时，`requiredPermission` 必须非空，且当前用户必须拥有该权限；否则拒绝调用。
2. `rateLimitEnabled=true` 时，按租户和 API 隔离 QPS；QPS 配置必须处于安全区间。限流基础设施不可用时失败关闭。
3. `cacheEnabled=true` 时，仅缓存成功的 GET 调用结果；缓存故障降级为直连，不影响主调用。
4. 缓存 Key 必须绑定租户、用户、API 和规范化参数摘要，只存哈希，不包含手机号或业务参数明文。
5. 重试默认只允许 GET/HEAD；POST/PUT/PATCH/DELETE 不自动重试。
6. 仅网络类失败和 502/503/504 响应可重试；业务失败、4xx 和其他 5xx 不重试。
7. 重试次数、退避时间、连接超时和读取超时必须归一化到平台安全上下界。

### 3.2 出站安全

1. 外部代理使用 `forge-starter-outbound` 的 `SecureOutboundClient`，场景为通用外部连接器场景。
2. 外部系统地址及 OAuth2 Token 地址必须经过出站白名单和目标安全校验。
3. 配置的危险 Header（例如 `Host`、`X-Inner-Call`）不得透传。
4. 现有 `trustedInternal` 只影响 Forge 内部加密握手语义，不得绕过出站目标校验。
5. 现有任意代理/关闭 SSL 校验配置不在未实现时伪装成生效；运行时使用统一安全客户端的固定校验策略。

## 3.3 密钥持久化

以下字段按凭据处理：`basicPassword`、`tokenValue`、`oauth2ClientSecret`、`apiKeyValue`、`proxyPassword`、`customAuthConfig`。

1. 新增和修改时使用 `PersistentCryptoService` 加密后入库。
2. 修改请求中密钥为空或为管理端掩码占位符时保留旧密文。
3. 运行调用前在内存副本中解密，不修改持久化实体。
4. 分页、详情和列表接口只能返回固定掩码，不返回密文或明文。
5. 对存量明文采用受控兼容：运行时可读取并告警；后续独立迁移任务批量加密。不能错误地把任意非空明文当成密文解密。

## 3.4 敏感信息与审计

1. Controller 不记录完整代理参数。
2. 持久化调用日志的 URL、请求参数、请求体、响应体和错误信息统一脱敏。
3. 敏感键至少覆盖 token、password、secret、authorization、cookie、mobile、phone、tel、orderNo、paymentNo、tradeNo、cardNo、idCard 等常用命名，并递归处理对象和数组。
4. URL query 仅保留键名，值统一替换为掩码。
5. 调试响应的 `responseBody` 同样脱敏，业务 `responseData` 保持原响应语义并由接口权限保护。

## 3.5 数据集只读运行

1. 最大返回行数默认 1000，范围 1～10000；查询请求只能收紧，不能突破数据集上限。
2. 查询超时默认 30 秒，范围 1～120 秒。
3. JDBC Connection 尝试设置 `readOnly=true`；驱动不支持时记录不含敏感值的警告并继续，SQL 仍必须通过只读安全校验。
4. 数据库异常转换为明确 `BusinessException`，不得返回空集合。
5. 运行日志只记录数据集 ID、类型、页码、字段数量、参数键集合和 SQL 摘要哈希，不记录参数值或渲染 SQL。
6. 数据集缓存仅缓存成功结果，Key 绑定租户、用户、数据集、字段和参数摘要；缓存失败降级直查。

## 3.6 脚本适配器失败语义

1. JavaScript Engine 不存在时抛出“当前运行环境未启用安全脚本引擎”的业务错误。
2. 脚本为空、编译/执行失败、结果类型异常时返回可定位但不泄露脚本数据的业务错误。
3. 本阶段不承诺脚本沙箱；生产启用脚本转换前仍需完成独立脚本运行时治理。

## 4. 接口兼容性

- 现有 `/external/proxy/{apiId}`、`/external/proxy/debug/{apiId}` 路径和业务响应结构保持不变。
- 外部系统管理接口路径保持不变，但密钥字段从原值调整为固定掩码或空值，属于安全收紧。
- 数据集发布态查询接口路径和成功结构保持不变；查询故障从“成功空数据”改为明确失败。

## 5. 数据库变更

本阶段不新增业务表和字段。新增幂等 Flyway 字典数据 `sys_outbound_scene=EXTERNAL_CONNECTOR`，让管理员可以在现有出站白名单页面配置连接器目标；不预置任何客户域名或凭据。现有密钥列继续存储版本化密文。若后续需要批量迁移存量明文，必须单独提供可审计的迁移任务，不能在 Flyway 中硬编码密钥或离线解密。

## 6. 安全与失败策略

- 权限、限流、目标校验失败关闭。
- 缓存读写失败降级为实时调用/查询。
- 非幂等请求不自动重试。
- 日志保存失败不覆盖原业务结果，但日志告警不得包含完整 URL 或响应。
- 密钥解密失败明确报配置不可用，不回显密文、算法或底层异常详情。

## 7. 测试策略

- 外部连接器：权限、限流、缓存 Key、缓存命中、GET 重试、POST 不重试、出站请求组装、敏感数据脱敏。
- 密钥：新增加密、空值保留、管理返回不泄露、运行时解密、存量明文兼容。
- 数据集：失败传播、只读连接、边界归一、缓存命中、日志契约。
- 脚本：Engine 缺失与执行失败语义。
- 详细用例见 `test-spec.md`，执行证据见 `execution-log.md`。

## 8. 风险与后续

- 启用统一出站白名单后，未配置 `EXTERNAL_CONNECTOR` 白名单的目标会被拒绝，部署前需由管理员配置允许目标。
- 存量明文凭据不会自动批量改写；本阶段确保新写入安全并为存量读取提供兼容。
- 复杂 JavaScript 沙箱、CPU/内存/时间配额需在后续统一脚本运行时阶段建设。
- 本阶段完成后进入“参数化只读查询”阶段，将外部 API 与数据集统一暴露为低代码字段动作数据源。
