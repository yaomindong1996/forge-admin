# 低代码设计器可用性闭环

> status: applied-with-runtime-e2e-pending
> created: 2026-08-20
> scope: 应用增强、应用内页面组、业务流程配置与独立流程状态
> risk: 高（流程状态流转、业务表自动增量 DDL，需人工审查）

## 1. 背景与问题

低代码应用设计器存在三类阻断性体验问题：

1. 新建增强时，条件字段和“设置字段”动作要求用户手工输入字段编码，且缺少完整性校验，普通业务用户难以正确配置。
2. 新建页面组后立即在组内新增页面会报“请选择有效的页面组”，返回后未保存的页面组丢失。
3. 业务流程配置弹层超出可视区，表单资产无法正确选择，业务对象没有独立、受平台管理的审批流程状态字段。

本变更面向低代码平台通用能力，不针对 `presale_registration_apply` 写死应用、对象、表或流程标识。

## 2. 目标

### 2.1 应用增强

- 条件字段、设置字段动作改为可搜索的业务字段选择，不要求用户输入编码。
- 仅当应用只有一个业务对象或存在唯一主对象时自动选中对象；多对象且无法判定时给出明确引导。
- 设置字段仅展示可写业务字段；系统字段、只读字段、禁用字段不可作为目标。
- 历史配置中已不存在的字段以“已失效”兼容项展示，允许用户识别并修正，禁止静默丢值。
- 条件值和动作值尽量根据字段类型提供布尔、字典、数字、日期等合适编辑器；不能识别时保留文本输入。
- 保存前校验条件字段、运算符、动作目标和必需参数，错误定位到具体规则行。
- 校验并保证 `VISUAL_RULE`、`CLIENT_JS`、`SCOPED_CSS` 的发布、下发和运行时装载链路可用；服务端绑定保持既有语义。

### 2.2 页面组与页面

- 新建页面组后，本地设计草稿必须立即成为创建子页面的有效父节点。
- 在页面组选中状态下新增页面，父子关系稳定，不因页面类型选择器的异步过程引用旧 schema。
- 页面组和子页面创建后触发同一套草稿脏状态；保存、返回、重进后仍可恢复。
- 对不存在或已删除的父页面组给出可理解提示，不创建悬空页面。

### 2.3 业务流程配置

- 流程设计/配置弹层在常见屏幕高度下始终位于可视区内，内容区内部滚动，操作区可达。
- 表单选择统一使用业务流程表单资产协议 `formKey/formName`，并覆盖已发布 CRUD 表单；无资产时提供安全的当前对象表单回退。
- 关闭流程设计器后刷新流程模型、节点和表单资产，避免选项陈旧。
- 每个绑定流程的业务对象使用独立流程状态字段，禁止默认复用业务 `status`。
- 平台可一键或自动补齐受管理字段 `flowStatus`，并通过安全、幂等的增量 DDL 同步到对象物理表。
- 流程状态字典固定为：`DRAFT`、`IN_PROCESS`、`APPROVED`、`REJECTED`、`CANCELED`，页面使用字典展示。
- 新记录默认为 `DRAFT`；发起流程写 `IN_PROCESS`；审批通过写 `APPROVED`；驳回写 `REJECTED`；撤回/取消写 `CANCELED`。
- 流程状态更新必须幂等，并且只更新配置的流程状态字段，不覆盖业务状态字段。
- 手动开始动作按“列表行、详情、编辑表单”独立投影；同一流程启动后，该记录对应的启动按钮立即隐藏。
- 按钮显示条件支持多个字段，并可选择全部满足（AND）或任一满足（OR）。
- 应用运行页加载对象 CRUD 配置时必须携带当前应用入口上下文，避免对象被多个应用复用时投影到错误流程。

### 2.4 审批完成后的运行闭环

- Flowable 审批到达通过、驳回或取消终态后，必须恢复外层应用业务流程，并按审批节点对应出口继续执行。
- `UPDATE_RECORD` 动作节点必须使用发布态对象配置更新当前业务记录；字段赋值为空、目标对象不明确或字段无效时明确失败，不得静默跳过。
- 审批终态回调与动作执行必须幂等；重复回调不得重复执行后继动作。
- 应用页面列表已选择或由平台托管的 `flowStatus` 列，在工作台预览和正式运行页保持一致，不得被旧页面块的字段快照静默过滤。
- 详情页流程时间轴以真实 `processInstanceId` 为显示依据，不得要求对象同时启用单据模式；应用级业务流程也能查看审批历史和流程图。

## 3. 约束与关键设计

- 前端技术 ID 始终按字符串处理。
- 字段、表单、流程节点均由用户选择，普通路径不得要求输入技术编码。
- 查询 SQL 继续放在 Mapper XML 中；业务表结构变更复用现有对象字段发布/同步能力。
- 自动 DDL 只允许安全的加列或与现有受管理字段一致的幂等同步；不得删除、重命名或覆盖业务列。
- `flowStatus` 已存在时先验证类型和语义，兼容后直接复用；冲突时停止并给出处理指引。
- 新增平台字典走 Flyway，`tenant_id = 1`，所有插入具备 `NOT EXISTS` 防重复保护。
- 流程状态流转和自动 DDL 属于人工审查敏感项；代码、测试与执行日志必须单独列明。

## 4. 非目标

- 不重写 Flowable BPMN 设计器。
- 不修改业务自身 `status` 的枚举或历史数据。
- 不为单一应用生成专用 Flyway 表结构脚本。
- 不在本变更中引入破坏性表结构迁移。

## 5. 验收标准

1. 新建可视化增强时，选择对象后条件和设置字段均可通过中文名称搜索选择；单/主对象自动带出。
2. 无效历史字段有明显提示，缺失必填项无法保存，并指明具体行。
3. 三类前端增强均能进入运行时装载链路，禁用或未发布增强不会执行。
4. 新建页面组后不保存也能立即在其下新增页面；保存并重新进入后父子节点仍存在。
5. 流程配置弹层在 768px 高度屏幕可完整操作；表单下拉显示真实表单名称且能保存回显。
6. 绑定流程的对象可安全补齐 `flowStatus`，数据库列、字段元数据、字典和表单展示配置一致。
7. 流程五种状态按事件自动回写，业务 `status` 不受影响。
8. 前端定向测试与生产构建通过；后端相关单测/编译通过。环境不可用的真实 E2E 明确记录，不虚报结果。
9. 列表、详情、编辑表单的流程按钮按配置分别显示；流程启动后仅隐藏相同 `processCode` 的启动按钮，不误伤其他可并行业务流程。
10. 流程按钮显示条件可配置两条以上规则，AND/OR 及等于、不等于、包含集合、空值和数值比较在运行态正确计算。
11. 审批通过后外层业务流程从审批节点继续执行，后继“更新记录”动作能把配置值写入当前记录，重复回调不重复写入。
12. 页面块使用旧字段快照时，平台托管且列表可见的 `flowStatus` 仍能投影到工作台预览和正式运行列表；显式隐藏配置继续生效。
13. 未启用单据模式但存在审批流程实例的记录，详情页仍显示流程时间轴和流程图入口。
14. 审批节点选择“指定人员”后，BPMN 使用固定用户 ID 作为 `assignee`，不得生成未赋值的 `${user_<id>}` 表达式；历史已发布模型仍可发起且任务准确分配给原指定用户。

## 6. 回滚

- 前端交互可按组件级改动回滚，不影响已保存协议。
- 运行时装载保留兼容解析；回滚后历史增强配置仍可读取。
- 自动 DDL 仅新增列，不做自动删列；回滚代码后新增字段保留但停止自动流转。
- 流程绑定恢复旧配置时不得把 `flowStatus` 自动切换为业务 `status`。
