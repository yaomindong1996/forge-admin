# 租户作为工作区：去掉业务页租户选择
> status: apply
> created: 2026-08-31
> complexity: 🟡中等

## 1. 背景与目标

当前租户同时是「工作区上下文」和「页面筛选条件」。超级管理员查询默认忽略租户隔离，登录页在账号前就列出全部租户。用户感觉数据范围混乱。

完成后：

1. 当前租户 = 工作区。列表、树、新建都只属于当前租户。看别的租户只能切换工作区。
2. 只属于一个租户时：登录页不展示「登录租户」，登录后顶栏不展示切换。
3. 属于多个租户或超级管理员可进入多个租户时：只在登录后顶栏（及 H5 我的）切换。
4. 用户/角色/组织/岗位的搜索、表单不再出现「所属租户」。跨租户绑定只留在用户高级「租户关系」和租户管理。
5. 普通用户不需要理解租户概念。

## 2. 代码现状

- `TenantInterceptor` 对 `isAdmin()` 执行 `setIgnore(true)`，切租户不改变业务查询范围。
- 用户/组织/角色/岗位 Service 大量 `executeIgnore`，仅非超管才把 `query.tenantId` 写成当前租户。
- 登录页 `/auth/tenant/options` 返回平台全部启用租户，`length > 0` 即展示下拉。
- `TenantSwitcher` 单租户仍展示名称，只是禁用下拉。
- 组织页左侧有租户下拉且默认选列表第一项，用户页左侧树没有。

## 3. 业务规则

1. 查询、新建组织/角色/岗位/用户默认租户一律取 Session 当前 `tenantId`，忽略请求里的租户覆盖。
2. 超级管理员进入某租户后与租户管理员看到同一数据边界；`sys_tenant` 等平台表仍忽略隔离。
3. 用户多租户绑定只走 `bindUserTenants` / 高级关系页签 / 批量加入租户。
4. 登录页默认不展示工作区选择。先校验账号密码，该账号可进入多个工作区时才返回 4091 并展示「进入工作区」。
5. 顶栏切换仅当可切换租户数 > 1 时渲染。
6. 登录消歧不得在验密前按用户名返回租户列表。

## 4. 不在本轮

- 租户管理页本身（平台能力，继续给超管看全集）。
- 手机号/社交登录的工作区消歧与密码登录对齐，可后续单独补。
