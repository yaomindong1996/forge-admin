# 低代码应用权限统一配置

## 背景

当前低代码权限同时存在应用设计态 `node.access.roleIds`、发布投影的
`sys_role_resource`、系统角色授权和对象设计器“数据权限”四个入口，实际语义不同：

- 应用发布会按设计态角色重建页面资源绑定，覆盖角色管理中的运行态调整；
- 正式运行配置仍按发布快照中的角色 ID 过滤页面，与 RBAC 菜单权限不是同一真源；
- 应用工作台只可编辑页面角色，按钮仅展示当前账号状态，数据范围仍需跳转；
- 对象设计器维护的是数据范围字段映射，不是角色授权，但页面命名为“数据权限”；
- 动态低代码查询未携带对象模块编码，角色的对象级数据范围覆盖不会生效。

本变更属于权限变更，必须人工审查接口范围、权限溢出校验和回滚路径。

## 目标

在应用工作台的“权限”分区，以角色为主视角集中完成当前应用的：

1. 页面入口权限（应用访问入口与应用内页面）；
2. 绑定业务对象的按钮权限；
3. 绑定业务对象的数据范围覆盖。

系统角色管理继续提供跨应用全局授权；数据范围字段适配也迁移到应用权限工作台，
业务对象设计器不再保留数据范围配置入口。

## 核心决策

### 1. 运行态授权单一真源

- 页面和按钮授权唯一落库到 `sys_role_resource`。
- 对象级数据范围覆盖唯一落库到 `sys_role_module_data_scope`，模块编码统一为
  `ai:business:{objectCode}`。
- 应用发布只创建、更新和停用资源目录，不新增、删除或重建角色绑定。
- 应用权限管理只由 Admin 服务提供真实系统适配器；App 和 Flow 服务加载 generator
  运行能力时提供失败关闭桥接实现，不执行角色、资源或数据范围读写。
- 应用访问入口复用既有 `ai:businessApp:open:{appCode}` 菜单权限；未同步管理端菜单的入口展示为待同步状态。
- 正式运行页对应用内系统菜单页面按页面权限码
  `ai:business:application:{applicationCode}:page:{pageId}` 过滤。
- 存量 `node.access` 继续兼容读取和保存，避免历史 JSON 丢字段，但不再参与运行态鉴权，
  前端不再提供新的配置入口。

### 2. 应用范围聚合接口

新增应用权限聚合服务，返回：

- 当前操作者可维护的角色；
- 当前应用的访问入口、已声明的应用内系统菜单页面及其资源注册状态；
- 当前应用绑定对象、数据范围适配状态及已注册按钮资源；
- 选中角色在上述资源和对象模块上的授权状态。

保存接口只允许修改聚合服务计算出的资源 ID 和模块编码。系统角色服务在同一事务中：

- 删除并重建当前应用资源范围内的角色绑定，保留其它应用和系统权限；
- 删除并重建当前应用对象模块范围内的数据范围覆盖，保留其它模块配置；
- 复用既有角色可维护性、用户类型数据范围上限和权限溢出校验；
- 提交后刷新数据权限缓存。

### 3. 数据范围职责

- 应用权限工作台配置“该角色对该对象看哪些数据”。
- 应用权限工作台同时配置对象级 `FOLLOW_SYSTEM`、本人字段、组织字段和区划字段适配；
  对象适配对该共享对象的所有角色和关联应用生效，角色数据范围覆盖仍按角色保存。
- 对象设计器移除“数据范围适配”入口；原面板中的树形模型能力保留为独立的“树形模型”配置。
- 未启用 `FOLLOW_SYSTEM` 的对象在应用权限工作台展示为“仅租户隔离”，不允许配置角色覆盖，
  并允许在当前页面直接完成适配，不跳转业务对象设计器。
- `DynamicDataScopeService` 必须调用
  `getCurrentUserDataScope("ai:business:" + objectCode)`，使角色对象级覆盖真实生效。

### 4. 前端交互

权限分区复用系统角色管理现有 `RolePermissionSettings` 展示内核，避免应用工作台再维护一套
权限交互。应用工作台只负责角色选择、应用范围目录转换和应用范围保存：

- 顶部选择当前要配置的角色，并固定展示角色默认数据范围和保存状态；
- 下方沿用角色授权工作台的“模块导航 + 页面卡片 + 数据范围 + 功能权限”结构；
- “页面入口”模块只表达角色可以进入哪些业务访问入口和应用内页面；
- 每个绑定对象作为独立模块，在同一工作台内配置对象数据范围和按钮权限；
- 角色默认数据范围在应用工作台只读展示，不允许修改全局角色属性；
- 未同步菜单、未发布页面、未注册按钮和未完成数据范围适配均保留在目录中并展示不可配置原因；
- 对象卡片提供就地数据范围适配弹窗，保存时只更新模型策略字段，不提交整份对象设计器草稿；
- 当前角色存在未保存授权时，先保存或放弃角色草稿，再修改对象适配，避免刷新角色状态时丢失修改；
- 选择按钮权限时不隐式开放页面入口；页面入口与对象动作保持显式、可审计；
- 一次保存当前角色在当前应用的全部变更。

复用范围只包含展示与交互组件，不复用角色管理弹窗的全量资源保存接口。应用工作台仍调用
应用范围 PUT 接口，避免覆盖角色在其它应用、系统模块和客户端上的授权。

## API

| 方法 | 路径 | 用途 |
|------|------|------|
| `GET` | `/ai/business/application/by-code/{applicationCode}/permissions` | 应用权限目录与可维护角色 |
| `GET` | `/ai/business/application/by-code/{applicationCode}/permissions/roles/{roleId}` | 角色在当前应用的授权状态 |
| `PUT` | `/ai/business/application/by-code/{applicationCode}/permissions/roles/{roleId}` | 事务保存当前应用范围授权 |
| `PUT` | `/ai/business/application/by-code/{applicationCode}/permissions/objects/{objectId}/data-scope-adapter` | 就地保存对象数据范围字段适配 |

查询要求 `ai:businessApplication:list`，保存要求 `ai:businessApplication:edit`；系统角色服务还会执行角色管理范围校验。

## 不在本轮范围

- 不新增角色、不调整角色成员；
- 不在应用工作台修改角色的全局默认数据范围或自定义组织集合；
- 不改变工作流节点表单字段权限；
- 不删除存量 `node.access` JSON 字段，只停止把它作为授权真源。

## 风险与回滚

- 权限收敛风险：页面运行时从快照角色切换为 RBAC 权限码后，未分配页面资源的普通角色将看不到该页面。
  发布前已有绑定保留；管理员可在应用权限工作台补授权。
- 并发风险：保存以角色和应用资源范围为边界执行事务替换；同一角色同一应用的最后一次提交生效，
  不影响其它应用范围。
- 回滚代码即可恢复旧鉴权；本轮不新增表结构。已写入的 `sys_role_resource` 和
  `sys_role_module_data_scope` 均为既有结构，可由系统角色管理继续维护。

## 验收标准

1. 应用权限分区可选择角色并在一个页面配置页面、按钮、对象数据范围。
2. 保存应用 A 不改变同一角色在应用 B 和系统管理模块的资源权限。
3. 应用重新发布不覆盖应用权限工作台或角色管理已有授权。
4. 无页面权限的普通用户无法在正式运行配置中获得对应系统菜单页面。
5. 对象配置 `FOLLOW_SYSTEM` 后，对象级角色数据范围覆盖参与动态 CRUD SQL 条件生成。
6. 未发布页面、未注册按钮和未完成数据范围适配均有明确不可配置状态。
7. 数据范围适配可在应用权限分区完成，业务对象设计器不再出现该入口，保存适配不会覆盖表单、页面或关系配置。
