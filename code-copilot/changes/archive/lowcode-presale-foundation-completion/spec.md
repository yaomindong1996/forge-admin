# 低代码表单移动扫码与动态字段基础能力

> status: completed
> created: 2026-08-11

## 目标

补齐通用低代码表单在 H5 和主子表场景下的运行能力，使实施人员可以通过设计器配置条码扫描、字段事件、动态选项和显示规则，不编写预售专用页面代码。

## 范围

- 新增 `barcodeScanner` 表单字段；企业微信优先使用宿主 SDK，普通 H5/浏览器使用受控摄像头扫码能力，并统一复用 `SCAN_COMPLETE`。
- 动态显示规则支持显式“显示/隐藏”效果；静态隐藏但配置了可见性规则的字段仍进入发布快照，运行时按规则显示和隐藏。
- 子表所有需要运行规则、查询事件、扫码或动态选项的字段使用同一字段运行时，事件上下文严格绑定当前行。
- 下拉/选择字段支持当前主记录子表集合的受控动态选项来源。
- 事务动作提供发布态 `ASSERT_RECORD` 状态门禁，并保持父子归属、租户、数据权限和数量边界校验。

## 非范围

不新增预售、会员、商品、收款或企业微信业务类；不修改需求原型/PRD HTML；不开放任意 URL、SQL、脚本、Header 或客户端身份覆盖；不启动真实外部系统做联调。

## 验收标准

1. 发布态默认隐藏字段在条件满足时显示，条件变化后再次隐藏；隐藏字段不参与必填校验。
2. H5 页面点击扫码可获得条码值，权限拒绝、取消、超时、无结果均返回稳定错误码并停止媒体流；企业微信和扫码枪 Enter 兼容。
3. 子表行扫码/字段查询只修改当前行，多个行并发请求互不覆盖；当前子表集合可作为受控选择项来源。
4. `LOCAL_TRANSACTION` 动作在状态门禁不满足或目标记录不属于当前父记录时失败关闭，数量调整不会越界。

## 风险与验证

前端运行时和设计器执行 Vitest/ESLint/生产构建；generator 相关 Java 模块执行定向测试和聚合编译；Flyway/真实数据库和扫码设备联调留待部署环境按已有分工补验。

## 本轮实现结论

- 已完成动态可见性规则、H5/企业微信扫码字段、子表行级事件与动态选项、事务状态门禁和数量边界能力。
- 运行规则和 `barcodeScanner` 已进入发布运行快照；静态隐藏但带可见性规则的字段会保留到运行时，并在隐藏时不参与必填校验。
- 已通过前端定向 Vitest（36 项）、generator 定向 Java 测试（30 项）和前端生产构建。
- 运行态表单编译已覆盖 `barcodeScanner` 字段白名单/默认映射，并保留静态隐藏字段的 `hidden/formVisible` 基线。
- 旧版“状态联动 → 显示/隐藏”配置会在表单协议规范化时迁移为目标字段运行规则，不再出现设计器有配置、运行页无效果；“满足时显示”默认在条件不满足时隐藏。
- 子表运行时已补齐独立扫码上下文、字段事件识别和动态必填校验；扫码字段关闭手工输入后会以只读输入框展示。
- 聚合测试命令的上游 `forge-plugin-message` 既有测试构造器与当前服务构造器不匹配，未进入 generator 测试阶段；该问题不属于本变更文件范围，已在执行记录中保留证据。
- 真实设备摄像头、企业微信生产容器、MySQL 行锁/回滚和 Flyway 实跑仍需部署环境补验。
