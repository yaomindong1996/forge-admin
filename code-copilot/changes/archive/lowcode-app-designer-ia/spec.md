# 应用设计器信息架构重构方案

> status: draft
> created: 2026-08-14
> parent: lowcode-platform-architecture/spec.md
> scope: 回答 6 个体验问题，重构应用中心信息架构，对齐飞书/简道云搭建范式
> complexity: 🔴🔴 高（纯前端信息架构 + 布局，不改运行时协议）

---

## 一、根因：不是 6 个 bug，是 1 个架构问题的 6 种表现

前序 Phase 1-6 把**协议层**打通了（pageSections、bottomBar、pageSchema.zones、CALL_API 都能跑），
但**信息架构层**没动。当前存在三个结构性缺陷：

### 缺陷 A：双壳并存，同一配置两个入口

```
/app-center/application/PRESALE_REGISTRATION_APP           ← 应用控制台（壳 1）
├── 概览 / 业务对象 / 页面入口 / 业务流程 / 动作与增强 / 权限 / 发布
│
└──[设计页面]──> /app-center/application/PRESALE_...?edit=1  ← 应用设计器（壳 2）
                 ├── 页面 / 事件 / 动作与增强 / 业务流程 / 数据模型 / 设置
                 └────────────  ↑ 与壳 1 重复 3 项  ────────────
```

`业务流程`、`动作与增强`、`权限/设置` 在两个壳里都有。用户不知道该在哪配，配完不知道另一边会不会覆盖。

### 缺陷 B：Tab 按"配置类型"切，不按"编辑对象"切

飞书/简道云的范式是 **先选资源，再看它的配置**（选中一张表单 → 右侧就是这张表单的属性）。
Forge 当前是 **先选配置类型，再选对象**（先点「事件」Tab → 再从顶部下拉切换"当前数据对象"）。

这个反转导致：
- 用户脑子里的问题是"我想改预售登记这张表单"，但界面要求他先回答"你想改的是事件还是动作"
- `事件` Tab 里装的其实是**完整的表单设计器**（`initialPanel: 'form'`），所以用户找不到"表单设计"在哪
- 每个 Tab 顶部都要挂一个"当前数据对象"选择器（`.application-object-context`），重复且占空间

### 缺陷 C：布局用左右分栏承载主从关系

`业务流程` Tab 把两个**各自带完整 heading 和独立滚动条的长表单**塞进 `420px + 1.35fr` 的 grid：
左边应用级流程交互，右边整个对象设计器。用户要在两个滚动区之间横向来回。

## 二、逐条回答用户的 6 个问题

### Q1：业务对象管理操作列是不是只保留"移除"？

**不是只保留移除，保留「编辑字段」+「⋯移除」两项。**

当前 4 个按钮（`ApplicationObjectsPanel.vue` L75-80）：

| 按钮 | 去向 | 处置 | 理由 |
|------|------|------|------|
| 数据结构 | 对象设计器 fields 面板 | **保留**，改名「编辑字段」 | 字段定义是对象的独占能力，控制台里点进去合理 |
| 设计表单 | 对象设计器 form 面板 | **删除** | 表单属于"页面"资源，正规入口在设计器页面树，这里是重复入口 |
| 业务动作 | 对象设计器 actions 面板 | **删除** | 动作属于"自动化"资源，同上 |
| 移除 | 解除应用关联 | **保留**，收进「⋯」 | 破坏性操作不应与普通操作平铺 |

最终：`编辑字段 | ⋯`（⋯ 内含"移除出应用"，红色 + 二次确认）。

判据：**控制台的操作列只放"这个资源本身的属性"和"关系管理"，不放"跳到别的资源类型去设计"。**

### Q2：点「设计页面」到底在设计哪个页面？

**当前确实无法回答，因为它不设计任何具体页面 —— 它进入的是应用级页面编排画布（空白态）。**

`openApplicationPageDesigner()` 跳 `?edit=1`，落到 `designerSection = 'page'` 的 builder 画布。
而用户心里的"预售登记页面"实际存在于**对象的 formDesignerSchema + pageSections 里**，
在页面树中完全不可见。所以入口和用户心智模型错位。

**修正**：
1. 按钮文案 `设计页面` → `打开设计器`
2. 设计器左栏建立**页面资源树**，把对象的表单页/列表页**显式列为节点**
   （详情页不设独立节点：它的主信息是表单布局的只读镜像，见 Q4 补充说明）：
   ```
   📄 页面
   ├── 预售登记（表单页 · PRESALE_REGISTRATION）   ← 点它 = 编辑这张表单和它的分区
   ├── 预售单列表（列表页 · PRESALE_REGISTRATION）
   └── 首页（自定义编排画布）
   ```
3. 进入设计器默认选中**第一个页面节点**，不再是空画布

这样"设计哪个页面"由树上的节点名直接回答。

### Q3：顶栏「设置」后面三个点位置错乱

**根因**：`.application-designer-tabs` 用 `margin-inline: auto` 在 flex 容器里居中，
而右侧操作区的每个按钮都挂了 `v-if="designerSection === 'page'"`：

| 当前 Tab | 右侧可见按钮 | 右区宽度 |
|---------|------------|---------|
| 页面 | 撤销/重做/页面资源/保存/预览/发布/⋯ | ~420px |
| 事件·动作·数据模型 | 保存/发布 | ~180px |
| 业务流程 | 保存/发布 | ~180px |
| 设置 | 仅发布 | ~90px |

右区宽度从 420px 塌缩到 90px，`margin-inline: auto` 的居中基准随之改变，
**中间 Tab 条整体向右漂移 300 多像素** —— 这就是"位置错乱"。

**修正**：
1. `.runtime-header` 改 `display: grid; grid-template-columns: minmax(240px, 1fr) auto minmax(240px, 1fr)`，Tab 条固定占中列
2. 右侧操作区 `justify-self: end` + `min-width: 320px`
3. **按钮不再增删，改为 `disabled`**：撤销/重做/页面资源/预览在非页面 Tab 下置灰而非消失，保持宽度恒定
4. `保存草稿`、`发布应用`、`⋯` 三个按钮**在所有 Tab 下恒定可见**（设置 Tab 也要能保存）

原则：**顶栏是应用级操作区，其内容不应随 Tab 变化。**

### Q4：事件 Tab 的按钮错位、蓝色区域突兀、Tab 命名不当、表单设计在哪

四个子问题，全部指向"`事件` Tab 里其实装了整个表单设计器"。

**4a. 突兀的蓝色区域** = `ForgeFormDesigner.vue` L121-137 的「表单切换」条，
`.designer-form-tab.active` 样式为 `border-color:#2563eb; background:#eff6ff`（L1768）。
它是个蓝底蓝框的实心色块，与顶栏下划线式 Tab 风格冲突，且在事件配置场景毫无意义（只有一个主表单时仍然渲染）。

**修正**：改为下划线式（`border-bottom: 2px solid #2563eb` + 透明背景），与 `.application-designer-tab` 统一；`formAssets` 为空时整条不渲染。

**4b. 「页面分区」按钮错位** = 它被塞进 `.page-switch-actions`（L138-144），
和撤销/重做/清空/⋯/属性栏开关 5 个圆形图标按钮并排。
一个带文字的语义化功能按钮混在图标工具组里，视觉重量不匹配。

**修正**：`页面分区` 不做按钮，改为**画布视图切换**：
```
[ 表单布局 | 页面分区 ]     ← 画布左上角 segment 切换，同一份 schema 两种视图
```
理由：分区和字段布局编辑的是同一份 `formDesignerSchema`，用弹窗（当前是 1240px n-modal）割裂了上下文，
用户配完分区要关弹窗才能看字段。

**4c. PageSectionEditor 内部左右标题栏不齐**：
`.workbench-heading` 有 `min-height: 58px` + 白底 + 底边框（L946-951），
右侧 `.settings-heading` 只有 `padding-bottom: 16px`、无固定高度（L1069-1072）。
两侧标题基线和高度都不同 → 右侧「删除分区」按钮比左侧「新增」按钮低。

**修正**：两侧 heading 统一 `min-height: 48px`、统一内边距、统一底边框。

**4d. Tab 叫「事件」不合适 / 表单怎么设计** —— 这是最关键的一条。

**取消「事件」这个 Tab。** 表单设计不是"事件"的子功能，反过来才对：事件是字段/表单的属性。

```
现状                              目标
─────────────────────            ─────────────────────
事件 Tab                          页面 Tab
 └ 表单设计器                       └ 页面树选中「预售登记（表单页）」
    └ 右侧属性面板                     └ 表单设计器画布
       └ events 子 Tab  ← 深 4 层          └ 右侧属性面板
                                              ├ 组件属性
                                              └ 事件与联动  ← 选中字段时可见
```

表单设计的正规入口 = 页面树里的表单页节点（Q2 的方案）。
事件配置作为表单设计器右侧属性面板的一个 Tab，选中字段时才出现 —— 因为事件本来就是字段级配置。

### Q5：业务流程左右布局比之前还乱

**根因**：`.application-flow-workbench` 把两个长表单并排（L4092-4107）。
更致命的是**左侧「节点分区策略」要求用户手填字符串**
（`ApplicationFlowInteractionPanel.vue` L58-72）：
- `nodeKey` 手填"流程节点标识，如 managerApproval" → 用户必须去 BPMN 里抄
- `visibleSectionIds` / `readonlySectionIds` 用 `n-dynamic-tags` 手打分区 ID → 用户必须去 pageSections 里抄

这是"我根本不会用"的直接原因：**配置项要求用户跨三个界面手工搬运标识符。**

**修正为纵向三段式，取消左右分栏**：

```
┌─ 流程绑定 ────────────────────────────────────────┐
│ 流程模型 [预售单审批 V3 ▾]   启动方式 [提交时自动启动 ▾]  │
└──────────────────────────────────────────────────┘
┌─ 节点配置 ────────────────────────────────────────┐
│ 节点          办理人        可见分区      只读分区      │
│ 提交          发起人        全部         —          │  ← 节点从流程模型
│ 门店经理审批   角色:店长     4/6 选中     2 个        │     自动读出
│ 财务复核      角色:财务      3/6 选中     3 个        │     不再手填
│   └ 点击行展开：分区用多选下拉（选项来自 pageSections）      │
└──────────────────────────────────────────────────┘
┌─ 高级（默认折叠）─────────────────────────────────┐
│ 审批按钮 / 审批时间轴 / 完成回调                        │
└──────────────────────────────────────────────────┘
```

三条硬性改动：
1. **节点列表从选定的流程模型自动解析**，禁止手填 nodeKey。
   数据源已存在：`businessFlowVariables(modelKey, { objectCode })` 返回的 `userTasks`
   （后端 `BusinessFlowVariableResolver` 解析 BPMN XML，`BusinessFlowBindingPanel.vue` 已在调用），**无需新增后端接口**
2. **分区选择用下拉多选**，选项来自当前表单的 pageSections（显示分区标题，存 sectionId），禁止手打 ID。
   不勾选即空数组，H5 运行时既有语义为"全部可见"，UI 用一行说明文案表达，不引入额外选项
3. **审批按钮/时间轴/回调收进"高级"折叠**，默认不占视觉空间

### Q6：控制台的业务流程/动作增强/权限该整合进设计器吗？

**该整合。判据：改配置的进设计器，看状态和授权的留控制台。**

| 控制台当前 section | 处置 | 去向 |
|------------------|------|------|
| 概览 overview | **保留** | 运营视角：用量、健康度、最近发布 |
| 业务对象 objects | **保留**（按 Q1 精简操作列） | 应用与对象的关系管理 |
| 页面入口 entries | **保留** | 菜单/入口挂载，属于"投放"不属于"设计" |
| 业务流程 automation | **移入设计器** | 设计器 → 流程 |
| 动作与增强 enhancements | **移入设计器** | 设计器 → 自动化 |
| 权限 permissions | **拆分** | 「按钮/字段权限」→ 设计器；「谁能访问这个应用」→ 控制台 |
| 发布 releases | **保留** | 发布记录、版本回滚、发布检查 |

整合后：**控制台 4 项**（概览/业务对象/页面入口/发布）+ **访问授权**；设计器承接全部配置动作。

## 三、目标信息架构（对齐飞书 aPaaS / 简道云）

参考范式的三条共性：
1. **一个应用一个编辑器**，没有"控制台配一半、设计器配一半"
2. **左栏是资源树，不是功能菜单** —— 树上的节点是"东西"（这张表单、这个流程），不是"配置类型"
3. **顶栏恒定**，右侧属性面板随选中资源变化

### 3.1 目标结构

```
应用设计器（唯一配置入口）
│
├─ 顶栏（恒定，永不增删按钮）
│   [← 应用工作台]  预售登记应用 · 已保存到草稿
│                              [保存草稿] [预览] [发布应用] [⋯]
│
├─ 左栏 资源树（232px，可折叠）
│   │
│   ├─ 📄 页面
│   │   ├─ 预售登记（表单页）        ← 表单布局 / 页面分区 / 底部操作栏
│   │   ├─ 预售单列表（列表页）      ← 列名 / 筛选 / 行操作
│   │   └─ 工作台首页（自由编排）
│   │
│   ├─ 🗄 数据
│   │   └─ 预售登记单               ← 字段 / 对象关系 / 数据权限
│   │
│   ├─ ⚡ 自动化
│   │   ├─ 触发器
│   │   └─ 业务动作与增强
│   │
│   ├─ 🔀 流程
│   │   └─ 预售单审批               ← 绑定 / 节点配置 / 高级
│   │
│   └─ ⚙️ 设置
│       └─ 按钮权限 / 字段权限 / 字典
│
└─ 工作区（随选中节点变化）
    画布 + 右侧属性面板（属性面板内容随画布选中元素变化）
```

### 3.2 与当前 6 Tab 的映射

| 当前 Tab | 目标位置 |
|---------|---------|
| 页面 | 📄 页面 → 自由编排节点 |
| 事件 | **取消**，能力拆到 📄 页面（表单设计）+ 属性面板「事件与联动」 |
| 动作与增强 | ⚡ 自动化 |
| 业务流程 | 🔀 流程（按 Q5 重构布局） |
| 数据模型 | 🗄 数据 |
| 设置 | ⚙️ 设置 |

### 3.3 关键差异：干掉「当前数据对象」全局选择器

当前每个 Tab 顶部都挂 `.application-object-context`。
目标架构下，对象上下文由**树上选中的节点**隐含决定（选中"预售登记（表单页）"就已经确定了对象），
该选择器整体删除。

## 四、分阶段实施

拆四个阶段，**每阶段独立可交付、可回滚**，不做一次性大爆炸重构。

### Phase A：止血 —— 布局错位与视觉突兀（P0，1 天）

只改 CSS 和按钮显隐条件，**不动信息架构**，风险最低，用户立刻感知改善。

| 项 | 文件 | 改动 |
|---|------|------|
| A1 顶栏三栏栅格 | `application-runtime.[applicationCode].vue` | `.runtime-header` 改 grid，Tab 占中列 |
| A2 顶栏按钮恒定 | 同上 | 撤销/重做/页面资源/预览改 `disabled`，不再 `v-if` 消失 |
| A3 保存按钮全 Tab 可见 | 同上 | 移除 `designerSection !== 'settings'` 限制 |
| A4 表单切换条去蓝底 | `ForgeFormDesigner.vue` | `.designer-form-tab.active` 改下划线式；`formAssets` 为空不渲染 |
| A5 分区编辑器左右对齐 | `PageSectionEditor.vue` | `.workbench-heading` / `.settings-heading` 统一 48px |

**验收**：1024px 和 1440px 下切换全部 6 个 Tab，中间 Tab 条位置零漂移；事件 Tab 无蓝色实心块。

### Phase B：入口去重 —— 解决"不知道在哪配"（P0，2 天）

| 项 | 改动 |
|---|------|
| B1 对象操作列精简 | `ApplicationObjectsPanel.vue` 改为 `编辑字段 \| ⋯(移除出应用)` |
| B2 控制台移除重复 section | 隐藏 `automation` / `enhancements`，`permissions` 只留访问授权 |
| B3 「设计页面」改名 | → `打开设计器` |
| B4 控制台补跳转 | 被隐藏的 section 位置放引导卡："业务流程已移入设计器 → [打开设计器]" |

**验收**：`业务流程`、`动作与增强` 在控制台和设计器中只存在一处入口。

### Phase C：页面资源树 —— 解决"设计哪个页面"（P1，4 天）

核心阶段，建立以资源为中心的左栏。

| 项 | 改动 |
|---|------|
| C1 左栏改资源树 | 6 个平铺 Tab → 分组树（页面/数据/自动化/流程/设置） |
| C2 页面节点显式化 | 对象的表单页/列表页/详情页作为树节点列出 |
| C3 删除对象选择器 | 移除 `.application-object-context`，上下文由节点决定 |
| C4 取消「事件」Tab | 表单设计由页面节点承接；事件保留在属性面板 |
| C5 分区改视图切换 | `页面分区` 从 modal 改为画布 `[表单布局 \| 页面分区]` segment |

**兼容**：旧 `?section=events` 等深链映射到对应新节点，不 404。

### Phase D：流程配置重构 —— 解决"完全没懂"（P1，3 天）

| 项 | 改动 |
|---|------|
| D1 取消左右分栏 | `.application-flow-workbench` 改纵向三段 |
| D2 节点自动解析 | 从选定流程模型读 BPMN userTask，生成节点表格 |
| D3 分区改下拉多选 | `visibleSectionIds` / `readonlySectionIds` 选项来自 pageSections |
| D4 高级项折叠 | 审批按钮/时间轴/回调收入折叠区 |

**验收**：不查任何其它界面、不手打任何标识符，能完成"财务复核节点隐藏付款分区"的配置。

## 五、设计规范补充（防止再次走乱）

沉淀为后续开发红线：

1. **Tab 命名必须是名词性资源，不是配置类型**：「页面」「数据」可以，「事件」「增强」不可以
2. **禁止两个带独立 heading 和滚动条的长表单左右并排**；主从关系用"列表 + 行展开"或纵向分段
3. **顶栏按钮禁止随 Tab 增删**，只能 `disabled`
4. **禁止要求用户手填另一个界面的标识符**（nodeKey、sectionId、fieldName），必须提供来源下拉
5. **同一份 schema 的不同视图不用 modal 承载**，用画布视图切换
6. **激活态用下划线或左边框，不用大面积蓝色填充块**（`#eff6ff` 只用于 hover 和小面积 badge）
7. **同一个配置只允许一个入口**；需要多处到达时，非主入口只做跳转引导，不内嵌编辑器

## 六、验收路径（预售登记全流程）

以"新用户第一次配置预售登记"为验收剧本，全程不看文档、不写 SQL：

1. 应用控制台 → 看到预售登记单对象 → 点「打开设计器」
2. 左栏 📄 页面 → 看到「预售登记（表单页）」→ 点开，画布显示当前表单
3. 画布切到「页面分区」→ 看到 6 个分区（导购/会员/付款/备注/明细/日志）→ 调整顺序、改标题
4. 切「表单布局」→ 选中"会员手机号"字段 → 右侧属性面板「事件与联动」→ 配置查询会员
5. 左栏 🔀 流程 → 选「预售单审批」→ 节点表格自动列出 3 个节点 → 财务复核行展开 → 可见分区下拉取消勾选"付款信息"
6. 顶栏「保存草稿」→「预览」→ 手机上看到多分区单页 + 底部提交栏
7. 顶栏「发布应用」→ 控制台发布记录出现新版本

**任一步需要跳出去查标识符、或找不到入口，即验收失败。**

## 七、风险与回滚

| 风险 | 影响 | 缓解 |
|------|------|------|
| Phase C 改左栏结构，旧深链失效 | 用户书签打不开 | 旧 `?section=xxx` 全量映射到新节点，保留 2 个版本 |
| Phase D 节点自动解析依赖 BPMN 结构 | 流程模型无 userTask 时表格为空 | 空态回退到手填模式，不阻塞配置 |
| Phase B 隐藏控制台 section | 用户找不到已有配置 | 原位置放引导卡 + 一键跳转，不直接删除 |
| Phase C 取消「事件」Tab | 已配置的 fieldEvents 找不到 | 属性面板「事件与联动」Tab 有配置时显示红点标记 |

**回滚原则**：A/B/D 三阶段纯前端，`git revert` 即可。
C 阶段涉及路由映射，回滚需同步恢复旧 Tab 定义（`application-designer-navigation.js`）。

## 八、优先级建议

**先做 A + B（3 天）**，用户能立刻感受到"不乱了"：错位修好、重复入口消失。
**再做 D（3 天）**，因为"业务流程完全没懂"是当前最影响功能可用性的一条。
**最后做 C（4 天）**，它改动面最大但收益最结构性，需要 A/B 先把地基理顺。
