# 门店预售登记低代码应用

> status: completed
> created: 2026-08-11

## 目标

基于 Forge 已有低代码运行时交付“门店预售信息登记”应用，不新增预售专用 Java Controller、Service 或 Vue 页面。应用覆盖企微/H5 登记、会员/商品/收款查询、主子表保存、动态字段显示、条码扫码、预售单提交、提货和退货事务动作。

## 输入依据

- `code-copilot/changes/20260810需求/预售信息登记-原型图.html`
- `code-copilot/changes/20260810需求/预售信息登记应用-PRD.html`

原型和 PRD 只作为需求输入，本变更不得修改这两个文件。

## 范围

- 新建预售主单、商品明细和操作日志三张低代码运行表及对应模型、业务对象、关系和 CRUD 配置。
- 使用 `barcodeScanner` 支持企业微信 SDK 和普通 H5 摄像头扫码，扫码完成后通过 `SCAN_COMPLETE` 查询受管商品源。
- 使用 `runtimeRules` 根据收款方式动态显示静态码字段或现金金额；隐藏字段不参与必填校验。
- 使用字段事件查询企微用户/工号/门店映射、会员、商品和静态码收款信息。
- 使用 `BusinessAction` 的 `LOCAL_TRANSACTION`、`ASSERT_RECORD`、`TRANSITION_STATUS`、`ADJUST_NUMBER` 和 `CREATE_RECORD` 实现提交、提货、退货。
- 使用单据配置生成 `PS-{yyyyMMdd}-{seq4}` 预售单号。
- 创建业务应用聚合、三条对象关联、移动运行入口和四条待绑定集成项。
- 独立 `forge-h5-ui` 通过通用运行页加载发布态低代码配置，复用动态 CRUD、字段事件和业务动作接口；不新增预售专用业务页面。

## 安全和一致性约束

- 字段事件只引用稳定 `sourceKey`，应用元数据不得保存 URL、Header、认证凭据、任意 SQL、脚本或处理器。
- 浏览器提交的企微 userid、租户、组织信息不作为授权依据；服务端继续以可信 Session、租户、ACL 和数据权限为准。
- 提货/退货动作只读取不可变发布快照；父子归属、状态、数量上限在同一本地事务和行锁范围校验。
- 业务表保留 `tenant_id`、审计字段和 `del_flag`；预售单号跨历史永久唯一，删除后不复用原单号。

## 外部依赖

以下查询源由受管查询源/集成中心提供，可以使用 HTTP API、受管数据库查询或经过安全治理的服务端脚本：

- `wecom/user-store`
- `member/member-by-mobile`
- `product/product-by-barcode`
- `payment/static-code`

初始迁移通过受管 `MOCK` 执行模式预置可用测试数据和输入/输出契约；不保存真实 URL、认证、数据库表、任意 SQL 或服务端脚本。真实联调时在“外围接口管理”将对应接口切换为 `HTTP`，再配置受控连接信息。

## 验收标准

1. 企业微信和普通 H5 均能在商品行扫描条码，且只回填当前行。
2. 收款方式切换时对应字段立即显示/隐藏，隐藏字段不阻断提交。
3. 新建预售单自动生成单号；草稿可提交为已提交状态。
4. 提货数量不得超过当前未提数量，退货数量不得超过已提数量；日志和数量调整同事务成功或回滚。
5. 应用、对象、关系、页面、动作和查询源引用全部由低代码元数据交付，无预售专用页面/接口代码。
6. 移动入口打开地址指向 `/forge-h5/#/pages/lowcode-runtime` 并携带 `configKey`；H5 支持列表、表单、详情、主子表、动态显隐、字段查询、扫码及动作。

## 未覆盖验证

真实 Flyway/MySQL、企业微信生产容器、真实手机摄像头及四个外部查询源联调由部署环境执行；本轮只做静态合同、单元测试、模块编译和前端构建。

## 实施结论

- 预售应用已完全落到通用低代码元数据和平台运行时，不包含预售专用 Java/Vue 实现。
- 应用已具备扫码、动态字段、外部查询回填、主子表、单号、草稿提交、提货和退货闭环。
- 现金金额字段遵循通用 MONEY 协议：H5/企微表单按元输入并保留两位小数，整数数据库列按分存储，读取回填按元展示；历史 decimal MONEY 字段不受影响。
- 四个集成挂接初始启用并指向受管 Mock 查询源，预售应用可在没有外围系统的环境中完成页面和字段事件验证；真实环境将接口执行模式切换为 HTTP 后无需改动预售低代码元数据。
- 外围接口管理支持 `HTTP` / `MOCK` 执行模式。Mock 仅返回管理员配置的 JSON，仍执行接口状态、权限和调用日志，但不发起出站 HTTP、不运行脚本或 SQL。
- generator 定向测试 49 项、前端 MONEY 增量测试 30 项，既有前端定向测试 43 项、Java 17 聚合编译和前端生产构建均通过。
- 新增 V1.0.106 checksum-safe 修复迁移：主模型改为 `MASTER_DETAIL`、两个明细模型改为 `SINGLE`，主模型字符串 `children` 改为空模型数组，并同步修复业务域默认值、配置和历史发布快照。
- 同一修复迁移将两个明细模型的 `presaleOrderId` 外键从非法的 `systemField` 标记改为隐藏的只读业务字段，避免明细对象校验继续失败。
- `app-server` 已直接补齐 generator 运行时所需的 `forge-flow-client` 类路径，移动低代码入口固定落到 `/forge-h5/#/pages/lowcode-runtime` 并携带 `configKey`。
- H5 扫码失败不会误触发商品查询；不支持摄像头时保留手工录入，并可通过输入法确认键触发同一个 `SCAN_COMPLETE` 受管查询事件。
- H5 字段事件运行时遵循 `skipWhenEmpty`、`clearTargetsOnTrigger`、CHANGE 防抖和过期请求失败关闭语义；保存前同时校验主表和已渲染明细行的动态必填字段。
- 业务对象设计快照版本与关联 CRUD 发布版本独立编号：对象设计版本始终由自身历史递增，避免种子快照 v1 与后续首次 CRUD 发布 v1 发生唯一键冲突。
- App 服务只运行低代码发布快照和动态 CRUD，不维护 Admin 菜单；通过无操作 `MenuRegisterAdapter` 完成 generator Service 装配，菜单写入仍由 Admin 服务执行。
- App 服务不启用 AI 生成插件；通过失败关闭的 `AiClientAdapter` 完成 generator Service 装配，任何误调用都会返回 fallback/不支持错误，不会发起外部模型请求。
