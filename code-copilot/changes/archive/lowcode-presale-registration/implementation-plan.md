# 门店预售登记低代码应用实施计划

**目标：** 用 Forge 通用低代码协议交付预售登记应用，并保留部署环境对真实外部查询源的配置边界。

**架构：** 页面复用 `AiCrudPage`、表单设计器、字段事件和协同扫码运行时；数据使用三个动态 CRUD 模型及主子关系；写操作复用已发布 `BusinessAction`，在 Forge 主数据源事务内完成状态、父子归属和数量校验。

## 文件边界

- 平台运行时：既有扫码、字段规则、字段事件、子表动作和 BusinessAction 通用实现。
- 业务交付：`forge-server/db/migration/V1.0.105__seed_presale_registration_lowcode_app.sql`。
- 后端测试：数值门禁策略/执行器测试和预售 Flyway 合同测试。
- SDD 记录：本目录的 `spec.md`、`tasks.md`、`test-spec.md`、`execution-log.md`。

## 执行阶段

1. 复核原型/PRD与现有低代码能力缺口。
2. 补齐 H5 扫码、动态字段、子表事件和事务门禁等平台能力。
3. 写入预售数据模型、表单、页面、动作、单号和应用聚合元数据。
4. 保留四个停用查询源挂接，部署时选择 API、受管数据库查询或安全服务端脚本实现。
5. 执行增量测试、构建与静态检查，记录未覆盖的真实环境联调项。
