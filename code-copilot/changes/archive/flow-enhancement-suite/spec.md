# 流程审批增强能力

## 目标

为 Forge Flowable 流程提供可配置的多级指定节点退回、发起人自选审批人、可扩展待办业务展示、发起人/管理员改派当前任务、驳回至发起人修改路径，以及可读模型 Key。

## 范围

1. `sys_flow_model` 增加 `allow_multi_return`，模型配置页可切换“允许多级退回”。任务退回接口接受可选 `targetActivityId`；关闭开关时只允许历史上一个可退回节点，打开后允许选择当前流程历史用户任务。目标节点必须属于同一流程实例，禁止跳转到当前节点或非用户任务。保留不传目标节点时的“上一节点退回”兼容行为。
2. 任务表单策略返回 `allowMultiReturn` 与历史可选退回节点，前端审批页可按策略提交指定节点退回；业务流程仍可通过 BPMN 自己设计驳回回路。
3. 审批人配置新增“发起人自选”。设计器将节点 key 作为 `PROCESS_START_USER['<nodeKey>']` 的多实例集合表达式，启动时变量协议为 `Map<String,List<Long>>`，key 为 userTask 节点 key；节点内每位选中审批人生成一个任务。
4. `FlowBusinessListDisplayItem` 增加 `businessType`、`businessParams`，业务侧 SPI 可以按业务类型读取参数并回填对象名、摘要及扩展参数；待办实体和前端卡片保留这些扩展字段。
5. 新增用户侧任务改派 DTO/API。只有当前处理人、任务 owner 或流程发起人可调用；管理员接口继续由流程监控权限保护。底层设置 owner 后再设置 assignee，保持本地待办为待处理，并校验本地任务、Flowable 任务、流程实例和租户一致。
6. 审批节点新增“驳回至发起人”动作权限。动作只写入 `rejectToStart=true` 与 `approvalResult=reject`，具体进入哪个发起人修改节点由业务 BPMN 网关/回路配置；申请人修正退回数据后可选择直送原驳回节点，跳过中间审批节点。
7. 创建模型时允许提交合法自定义 Key；服务端校验 `[A-Za-z][A-Za-z0-9_-]{1,63}`、租户内唯一，已发布/挂起模型仍不可修改。前端新增模型时可编辑 Key，默认仍生成安全 Key。

## 非目标

- 不改变 Flowable 原生 ACT_* 表。
- 不把动态业务记录固定字段改成 Map 请求体；只有 `variables` 和 SPI 的动态 `businessParams` 保持 Map。
- 不自动改写已有非空 BPMN XML；设计器仍是节点配置的唯一来源。
- 不在平台代码中硬编码某个“发起人修改”节点 ID；业务需在 BPMN 中配置对应回路和条件表达式。

## 安全与一致性

- 所有改派、指定退回都校验任务/流程实例存在，并通过当前租户流程锁。
- Java 状态字段继续使用现有枚举；模型 Key 不是业务状态，不使用状态魔法值。
- `PROCESS_START_USER` 用户 ID 在前端和 JSON 协议中保持字符串，后端只将其作为 Flowable 变量传递。
