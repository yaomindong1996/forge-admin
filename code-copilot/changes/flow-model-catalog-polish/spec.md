## 实现约束

- 列表继续展示真实模型、分类与状态字典。设计入口称“设计流程”，信息弹窗称“编辑信息”，实例入口称“运行记录”；面向用户统一称“发布”。
- 发布版本来自与当前部署/流程定义匹配的未删除版本快照。后端比较当前 BPMN 和表单快照，返回尚未发布/已同步/有未发布修改/发布信息待核对；不推算下一版本、不以更新时间或状态码推断草稿差异。
- 比较仅涵盖已版本化的 BPMN 与 formJson；不是审批语义级差异分析。历史快照/部署引用缺失或不匹配时保守返回待核对，不伪称从未发布。新增字典走下一 Flyway 迁移，不修改旧迁移。
- 不改变原发布、激活、挂起和审批运行规则；仅在已有发布动作上补充清晰入口与提示。已有运行实例不改变，真实发布仍由用户确认。
- 业务绑定新增有界批量只读查询（最多 100 个模型 Key），沿用 ai:businessFlow:config 权限及可信租户，SQL 在 Mapper XML；不逐模型请求、不放宽权限。兼容单模型接口和原表单引用上下文。
- 前端先拆分超长 useFlowModel.part1 的列表/排序/绑定领域，保持既有表单、设计器、测试发起能力；复用系统 Naive UI 和 DESIGN.md，不增加依赖。
- 搜索/筛选在左，新增和低频操作在右；排序时锁定查询和分页并明确当前页范围。卡片直显最多两项常用动作，真实版本与变化状态清楚，不增加装饰区块。
- 区分首次加载、刷新、无模型、无匹配、列表失败与绑定失败；失败不显示为“未绑定”。并发请求只允许最新结果落地，卸载后不写回，分页与查询上下文不串页。
