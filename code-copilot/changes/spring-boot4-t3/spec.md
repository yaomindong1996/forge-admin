# Spring Boot 4 T3：功能回归与剩余兼容性收敛

> status: local-validation-complete-awaiting-runtime-acceptance
> created: 2026-10-12
> complexity: 复杂

## 基线与授权

用户要求继续下阶段，保证升级后的功能回归正常。继续当前 `codex/spring-boot4-t0-compatibility`，
不改 main。复用 T2 的 665 项和独立 28 项证据，不覆盖历史记录，也不把历史通过算作本轮通过。
本轮是日常开发，revision 保持 1.2.0；保留已有 307 条工作区状态及无关修改。
不自动提交/push/发版/部署，不连接真实业务库、Redis 或付费模型。

## 本轮范围

1. 扩展生产 Java 回归，修复升级引起的 API/自动配置/序列化/测试 fixture 兼容问题；
   核对原有五项测试源码排除，能修的恢复编译和执行，不能删用例或放宽业务断言。
2. 修复 Agent SSE 旁路订阅的登录、权限与会话归属，多订阅/断连/终止隔离；
   初始流在读取历史和修改记录之前验证会话归属，阻止跨用户/跨租户使用同一 sessionId。
3. 补图像工具模型选择：只能使用服务端 Agent 配置（extraConfig 的 imageModelId），
   校验当前租户、启用、IMAGE 能力；不让模型参数指定任意供应商、API Key 或提升权限。
4. 工具注册桥核对依赖方向与现有身份链。普通 Agent 登录没有客户端委托，不伪造 MCP clientId。
   在用户确认前保持现有鉴权，先完成可安全实现的注册/能力声明和回归边界。
5. 复用真实采购 BPMN/H2，核对审批、驳回重提、会签、JSON 字段权限与租户隔离；
   PC/H5/Report 前端测试和构建做回归，不进行无关 UI 重构。
6. 按模块维护验证清单和真实未完成门禁，只有有证据的功能才标为通过。

## 扩展回归发现的兼容与既有缺陷

- 打印来源 DTO 新增的独立业务字段不能混入应用快照：只兼容 null，非空仍拒绝。
- 公式错误按已有公式 Spec 保持发布阻断，修复公共收集器误降为 WARN；不调整正常发布协议。
- PC 嵌套选择等待真实布局初始化；未选择/已删除节点的属性抽屉不读取 null。
- 幂等 Token 仅接受明确 UNUSED 状态，缺失/未知/已消费状态均拒绝。只收紧无效状态，
  不更改正常 Token 生命周期或赋权，不连接真实 Redis；并发原子消费仍列为独立真实环境门禁。
- 旧测试的源码形态断言跟随已存在的组件拆分/懒加载/权威 uiDocument 契约，保留真实行为断言，
  不为了绿灯恢复未在画布中的字段、错误配色或禁用组件操作。

上述权限/状态收敛上线前需要人工审查。用户本轮确认保持现有客户端鉴权，不增加 Agent 客户端委托。

本轮图像工具仅解决服务端模型绑定，不宣称既有图像服务的异步工作线程、URL 下载与真实存储已闭环。
普通 Agent 直接绑定 MCP 客户端的功能依用户决定不在本轮实现；现有 MCP 独立鉴权/委托保持不变。
存量多 part JS 仅修正初始化监听条件，不增长文件行数、不扩展巨型编排职责；SFC 981 行。

## 权限 / 配置审查边界

新增 SSE 权限复用现有 ai:engine:stream，不新增角色授权或菜单 SQL。
会话归属来自当前认证上下文和已存储 session，不信任请求里的用户/租户字段；只收紧越权。
图像模型配置是现有服务端 extraConfig 的可选扩展，不新增表结构；无配置明确错误，不能偷偷选择付费模型。
客户端委托配置/新增权限映射须用户选择后单独设计，不借“回归”自动赋予客户端权限。
真实业务状态变化、真实环境验收由用户执行，上线前需人工审查本轮权限收敛与配置兼容影响。

## 验证与非目标

先执行现有生产回归并记录失败，逐项修复，再跑扩展集与四服务打包。
测试只使用 Mock、loopback 或 H2；不读取真实 dev 数据源启动应用，不用 repair/关闭校验改旧迁移。
不会凭本地全量单元测试承诺所有真实业务都已验收；MySQL 存量升级、真实 Redis、供应商、
登录/业务 E2E、插件授权和部署仍要明确独立门禁。
