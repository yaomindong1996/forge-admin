## 本轮完成

- Agent 审计事件不再跨通用异步线程分散缓冲，按可信租户与框架 ID 有序批量 INSERT。
  结束/人工确认/loop finally 刷新余量并清理线程；断开 HTTP 不提前终止后台任务。
- 失去 lease 时只刷新此前已接受的审计，不发布旧全局 AGENT_END 或收口另一执行的消息。
  数据库审计失败不重放业务/模型，日志只保留安全类型与批次数。
- 历史工具缺少真实成功结果、结果非法或前一工具未结束时，不再标成功；
  已完成、拒绝和待确认记录保持原有语义。
- 旁路事件订阅在确认时结束本轮；恢复需重新订阅。
  慢连接缓冲溢出明确失败，新旧连接条件清理，多读者和用户/租户隔离保持。

## 范围收敛与已知边界

2026-10-12 用户明确：只保证现有功能升级兼容，不新增功能。
此前建议的 T7–T9 不再作为必做阶段；后续只做兼容审查/回归和有证据的最小修复。
下面的未实现增强是能力边界，不意味着要在这次 Boot 4 升级中继续开发，也不能据此改写为已支持。

- 审计批次是尽力保存；进程骤停时未提交部分与数据库失败部分无持久化重试保证。
- 旁路 SSE 仍是节点内通道、仍需粘性路由；没有跨节点事件总线或 Last-Event-ID 重放保证。
- 图像任务没有持久化崩溃恢复，旧 assistant 行清理和数据库写入 fencing 仍未实现；
  不自动重新调用付费模型，不把审计修复宣称为这些边界也已补齐。
- 真实 Redis/Lua/Cluster、MySQL/Flyway/Flowable、供应商/COS、PC/H5 业务 E2E 按用户要求未验证。
  MCP/受控能力仍保留既有客户端鉴权，不给普通 Agent 用户伪造委托。
- 版本仍是 1.2.0 日常开发基线；正式升级发版目标需单独确认。
  当前升级分支有未提交改动，main 未动，未提交/push/发布/部署。
