## 发现的问题

- `AgentEventPersistence.persist` 使用 `@Async` 与 `ThreadLocal` 缓冲，事件被调度到不同线程；
  不足 20 条的短对话没有可靠刷新入口，顺序、租户和结束/确认事件的落库都不能保证。
- 事件 ID 使用时间加随机数，未复用框架 ID 生成器；事件实体未显式捕获可信租户和时间。
- 会话工具调用缺少结果时，持久化器在下一工具开始时把旧工具标成成功，与 T5 客户端纠错不一致。
- 旁路 SSE 仅在 AGENT_END 关闭，人工确认使 loop 返回后仍保留订阅；缓冲溢出时忽略失败结果，
  会静默丢失事件或终态。

## 实现契约

1. 事件缓冲留在唯一 loop 执行线程，不再使用通用异步池。继续有界 20 条批次，
   使用 Mapper XML 一次 INSERT，按发布顺序生成 ID、显式捕获可信 tenantId 与 createTime。
   默认使用项目已有 IdentifierGenerator，不增加依赖或新 ID 算法。
2. AGENT_END、REQUIRE_USER_CONFIRM 刷新余量；loop 的 finally 无论正常、取消、异常、租约失效
   都刷新已接受事件并清理线程缓冲。旧节点失去租约仍只发直接流 ERROR，不发布旧全局终态。
   身份切换不得把未刷新记录写到另一租户；数据库失败记录安全类型/批次数，不输出事件正文，
   不自动重放工具或再次调用模型。本轮是尽力审计，不承诺跨系统 exactly-once 或进程崩溃零丢失。
3. 工具只有收到真实成功结果才成功；缺失/非法结果和缺失收尾保持错误，
   沿用现有 success/error/aborted/waiting_confirm 状态，不新增状态机或权限。
4. 旁路 SSE 在确认终态关闭本轮订阅，恢复需重新订阅；缓冲溢出明确失败并条件移除旧订阅，
   旧连接断开不能删除新订阅。同会话多读者及可信用户/租户隔离保持。
