# Forge 原生打印能力提案

> 变更名：`forge-native-print`
>
> 日期：2026-09-18
>
> 状态：`accepted — 2026-09-18 用户确认进入编码，按阶段 commit，不 push`
>
> 权威规格：[spec.md](spec.md)

## 1. 要解决的问题

让业务人员在现有应用工作台为表单配置打印模板，在业务列表、详情和流程审批详情中打印真实单据。模板设计、字段绑定、取数、权限、发布和流程记录使用 Forge 平台能力。

当前设计器的“打印表单/列表”仅打开设计预览并调用浏览器打印，尚无独立业务打印模板。现有业务字段目录、主子表详情、流程表单上下文、审批时间轴和应用发布版本可以作为基础。

## 2. 已确认的方向

- 自主实现打印设计器、模板协议、分页排版和浏览器打印链路。
- hiprint 作为功能研究参考；运行时不引入 `vue-plugin-hiprint`，不复制其 bundle 到本项目。
- 优先服务现有低代码与流程，做平台级能力。
- 按 SDD 顺序：提案 → 技术规划 → 任务拆解 → 范围审查 → 编码 → 增量验证 → Review。

## 3. 建议的首期范围

| 交付 | 可见结果 |
|---|---|
| 模板工作台 | 从应用/表单进入，创建、复制、编辑、预览、发布、停用模板 |
| 原生设计器 | 纸张、页边距、元素拖拽缩放、对齐、撤销重做、字段选择 |
| 打印元素 | 文本、图片、线框、二维码、条形码、明细表、审批记录表 |
| 分页 | A4/自定义纸张、文本增高、明细按行分页、重复表头、页眉页脚与页码 |
| 业务打印 | 已保存记录的主表、子表、关联名称、字典与金额格式化 |
| 流程打印 | 待办/已办/我发起入口，绑定明确流程实例，附意见与签名 |
| 发布与权限 | 不可变模板版本、应用发布引用、记录权限、节点字段权限、审计 |
| 输出 | 多页预览、浏览器打印；浏览器支持时由用户选择“另存为 PDF” |

首期流程打印使用当前授权可读数据，界面和纸面注明数据生成时间；不称为“审批时点原件”。

## 4. 后续阶段

- 审批时点业务快照、自动 PDF 归档、历史原样重打。
- 多记录批量打印、客户端静默打印和打印队列。
- 跨页合并单元格、复杂富文本合同、多栏流式排版。
- hiprint 模板导入适配、服务端无头浏览器输出、更多浏览器兼容。

## 5. 实施顺序

1. M1：协议、真实浏览器测量、分页与打印最小闭环。
2. M2：设计器、Pinia 状态、属性面板和模板往返保存。
3. M3：模板后端、版本、数据提供方协议和授权。
4. M4：低代码字段/主子表接入、工作台入口、应用发布与下载协议。
5. M5：流程上下文、审批记录/签名、打印入口与实例权限。
6. M6：回归、构建、权限验证、真实单据与打印机验收。

每个里程碑有可验收产物；M1 分页不可用时不继续堆设计器功能。

## 6. 审查要点

- 首期采用“当前数据打印”，归档与历史快照进入后续阶段。
- 首期动态表格按整行分页；单行超过整页可用高度时明确阻止输出并提示调整。
- 模板新增发布状态和权限资源；普通使用者与设计/发布人员权限分开，默认不批量放权。
- 真实数据库、Admin/Flow 服务及打印机联调由用户按现有偏好执行；自动验证使用合成数据。
- 目标已纠正为现有 forge-admin Git 仓库；在功能分支按阶段提交，不 push，不纳入其它改动。

审查状态见 [spec.md](spec.md) 第 11 节。技术规划、任务和验收分别见 [design.md](design.md)、[tasks.md](tasks.md)、[test-spec.md](test-spec.md)。
