# 条件分支公共审批节点合并

## 用户授权与边界

2026-10-20，用户要求把截图中两条条件分支末端重复的审批节点合成一个公共节点，并与本轮设计器 UI 调整一起交付。
本变更依赖 `flow-designer-soft-ui` 的当前 main 工作区实现，保留其中全部未提交修改及其他部署记录。
日常开发不升版，不提交/push、不部署，不修改已发布模型或正在运行的实例。

## 交互与语义

- 审批节点“更多”增加“合并审批节点”，局部使用 Naive Modal，选择要保留的目标节点，明确说明删除当前节点、保留目标 ID/名称/配置以及保存/发布生效边界。
- 不自动按审批人相同去重。只允许同一互斥条件网关的不同分支，普通单链末端、后继相同的审批节点手动合并。
- 审批配置必须一致，包括人员、候选组、表单、字段/子表权限、意见/签名、会签、提醒、审批要点和监听器。仅忽略画布内部 mergeNode 标记，未知配置同样参与比较。名称可不同，保留目标名称。
- 并行/包容、同一路径、前后串联、回流、普通节点分叉、跨网关、多个不同后继或条件出边不一致等情况拒绝合并，不能引入重复任务或绕过审批。
- 重定向当前节点原有入边到目标节点，保留边 ID、条件、默认分支与顺序；移除当前节点及重复出边，目标的完整配置不做并集或覆盖。
- 已经共享的目标节点可以继续接入其他互斥支路；同一个分支不能重复接入。
- 合并前不得丢弃未确认属性草稿；先提示确认/取消属性。应用时重新校验最新图，单次原子提交并产生一条可撤销历史。
- 新增跨面板操作状态使用按设计器 ownerId 隔离的 Pinia store；算法在纯函数中，编排壳不超过 1000 行。

## 风险与人工审查

**本操作会改变审批路由结构与节点 ID，属于流程状态/权限敏感设计变更。** UI 必须展示保留与删除对象及目标配置一致性，只有用户明确点击确认才修改草稿。
不自动发布、不改历史任务/实例。后续真实模型发布仍由用户人工检查办理人、字段权限和路径后执行。
外部业务可能按节点 ID 绑定规则或回调，确认框展示保留/删除 ID 并提示发布前核对；不能承诺仅因节点配置一致就自动迁移外部绑定。
本轮通过局部纯函数、真实组件浏览器与 XML 导入/导出测试验证，不启动真实 Admin/Flow 或连接数据库。

## 验收

1. 截图同构流程由两个审批节点变成一个，多条互斥入边与公共出边正确，画布只显示一个公共节点。
2. 新增操作可取消、可撤销/重做；readonly 不出现入口；选中/配置转到保留节点。
3. 人员相同但其他配置不同必须拒绝；不产生悬空边、自环或错误默认分支。互斥网关原有不同条件/默认分支边即使指向同一目标也分别保留，不新增普通节点重复出边。
4. 保存 XML 只有一个目标 userTask，条件及目标权限不变；重新导入后仍为共享节点，新增分支和删除网关不回归。
5. 原 404 项基线、增量测试、前端 ESLint/build、桌面和窄屏真实组件检查通过。
