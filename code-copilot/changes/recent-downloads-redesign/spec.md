# 最近下载轻面板改造

## 范围与基线

- 用户确认按已展示设计实现，直接在 `main` 开发；基线 `7329a52f7`。
- 复用 `GET /system/file/download-log/page`、现有下载工具与服务端下载审计，不新建下载业务表。
- 本轮为日常开发，不升发行版本、不部署、不执行数据库迁移；后续提交/推送以用户追加授权为准。
- 现有六个无关未提交文件保持原状。

## 交互与实现

1. 有侧栏时入口放入底部布局流，折叠/窄栏只显示图标；无侧栏时左下角提供紧凑入口。
2. 采用 Naive UI Popover/Button/Progress/Skeleton/Popconfirm，不遮罩、不切换业务页面。
3. 宽约 404px，按今天/更早分组，展示真实文件名称、来源字典、大小、时间和管理员可见的下载人。
4. 复用后端现有权限与租户范围，不由前端传 userId/tenantId 放宽访问。
5. 首次加载、刷新、分页、错误重试及空状态各自区分；并发查询合并，迟到响应不能跨账号/租户覆盖。
   以 20 条分页读取，面板最多展示最近 500 条；本地隐藏 ID 也按此上限保存，避免无界积累。
6. 系统文件下载接入实际接收事件；只有响应声明总字节数时展示百分比，否则只显示接收字节或准备中。
   不伪造后台生成任务、不重放导出写请求；无 fileId 的历史导出仅提示回来源页面重新导出。
7. 成功只表示交给浏览器保存，不宣称磁盘写入完成。失败重试复用 fileId 下载并处理 Promise 异常。
8. 清空只隐藏当前浏览器已加载的已结束记录，按账号/租户隔离保存记录 ID，不删后台审计或本地文件。
   进行中的任务保留；无效/不可用的浏览器存储不阻断下载。
9. 所有面板随账号、租户、会话或页面切换关闭；旧下载事件不携带 Token、签名地址或敏感失败正文。
10. 下载被 4xx 或 JSON 业务错误拒绝时不使用旧签名地址绕过；错误 JSON 不作为文件保存。

## 明确边界

- 不新增本地文件夹访问权限；浏览器无可确认的磁盘保存回执。
- 不改后端下载权限、审计接口和既有 SQL；不自动访问真实业务环境。
- 下载即时状态是技术传输态，不是新增业务枚举；来源继续使用既有 `sys_file_download_source` 字典。
- 历史记录只有成功审计，不将历史接口失败伪装成空记录或生成进度。
