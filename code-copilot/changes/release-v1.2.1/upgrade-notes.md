# V1.2.1 升级说明（发布准备）

整理日期：2026-10-17。目标发行版本 1.2.1，代码准备分支 main。
尚未创建 v1.2.1 标签、发布正式包或部署；不要把本文当作生产验收结果。

## 本次版本边界

发行源为根 `forge-server/pom.xml` 的 revision，Admin/H5/Report 私有包与独立依赖 BOM 同步为 1.2.1。
PC 入口为头像菜单/账户与工具 → 关于系统；H5 为我的 → 关于系统。
重建并更新对应服务/静态资源后才能看到新版本，修改源码不会改变正在运行的旧服务。

维护者指定使用 1.2.1，但这次包含 Spring Boot 4.1.1、Flowable 8.0.0、Spring AI 2.0.1 的底座升级。
这是指定的发行编号，不代表所有自定义扩展都满足补丁级兼容；按严格语义版本，应对不兼容契约另行评估主版本。

## 升级前

1. 确认源版本、实际数据库迁移历史、各服务与前端版本；备份业务库（包括 ACT_* / flw_* 引擎表）、
   配置、旧制品及所需文件。不要在升级时重跑全量初始化 SQL。
2. 在库副本验证 Flowable 8 的引擎结构与历史流程、变量、表单、回调、审批与撤回；
   Admin、App、Flow、Report 及自定义插件使用同一套目标底座依赖，避免新旧引擎/Starter 混跑。
3. 核对 Java、MySQL、Redis、模型供应商与存储的实际部署条件；当前工程 Java 源码目标仍为 17，
   不擅自抄用其它工程或其它机器的配置。
4. 自定义 Starter、Jackson 序列化、MCP transport 与模型适配器需要重新编译和回归；
   当前代码已做相应兼容迁移，但不意味着所有外部插件天然兼容。

由 Admin 的 Flyway 按实际 forge_schema_history 执行，Flowable 自身结构升级另按引擎方案演练。
本轮没有执行这些迁移。禁止修改已执行 SQL、关闭校验或 repair 掩盖差异；发现重复版本先确认落地历史。
纯净版 SQL 仅用于新建空库，不能导入已有业务库；不要把本次纯净版清理误用到生产表。

不清空共享 Redis。旧 Sa-Token 会话需验证过期/重新登录路径，升级窗口结束旧 Agent 待确认会话，
新旧节点不要混用旧确认快照恢复；必要时重新发起会话，不伪造或重放已执行工具。

## 扩展与运行边界

- 自定义 TokenService 必须适配现有新增原子生成/领取接口；旧或未知幂等 Token 需重新申请。
- Agent SSE 旁路仍为节点内通道，负载均衡需粘性路由；没有跨节点事件重放保证。
- 图像任务不提供进程崩溃后的持久化恢复，不自动重调付费模型；审计是尽力保存，不保证进程骤停零丢失。
- HTTP/图像下载继续走受控出站及大小/格式校验，模型/存储私有凭据不写入发版图片或社群稿。
- 下载历史来源由既有字典解释；无 fileId 的导出记录不重放导出写请求，需回原页面重新导出。
- 清空最近下载只隐藏当前浏览器已加载记录；租户/账号各自隔离，不删除审计或真实文件。

用户已追加授权提交/推送准备改动；后续正式交付仍需另行授权：
从同一干净提交重建制品 → 核对 build-info/version.json →
完成上述真实环境验收 → 创建不可变 v1.2.1 标签与发布包 → 按已授权环境部署。
任一步失败不得宣称已发布或生产升级成功。

## 升级后核对与回退

- 登录后查看 PC/H5 关于系统；分别核对当前后端发行版本、当前浏览器前端版本、提交及构建时间。
- 下载、导出、审批、待办/抄送计数、低代码设计/预览/发布、打印、模型调用及租户权限按实际业务回归。
- 只有静态资源更新时，可回退对应前端包；后端/数据库已迁移后不能假定旧 JAR 可直接回滚。
  回退需与备份数据库、Flowable 引擎版本、插件、会话及配置配套，并在副本上验证。
