# 插件中心（可视化管理）

状态：developing；P1/P2/P3.1 核心代码与本地验证完成；真实容器、部署验收及 P3.2/P3.3 待完成。
用户于 2026-10-07 确认按所提架构开始开发。

## 目标与交付阶段

在「平台管理」下建立独立插件中心，不占用应用总览、打印中心或业务菜单。
先交付当前服务的真实运行清单，再交付源码安装工作台和独立构建执行器。
承接 plugin-foundation 的注册表、FeatureGate、源码 CLI 与修复后的覆盖保护。

### P1 本轮：运行插件清单

- 内置业务插件 JAR 携带 `META-INF/forge-module.json`，仅此资源过滤 Maven 版本/模块坐标。
  不扫描源码目录，不将模块目录或配置文件存在误认为服务已部署。
- starter-plugin 的不可变运行目录合并内置声明和已有外部 PluginRegistry，重复 ID/坏声明启动失败。
- 清单按当前实例 classpath 展示；加载成功只代表描述/类路径装配，不代表健康检查通过。
  外部描述没有 server 的只能显示「仅元数据」，不能冒充后端已加载。
- API 提供核心版本、发行标识、分页/名称或 ID 查询、来源筛选、详情、声明功能及当前 Gate 结果。
  不读取许可证、凭据、源码路径、数据库连接或任意工作区文件。
- `GET /system/plugin/page` 和 `GET /system/plugin/{id}`；平台超级管理员限制与 RBAC 注解同时检查。
  权限变更范围仅新增最小用户类型为 0 的菜单/API/查看按钮，不授权普通角色。
- 前端 `/system/plugin`：紧凑筛选/表格、真正详情、刷新、错误重试、空状态、窄屏/明暗主题。
  来源、发行版、加载状态用系统字典；不加入无实现的安装/升级/卸载按钮。
- 本轮清单范围明确为**当前后端服务**。纯前端插件/current UI build manifest 在 P2 补齐，
  独立 Flow/Report 实例不会被当前 Admin 清单伪装成已加载。

### P2：安装工作台与部署差异

- 受控 ZIP 上传、元数据/兼容/哈希/路径/大小预检、变更及冲突预览、显式确认。
- 区分源码登记、当前 UI 构建清单、当前服务 Registry，展示版本/部署差异。
- 持久化审计任务及状态机；复用 CLI，不在生产 Web 进程执行上传代码或构建命令。

#### P2 本轮执行契约（2026-10-07）

- Web 预检不接受客户端目标目录/tenantId/命令。ZIP ≤8 MiB、单文件 ≤4 MiB、
  展开总量 ≤32 MiB、条目 ≤2000，仅 stored/deflate；拒绝链接、特殊文件、加密、ZIP64、
  路径穿越、大小写/NFC 冲突、本地头不一致/范围重叠/CRC 失败；只在有界内存解析。
- 复用 starter-plugin 的描述与版本校验；根描述必须与后端 runtime 描述完全一致。
  校验单模块 POM（禁 DTD/外部实体）、UI 组件存在、组件不重叠/无保留文件；
  拒绝本地配置、构建产物/隐藏仓库目录，避免上传密钥（仍不声称自动内容审计）。
- 包 SHA-256、当前核心版本/运行清单快照、预览、文件摘要存入任务；ZIP 私有 BLOB 不出普通 API，
  页面预览最多 200 项且明确截断。无文件下载/执行接口。任务记录默认逻辑删除且不提供删除动作。
- 状态机：待确认→待构建，或待确认/待构建→已取消；有已知冲突→预检阻断。
  确认需任务 revision+SHA-256，服务端重新验证包及当前核心/运行快照，CAS 防并发；
  同一上传 requestId 幂等，同 requestId 不同字节拒绝；重复确认不重复创建任务。
- 仅当前租户上下文的平台管理员：上传/确认/取消/任务查询新增独立 RBAC，不给普通角色授权。
  新权限属于用户已批准的插件管理范围，上线前人工审查迁移；不自动执行共享数据库变更。
- 检查已知 ID/模块/内置冲突及版本降级；源码目标路径、未提交定制、构建依赖和 UI/API/SQL
  实际影响仍标为待执行器预检，绝不把运行目录比较冒充完整源码差异。社区 Web 不受理 ee 包。
- UI manifest 由 Vite 构建时读取真实安装登记/组件所有权，不接受后端/上传包伪造 UI 已部署。
  显示 UI/后端构建声明对比；源码工作区未连接明确显示不可核验。
- 新 V1.0.211 建任务审计表/权限/字典；清理模板时清空任务包，不携带客户上传代码。
  生成工程沿用格式和 CLI；最终源码安装仍由 P3 通过现有 CLI 做完整宿主检查。
- 本轮不提供运行安装/卸载、自动部署、商业授权校验，也不调用 shell/Node 子进程或读取源码工作区。

### P3：独立构建执行器

- 独立低权限工作区/容器，固定命令、超时、有界日志、无生产 Secret/数据库/宿主 Docker socket。
- 状态为预检→待确认→安装→构建验证→待部署→部署→运行核验；失败可解释、恢复可审计。
- 升级/卸载保留恢复副本；卸载不删数据库，Flyway 失败不自动 repair，不宣称源码回滚能回滚数据库。
- 部署需后续单独确认目标环境及权限，不由本轮「开始开发」推定生产部署授权。

#### P3.1 本轮：离线执行器核心（2026-10-07）

- 交付 `forge:plugin-build check/run`；输入为运维本地配置、固定 Git commit、ZIP SHA-256，
  不接受 Web 命令或目标目录。先只读检查，run 必须显式 `--reviewed`；不连接任务 BLOB/API。
- 从干净 Git 工作区复制已提交普通文件，逐文件核对 Git blob，拒绝链接/子模块/本地配置、
  构建产物、开发接入。只在独占临时副本预检并调用原安装器，不改原源码或数据库。
  已安装源码摘要有客户定制（即使已提交）仍阻断；整包替换须显式 `--force`。
- 源快照最多 30000 文件、单文件 64 MiB、总量 512 MiB；包沿用 CLI ZIP 边界。
  Git 信息/配置不进入容器；受审查的公开 `.env`/环境模板可复制，本地覆盖和私钥拒绝。
  该规则不等于内容级 Secret 扫描，源码、ZIP、镜像仍必须人工审查。
- 仅专用非 root 用户的本地 rootless Docker daemon；预装镜像必须指定 sha256 digest、
  `--pull=never`、无网络、只读根、cap-drop/no-new-privileges、资源/时间限制。
  容器内 UID 0 仅映射专用非 root 宿主用户，挂载只读快照/包/工具及独占输出；
  不挂生产目录、数据库配置、宿主 socket 或 credentials，不以宿主构建作降级。
  socket 父目录须私有；要求 cgroup v2/systemd 及内存/交换/CPU quota/PID 控制可用，
  防止 rootless 环境静默忽略资源限制，未满足时直接阻断。
- 固定离线 Maven/pnpm/Vite 命令；镜像预备 Node20.19+/Java17/Maven/pnpm 与公开依赖缓存。
  不运行服务器、Flyway 或部署脚本。缓存缺失直接失败，不开放网络补依赖。
- 有界子进程输出与超时、只清理本次随机名称和标签匹配的容器；SIGINT/SIGTERM 转失败并清理。
  stdout 只输出结构化状态/错误码，不回传原始源码编译日志；结果 JSON 绑定包/源码/镜像摘要，
  核对真实产物路径、大小及 SHA-256。产物最多 4096 文件、单个 512 MiB、总量 1 GiB。
  构建通过不表示健康、授权或部署完成，不信任包提供的产物清单/回执。
- P3.2 再实现认证领取、租约/CAS、包下载及回写与工作台；P3.3 为人工确认的部署/健康核验。
  本轮无任务状态/权限/SQL 变更，P2 队列不会自动执行；Docker 缺失时明确未验收真实容器。
- 生成后的工具在改名后原样复制；修正把管理端 build 源码插件目录当产物忽略的旧规则，
  防止新 Git 工程的受审查快照漏掉 Vite helper，保留真正的 dist/target 忽略规则。
- full 实测发现独立 Report UI 字体库约509 MiB，完整导入超过512 MiB快照上限。
  不增加限额：源码固定视图收敛为后端根目录、Admin UI、根包管理配置及原模块 catalog；
  排除独立前端/部署/文档与历史 `<Admin UI>/dist.zip`，结果声明 admin-build 范围及排除数量。
  仍校验全仓 Git 干净状态、路径/链接/本地配置；不支持构建依赖宿主范围外的自定义工作区。

## 安全与兼容

社区只交付通用扩展点、管理界面及源码工作流，收费源码/License 在以后独立 Pro 工程。
不创建未确认的 Pro 名称/groupId/包名，不实现动态 JAR 热安装，不推送、不合并 main。
V1.0.210/211 为幂等菜单/字典及任务迁移，tenant_id=1；回滚只隐藏新增入口，不删除审计或用户数据。
用户已批准本阶段平台管理员权限架构；迁移上线前仍需人工审查。无新增运行时第三方依赖；
P2 使用已有 BOM 管理的 H2 测试依赖验证真实 Mapper，不用于生产数据库。

## 验收

1. 内置/外部真实合并，重复/损坏/超限声明拒绝、顺序稳定、结果不可变。
2. 无插件/未知 ID/越界分页/超大页/非法筛选可解释；Gate 切换只影响功能展示。
3. 非平台管理员即便有插件权限也拒绝，未登录不能访问；不泄露内部文件路径。
4. 页面可查询/翻页/刷新/详情/重试，竞态不覆盖新结果；构建、单测、视觉验证。
5. 聚合编译、生成 full 工程与 DB 桩、edition 门禁；未实跑真库须明确记录。
