# 插件中心

平台超级管理员从「平台管理 → 插件中心」查看**当前后端服务实例**包含的插件。
首次升级需要部署本轮后端/前端，主 Flyway 按序执行 `V1.0.210__add_plugin_center.sql`
及 `V1.0.211__add_plugin_install_workbench.sql`、`V1.0.212__add_plugin_build_leases.sql`、
`V1.0.213__add_plugin_task_review.sql`。
权限资源及机器入口上线前需人工审查。
菜单不会覆盖应用总览、打印中心或客户已有同路径菜单；同路径冲突需管理员人工核对。
既有同权限编码或 API 路径也不覆盖；若被客户资源占用，需人工核对权限与路由绑定后再启用。
租户管理员和普通用户即便被授予插件编码也不能读取这个全实例目录。

## 可以查看什么

- 内置业务模块：由实际 JAR 的 `META-INF/forge-module.json` 登记，不是源码模块目录清单。
- 外部插件：来自已校验的 `META-INF/forge-plugin.json` 和 `PluginRegistry`。
- 插件独立版本、当前核心版本、来源、发行版、核心兼容范围、后端 Maven 模块。
- 外部插件声明的功能编码及当前 `FeatureGate` 使用权结果。

「后端已加载」只表示当前服务带有后端模块声明，**不是健康检查通过**。
没有 server 的描述只能显示「仅元数据」。前端声明也不代表 UI 已构建部署。
纯前端插件通过「构建对比」核验；尚未部署的源码、独立 Flow/Report 服务不在当前后端清单范围。
刷新只重新查询目录和功能授权，不会重新加载 Java 代码或清除权限缓存。

## 安装与部署的边界

「安装工作台」已支持 ZIP 上传预检、人工确认和任务审计，但**确认仅进入待构建，不会安装**。
已有[独立离线执行器](./plugin-builder.md)与[机器认证桥接](./plugin-worker.md)，可处理已审查的选定任务；
已支持部署前人工审查与失联关闭，以及独立[本地候选制品封存](./plugin-release.md)。
P3.3b2a已支持原构建机器对候选制品与当前审批做只读认证核验；
通过只代表查询时点元数据一致，不是部署许可。制品登记、远程发布、部署及运行核验尚未接入。
机器入口默认禁用，须运维配置和真实环境验收。
已有 `scripts/forge-plugin/index.mjs` 源码 CLI 仍可使用，
操作前阅读工程内 `.agents/skills/forge-project-init/references/plugins.md` 的安装维护参考。
源码安装成功后要重新构建、部署，再来插件中心核验实际插件版本。
源码配置文件里的登记不等于运行成功，卸载源码也不删除数据库或迁移历史。

离线执行器对受审查源码副本做真实冲突检查/构建；认证桥接仍需人工审查，不自动执行全部队列。
生产 Web 服务始终不执行外部命令。
商业许可证、维保权益和 Pro 工程另行建设，
当前功能结果不能被当作商业许可证有效性证明。

## 上传与任务

- 平台超级管理员需要对应上传、任务查询、确认和取消权限；租户管理员不能使用。
- 接受 `.zip`：包 ≤8 MiB、单文件 ≤4 MiB、展开总量 ≤32 MiB、条目 ≤2000。
  拒绝不安全路径、符号链接/特殊文件、加密/ZIP64、不一致的 ZIP 头/CRC、本地配置及构建产物。
- 根 `forge-plugin.json` 与后端 runtime 描述须一致；严格验证版本兼容、单模块 POM 和 UI 存在。
  包必须来自可信交付方；格式预检不能证明源码安全，POM/SQL/权限仍需审查。
- 预览展示版本、包 SHA-256、已知运行目录冲突、风险及前 200 个文件摘要。
  源码工作区尚未连接，客户定制、未提交文件、目标路径冲突和迁移影响仍待执行器核验。
- 状态为「待确认 → 待构建 → 构建中 → 构建通过（待部署）/构建失败」；已知冲突阻断确认。
  仅待确认/待构建可取消；构建中/失联及完成后保留占用，须按下节人工核查后处置。
  同一上传请求 ID 幂等，确认/取消校验摘要及 revision；运行目录变化需重新上传预检。
- ZIP 存储为当前租户上下文的私有审计数据，无普通下载接口。取消不删除审计记录/包。
  同租户同插件只允许一项占用任务，失联不自动重试或释放占用。机器下载另有认证及有效租约保护。
- 上传使用 multipart，不走 JSON 请求体加密；部署必须启用 HTTPS、合理的代理上传限额。
  存储容量与包保留周期需运维规划，本阶段不自动清除审计数据。

## 构建验收与人工关闭

平台超级管理员还需独立 `system:plugin:review` 权限。该权限不会自动授予普通角色。
工作台的任务详情提供两条路径，不是部署按钮：

- **审查构建**：仅构建通过且已有一致的结果报告可以使用。独立核对私有工作区内的实际产物、
  摘要、迁移/权限影响与数据库恢复方案，并确认执行器及对应容器已停止、本次产物尚未部署。
  填写核查说明后标记为「已审查（待部署）」，仍保留插件占用。
- **核查并关闭任务**：适用于构建通过、构建失败、已审查任务，或租约/硬期限到期的失联构建。
  必须先停止对应执行器及容器，确认尚未部署；活跃构建不能关闭。
  关闭后释放插件占用，可重新上传新任务，不自动重新构建、不删除包、产物或审计。

这些勾选是管理员的声明，不是平台远程验证。已经部署的产物不应使用“尚未部署”声明来关闭；
请保留任务并走目标环境的部署、回退和核验流程。
失联任务关闭时封存原构建记录，拒绝旧租约的续期与结果写入。
该结束时间是管理员关闭时间；如果没有执行器报告，系统不会伪造成功/失败结果。

核查校验任务 revision、包 SHA-256 和报告 SHA-256；过时页面须先刷新。
结果不确定时保留同一冻结请求重试，不能修改说明后沿用原请求 ID。
关闭详情或刷新页面不会把核查请求写入本地存储；重新操作前先刷新核对任务状态及历史。
审查状态、占用释放、封存和审计在同一事务中完成；详情显示最近20条纯文本核查记录。
说明不要填写凭证、个人敏感数据、私有路径或原始日志。

## UI 构建对比

Vite 构建时核验 `forge.config.json`、实际 UI 组件所有权/开发链接后生成清单，
只输出插件标识、版本、名称和发行标识，不泄露源码路径或客户配置。
页面与当前后端完整快照比较，版本不同会提示；后端无声明也可能是纯 UI 插件。
此清单不是页面健康检查，也不能代表源码登记或其它独立服务已经部署。
复制模式保留客户改动，不把文件摘要差异误报为组件不存在；源码定制保护由 CLI/执行器负责。

## 内置声明的维护

仅真实业务插件 JAR 携带 `META-INF/forge-module.json`；聚合父 POM 和技术 starter 不登记。
稳定 ID 使用模块目录清单的逻辑 ID，例如 `plugin-system`，不能随宿主品牌/坐标改名。
声明里的 `version` 和 `module` 分别用 Maven 构建版本、artifactId 占位符，由插件父 POM
仅过滤此文件；业务 JSON/SQL 保持不过滤。声明重复、损坏或尚未过滤会在启动期报错。

API：`GET /system/plugin/page` 使用 `pageNum` / `pageSize` / `keyword` / `origin`，
`GET /system/plugin/{id}` 查询详情。清单是当前服务不可变 classpath 快照，功能结果每次查询计算。
`GET /system/plugin/snapshot` 提供完整后端构建快照；任务接口为 `/system/plugin-task` 下
`POST /upload`（file、requestId）、`GET /page`、`GET /{id}`、`POST /{id}/confirm`、
`POST /{id}/cancel`（revision、sha256）、`POST /{id}/review`。
核查接口沿用正常 JSON 加密链路，使用明确的 DTO：requestId、revision、sha256、resultSha256、
decision、executorStopped、notDeployed、artifactsReviewed、migrationsReviewed、note。
请求不接受租户 ID、源码目录、部署地址或执行命令。
