脚本按职责分为三类：
- 初始化类：`init-db.sh` 通过 `mysql` CLI 创建 `forge_admin` 库（强制 `utf8mb4_0900_ai_ci`），并按顺序执行全量初始化 SQL、`db/seed/required`、可选的 `db/module`、`db/seed/demo`、`db/seed/optional`，支持 `--with-demo/--with-optional/--with-module/--skip-admin-init` 等开关。
- 导出类：`dump-safe-full.sh` 基于 `mysqldump` + `mysql` 生成 DDL+INSERT 的安全备份，默认跳过 Flowable (`act_*`)、版本表 (`*_version`)、日志/运行时表及敏感配置表，并通过 `information_schema` 递归推导外键依赖子表一并排除；支持 `--include-log-data/--include-sensitive-data/--ignore-data-table/--ignore-data-regex/--dry-run/--gzip` 等参数，输出到 `db/backup`。
- 社区版发布类：`export-community-db.sh` 编排 `export-community-schema.js`（复制 `../../db/migration` 下符合 `Vx.y.z__xxx.sql` 命名规范的迁移文件）和 `export-community-seed.js`（仅允许 `R__/D__/O__` 前缀的 seed 文件），再由 `check-sensitive-data.js` 依据 `community-db.config.json` 中的 `sensitiveColumns`/`sensitivePatterns` 扫描导出产物并输出 JSON 报告；所有 Node 脚本共享同一份 `community-db.config.json` 配置路径。
- 一致性检查：`check-collation-consistency.sh` 使用 `rg` 在 init 脚本、docker-compose、SQL 及文档中强制校验统一使用 `utf8mb4_0900_ai_ci`，禁止遗留 `unicode_ci/general_ci`。
依赖方向单向向外：脚本仅依赖外部工具 `mysql`/`mysqldump`/`node`/`rg`/`gzip`，不引入项目内 Java 代码。
