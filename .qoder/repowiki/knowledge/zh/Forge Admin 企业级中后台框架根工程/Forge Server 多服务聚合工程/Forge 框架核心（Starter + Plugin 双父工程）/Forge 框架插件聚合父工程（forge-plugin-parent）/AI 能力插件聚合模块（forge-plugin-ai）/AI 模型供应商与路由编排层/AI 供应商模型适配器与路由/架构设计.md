模块以 `AiProviderAdapter` 接口为核心契约，定义 `adapterCode()`、`validate()`、`createChatModel()`、`createEmbeddingModel()` 四个方法，屏蔽各厂商 SDK 差异；具体实现包括 `OpenAiCompatibleProviderAdapter`（基于 Spring AI 的 OpenAI SDK）和 `DashScopeNativeProviderAdapter`（基于阿里云 DashScope SDK），均标注 `@Component` 由 Spring 自动发现。

- 注册与路由：`AiProviderAdapterRegistry` 在构造时注入所有 `AiProviderAdapter` 实现，按 `AiProviderAdapterCode` 枚举值建立不可变映射，提供 `getRequired()` 及 `createChatModel/createEmbeddingModel` 统一入口，并在调用前通过 `AiSecretCrypto` 解密存储的 apiKey，再按“选择→校验→创建”固定顺序委派给具体适配器。
- 协议约束：`AiProviderAdapterCode` 枚举集中管理适配器代码（`openai_compatible`、`dashscope_native`），`require()` 对未知或空值直接抛出 `BusinessException`；`AiProviderBaseUrlPolicy` 负责 Base URL 归一化、协议白名单校验（仅 http/https）、DashScope 官方路径强制匹配（原生必须根地址、OpenAI Compatible 必须 `/compatible-mode`），并为常见 providerType 提供默认端点映射。
- 运行参数：`AiModelRuntimeOptions` 作为无凭据的运行时配置记录，供各适配器共享 temperature/maxTokens/model 等通用参数。
- 数据层：`domain/AiProvider` 是 MyBatis-Plus 实体（`TenantEntity` 扩展多租户），配合 `mapper`、`service`、`dto`、`vo`、`controller` 完成供应商配置的 CRUD、测试与缓存淘汰（`support` 包中的 `AiProviderCacheEvictionScheduler`、`AiProviderFailureDiagnostics`、`AiProviderSecretMasker`、`AiSecretCrypto`、`ProviderModelFetcher`）。依赖方向单向：controller → service → adapter registry → 具体 adapter → 厂商 SDK。
