模块按职责划分为三个子包：
- `invocation`：以 `AiInvocationObservation` 记录对象为核心，由 `AiModelInvocationRecorder` 将观察数据持久化为 `AiModelInvocationLog`（MyBatis Plus Mapper），并通过 `AiModelInvocationController` 暴露分页/汇总查询接口；`AiInvocationLogRetentionJob` 使用 `@ScheduledJob` 定时清理超期日志。
- `health`：定义健康状态机（`AiModelHealthStatus`、`AiModelHealthKey`、`AiModelHealthSnapshot`、`AiModelFailureCategory`）及 `AiModelHealthRegistry` 接口，`InMemoryAiModelHealthRegistry` 用 `ConcurrentHashMap` + `synchronized` 实现 OPEN/DEGRADED/HALF_OPEN/HEALTHY/UNKNOWN 五态流转，通过 `AiModelHealthLease` 租约封装成功/失败/取消/中止的原子收尾逻辑，并提供手动探针能力。
- `coordination`：`AiModelProviderManager` 作为事务性编排层，在增删改模型/供应商时先通过 `providerService.lockForModelSummary` 加锁、再校验快照一致性，最后同步供应商模型摘要，保证并发安全。
依赖方向：`invocation` 依赖 `health`（错误分类），`coordination` 独立协调 model/provider 服务，三者均不互相耦合。
