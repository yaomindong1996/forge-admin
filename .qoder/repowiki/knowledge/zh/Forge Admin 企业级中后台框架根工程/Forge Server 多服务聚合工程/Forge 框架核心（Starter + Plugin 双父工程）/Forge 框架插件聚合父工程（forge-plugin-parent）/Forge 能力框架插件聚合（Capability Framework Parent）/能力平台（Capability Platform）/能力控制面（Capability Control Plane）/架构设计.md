模块以 Spring Boot 自动装配为入口：`CapabilityControlPlaneAutoConfiguration` 通过 `@EnableConfigurationProperties` 加载 `CapabilityControlPlaneProperties`，并以 `@ConditionalOnMissingBean` 暴露 `CapabilityClientSecretCodec` 与 `CapabilityGrantPolicy` 两个可替换的安全组件。

分层结构清晰：
- `controller/` 暴露 `/ai/capability/*` 下的 REST 端点（`CapabilityCatalogController`、`CapabilityClientController`、`CapabilityGrantController`、`CapabilityInvocationController`），仅做参数校验、权限注解与日志记录，业务委托给 service。
- `service/` 是核心编排层，`CapabilityCatalogService` 负责能力元数据与版本发布（含 schema 校验、指纹计算、checksum），`CapabilityClientService` 管理客户端与密钥轮换，`CapabilityGrantService` 处理授权生命周期与字段/操作白名单策略校验，`CapabilityInvocationAuditService` 记录调用审计，其余服务（`CallGuideService`、`OpenApiDocumentService`、`SchemaFieldService`、`CapabilitySchemaChecksum`、`CapabilityVersionFingerprint`）提供辅助能力。
- `security/` 定义访问决策模型：`CapabilityGrantPolicy` 集中执行租户/组织/客户端状态/版本策略（PINNED/FOLLOW_MAJOR）判定并返回 `CapabilityGrantDecision`；`CapabilityClientActorMode`、`CapabilityClientPrincipal`、`IssuedClientSecret`、`CapabilityClientSecretCodec` 构成客户端身份与密钥编解码。
- `domain/` 对应 MyBatis-Plus 实体（`AiCapability`、`AiCapabilityVersion`、`AiCapabilityClient`、`AiCapabilityGrant`、`AiCapabilityInvocationLog`），`mapper/` 下各 Mapper 直接映射到数据库表，`mapper/model/CapabilityGrantOptionRow` 用于复杂查询 DTO。
- `dto/`、`vo/`、`enums/`、`audit/` 分别承载入参、出参与枚举常量，`audit/CapabilityActorType` 与 `CapabilityInvocationAuditEvent` 描述审计事件模型。

依赖方向单向：controller → service → mapper/domain，security 组件被 service 注入并可被外部覆盖，测试位于 `src/test/java` 中按 controller/service/security 子包镜像组织。
