模块划分为两个并列的子包：`parser` 负责把原始输入流解析为 `ParsedDocument`（标题、全文、段落片段、元数据），`chunker` 负责把全文切分为 `ChunkResult` 列表。
- 解析层：`DocumentParser` 接口定义 `getSupportedType()` + `parse(InputStream, fileName)`；各格式实现位于 `impl/`（Excel/Markdown/Pdf/PlainText/Tika/Word），由 Spring 自动装配进 `DocumentParserRegistry`，后者维护 `Map<String, DocumentParser>` 并在 `resolveParser` 中按 docType 精确匹配 → html/manual/url 回退到 txt → 再回退到 Tika，未命中抛 `BusinessException`；`inferDocType` 根据文件后缀推断类型。
- 分块层：`DocumentChunker` 接口定义 `getStrategy()` + `chunk(content, configJson)`；各策略实现位于 `impl/`（Delimiter/Length/Qa/Regex/Smart），由 `ChunkerRegistry` 以相同懒加载 Map 方式注册并路由，默认策略为 `length`。
- DTO 层：`dto/ParsedDocument` 与 `dto/ChunkResult` 作为两阶段的中间数据结构，分别承载解析结果与分块结果。
- 依赖方向：上层仅依赖接口与 Registry，新增解析器/分块器只需实现接口并加 `@Component`，无需修改调用方。
