模块以 `spi` 包定义扩展点：`CapabilitySource` 负责加载 `CapabilityDefinition`，`CapabilityExecutor` 负责按 `supports` 匹配并执行调用，`CapabilityAuthorizationPolicy` 和 `CapabilityInvocationObserver` 分别承担授权与观测扩展；`model` 包集中声明不可变数据契约（record 形式的 `CapabilityDefinition`、`CapabilityInvocation`、`CapabilityResult`、`CapabilityPage`、`CapabilityQuery`、`CapabilityCursor` 等），并通过构造函数与 getter 的 deepCopy 保证 JSON Schema 不被外部篡改。

`registry` 包中的 `InMemoryCapabilityRegistry` 是核心编排器：启动时聚合所有 `CapabilitySource` 产出、通过 `CapabilityToolNameMapper` 校验 `protocolToolName`、用 `CapabilitySchemaValidator` 校验输入/输出 Schema，并为每个定义精确匹配唯一 `CapabilityExecutor`，构建按排序键索引的只读映射；`list` 方法基于带 HMAC-SHA256 签名且绑定快照版本的 `CapabilityCursor` 实现分页游标，`invoke` 方法依次执行授权策略、输入 Schema 校验、委派 executor、输出 Schema 校验并以统一 `audit` 流程记录日志并触发 `CapabilityInvocationObserver`。

`schema` 包自实现轻量 JSON Schema Draft 2020-12 子集校验器，仅支持 `object/array/string/integer/number/boolean/null` 及有限关键字集合，避免引入第三方 JSON Schema 依赖。

`execution` 包提供面向受控调用的适配器 SPI（`GovernedCapabilityExecutionAdapter`、`SecureActionDescriptor`、`GovernedOpenGatewayAdapter`），用于在可信身份与实时授权之后对副作用操作做二次校验。

`config/CapabilityAutoConfiguration` 通过 Spring Boot `@AutoConfiguration` 装配默认 Bean（`Clock`、`CapabilityToolNameMapper`、`CapabilitySchemaValidator`、`ScopeBasedCapabilityAuthorizationPolicy`、内置 `PingCapabilitySource`/`PingCapabilityExecutor` 以及 `InMemoryCapabilityRegistry`），并通过 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` 暴露自动装配入口。

依赖方向单向向外：`registry` → `spi` + `model` + `schema` + `naming`；`config` 依赖所有子包；`builtin` 仅为测试/演示用途的实现，不反向依赖上层。
