本模块以 `coordination/AiModelProviderManager` 作为跨子模块的编排入口，统一协调 `model`（模型元数据）、`provider`（供应商适配器注册表）、`routing`（策略路由器）、`health`（熔断与健康状态机）四个底层能力：所有对模型/供应商的增删改都在事务内加锁并触发 `syncProvider` 刷新缓存摘要，保证路由与健康检查使用一致视图。
- 调用链路自上而下：`client`（AiClientImpl + ContextInjector）→ `routing`（PolicyBasedAiModelRouter）→ `provider`（AiProviderAdapterRegistry + OpenAiCompatible/DashScopeNative 适配器）→ `invocation`（记录日志）+ `health`（健康探测/租约），被 `chat`、`agent`、`multimodal`、`knowledge`、`prompt` 等上层业务共同复用。
- 事件与流式输出通过 `agent/engine/event` 中的 AgentEventPublisher/Listener + SSE 通道向外部推送；RAG 由 `knowledge` 提供文档解析/分块/向量存储，`rag/search` 以 Pipeline + Handler 模式组合 BM25/向量/Rerank/Fusion。
- 所有持久化统一走 MyBatis Mapper XML（`resources/mapper/*.xml`）与 SQL 脚本（`resources/sql/*.sql`），各子模块仅负责领域对象与 Service，不直接写 SQL。
- 扩展点采用“接口 + Registry”模式：工具（`agent/tool`）、文档解析器（`knowledge/parser`）、分块器（`knowledge/chunker`）、向量存储（`knowledge/vectorstore`）、模型适配器（`provider/adapter`、`model/adapter`、`multimodal/*/adapter`）均通过对应 Registry 动态发现与装配。
