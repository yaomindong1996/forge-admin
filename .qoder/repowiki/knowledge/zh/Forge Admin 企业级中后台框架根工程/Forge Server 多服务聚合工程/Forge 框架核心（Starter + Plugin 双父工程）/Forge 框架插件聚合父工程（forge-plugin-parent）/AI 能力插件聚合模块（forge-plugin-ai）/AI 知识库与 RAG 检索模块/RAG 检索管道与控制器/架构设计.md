模块以 `RagSearchPipeline` 为编排入口，通过构造时注入的多个 `RagSearchHandler` 实现责任链式执行：先根据 `KnowledgeSearchRequest.searchType`（vector/bm25/hybrid/null）选择单路或默认双路检索，再统一进入 `RerankHandler` 与 `FinalizeHandler`；中间状态集中在不可变共享的 `RagSearchContext` 中传递（vectorResults/bm25Results/hybridResults/fusedResults/finalResults/expandedQuery）。`handler/` 子包内每个 Handler 对应一个检索步骤，依赖 `VectorStoreFactory`、`AiModelAdapterRegistry`、`AiProviderService` 等外部能力；`fusion/` 子包提供纯算法类 `RrfFusion` 与 `WeightedSumFusion`，被 `HybridFusionHandler` 调用。`QueryCompleter` 在管道首步可选地通过 Spring AI ChatModel 扩展查询文本，且仅作用于请求副本，不污染入参。`controller/RagSearchController` 暴露 `/ai/rag/search` 两个 POST 端点（search 与 debug），使用 Sa-Token 权限注解 `@SaCheckPermission("ai:knowledge:search")` 保护，并统一包装为 `RespInfo` 返回。
