- 每个业务领域采用 controller/domain/mapper/dto/vo/enums/service(含 impl)/support/provider 的标准分层目录结构。
- 流程相关常量（modelKey、businessType、节点键、变量名、字段名、状态码、表单 key 等）集中定义在 `*FlowDefinition` 静态工具类中，服务与 Provider 仅引用该常量而不硬编码字符串。
- Service 实现继承 MP 的 `ServiceImpl<M, T>`，CRUD 操作通过 `getBaseMapper()` 调用自定义 XML 方法，并在需要时结合 `resolveTenantId()` 注入租户上下文。
- 流程交互通过 `@FlowBind` 声明绑定、`@FlowCallback` 声明回调，且流程启动调用放在事务外执行，状态更新单独提交以避免长事务。
- 业务校验失败统一抛出 `BusinessException`，并在 DTO 入参处集中做非空/范围校验（如金额大于0、会签至少2人）。
- 状态变更通过私有标记方法（`markInProcess/markNeedModify/markApproved/markRejected/markCanceled`）集中设置，配合枚举 `SamplePurchaseOrderStatus.matches/deletableCodes` 进行状态机约束。
