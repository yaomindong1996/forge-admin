- 组件能力以 spec 数组形式集中声明（field/layout/business 等分类文件），再由 `designer-core/index.js` 统一 `registerComponents` 注册到全局注册表，新增组件只需追加 spec 即可被各设计器消费。
- 页面 schema 通过 `zones`（search/table/edit/detail）+ `listGridLayout` 双结构描述，所有变更经由 `page-schema.js` 中的 `sync*` / `apply*` 函数做双向同步，避免直接修改 props。
- 扩展脚本必须通过 `ExtensionSandboxHost.execute` 调用，Worker 内部仅暴露 readField/setField/showMessage/triggerAction 四个白名单方法，字段名/动作编码均经 allowlist 校验后才可访问。
- 测试用例与源码同目录放置（`__tests__/`），并按被测模块命名（如 `bridge.test.js`、`page-schema.spec.js`、`scoped-css.spec.js`）。
- 错误消息在跨进程边界统一脱敏，Worker 与 Host 侧均对 token/secret/password/cookie/authorization 等敏感片段进行 `[REDACTED]` 替换后再上报。
- 模板化页面通过 `page-templates/*.vue` 导出默认 schema，由 `LowcodePageBuilder` 根据 modelSchema 的 appType（TREE/MASTER_DETAIL/其他）自动选择布局类型。
