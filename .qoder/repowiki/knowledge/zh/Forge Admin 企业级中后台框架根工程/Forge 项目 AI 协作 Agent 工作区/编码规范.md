- 每个功能变更以 `changes/<变更名>/` 为单位组织，至少包含 spec.md、tasks.md、execution-log.md，涉及测试时补充 test-spec.md。
- Spec 驱动开发：没有 spec 不写代码，spec 与实际不符时先修正 spec 再修正代码（Reverse Sync）。
- Agent 通过命令协议交互（/propose、/apply、/fix、/review、/test、/archive），自然语言指令需映射到对应命令后再执行。
- 长期记忆按类型写入 memory/decisions.md、memory/pitfalls/<主题>.md、memory/preferences.md，不在 .opencode/memory 维护副本。
- 踩坑记录采用统一格式：问题标题 + 发现日期 + 问题描述 + 解决方案，并在 pitfalls.md 索引中登记条目。
- Git 提交遵循一个 task 一个 commit、禁止 master 分支变更、消息格式 `[<变更名>] <中文简述>`。
