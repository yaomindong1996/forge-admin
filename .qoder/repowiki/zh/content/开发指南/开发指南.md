## 简介
本指南面向 Forge Admin 的开发者与协作者，覆盖编码规范、提交规范、测试规范、文档规范；深入说明插件开发流程、组件开发模式、API 设计原则与代码审查标准；并提供开发环境搭建、IDE 配置、调试技巧、性能分析与质量保证措施，以及团队协作最佳实践。目标是让新成员快速上手、老成员高效协作，确保代码质量与交付稳定性。

## 项目结构
Forge Admin 采用“微内核 + 插件化”的后端架构与“Vue3 + Naive UI + UnoCSS”的前端工程组织：
- 后端分层：starter（技术能力）、plugin（业务能力）、应用服务聚合插件对外提供接口。
- 前端分层：views/components/composables/api/utils/stores 等职责清晰，统一通过请求工具与字典能力。

## 详细组件分析

### 插件开发流程
- 新增插件应遵循“仅依赖 Starter，不反向依赖其他 Plugin”的原则，通过 SPI/Provider 注册扩展点。
- 在插件父 POM 中声明模块，并在主应用引入该插件。
- 插件内按 Controller/Service/Manager/Mapper 分层，DTO/VO 明确类型，避免 Map 接收请求体。

```mermaid
flowchart TD
Start(["新建插件"]) --> DefinePOM["定义插件POM<br/>声明依赖Starter"]
DefinePOM --> RegisterBean["注册配置类/扫描Mapper/Provider"]
RegisterBean --> ExposeAPI["暴露Controller接口"]
ExposeAPI --> TestVerify["编译+单测+集成验证"]
TestVerify --> MergePR["提交PR并评审"]
```

### 组件开发模式（前端）
- 页面使用 AiCrudPage/AiForm/AiTable 进行配置化开发，减少样板代码。
- 字典通过 useDict 获取，Schema 用 computed 派生，保证异步回显。
- 图片/文件字段使用 AuthImage 与 getFileUrl，避免 token 缺失导致下载失败。
- 样式优先 UnoCSS，复杂样式使用 scoped SCSS，主题变量驱动亮暗主题。

### API 设计原则
- RESTful 风格：GET /page、GET /{id}、POST /、PUT /、DELETE /{id}。
- 统一响应体 RespInfo.success/error。
- 敏感接口使用注解加解密；Controller 必须使用 DTO/VO，禁止 Map 接收请求体。
- 枚举替代魔法值，前端展示走字典，前后端状态码一致。

```mermaid
flowchart TD

Validate --> |通过| Service["Service编排/事务"]
Validate --> |失败| Err["返回错误响应"]
Service --> ORM["MyBatis-Plus 访问"]
ORM --> Cache["Redis 缓存/锁"]
Service --> Resp["RespInfo 统一响应"]
Resp --> Client["客户端处理"]
```

### 代码审查标准
- 是否复用现有组件/Composable/API，避免重复实现。
- 是否正确处理 loading、空态、错误、重复点击与组件卸载。
- 是否遵守字典、租户、权限、文件与加密约定。
- 是否避免硬编码颜色、枚举、接口地址、密钥与用户敏感信息。
- 是否在亮暗主题与窄屏下保持可读、可滚动、可点击。
- 是否只修改任务相关文件，保留用户工作区改动。

## 性能考虑
- 后端
  - 外部调用设置超时与降级；并发场景明确同步策略。
  - 高频查询建索引，避免全表扫描；SQL 幂等或防重。
  - 合理使用缓存与分布式锁，避免热点竞争。
- 前端
  - 列表分页、懒加载与虚拟滚动；大组件按需动态导入。
  - 计算属性与受控状态最小化重渲染；避免无意义动画。
  - 图片/文件通过鉴权组件与工具函数，减少无效请求。

## 故障排查指南
- 首次启动报数据库/Redis 连接错误：检查 application-dev.yml 与端口、账号密码。
- 前端请求失败：确认后端端口与 .env.development 代理目标。
- 字典为空：检查数据库中字典数据的 tenant_id 是否为 1（被拦截器过滤）。
- 图片无法预览/下载：使用 AuthImage 与 getFileUrl，避免直接拼接 URL。
- Flyway 迁移失败：检查 SQL 命名、占位符与幂等性；查看 forge_schema_history。

## 结论
Forge Admin 以插件化与 Starter 解耦技术能力，配合前端配置化组件与统一规范，形成高内聚、低耦合的工程体系。遵循本指南的编码、提交、测试与文档规范，结合自动化检查与最小闭环验证，可显著提升交付质量与团队协作效率。

### 开发环境与 IDE 配置
- 环境要求：JDK 17+、Node.js 20.19+、pnpm 8+、MySQL 8.0+、Redis 6.0+。
- 后端：复制 application-dev.example.yml 为 application-dev.yml，配置数据库与 Redis，使用 mvn spring-boot:run 启动。
- 前端：进入 forge-admin-ui，执行 pnpm install 与 pnpm dev。
- IDE：启用 ESLint、Vite 插件、Vue DevTools；Java 侧开启 Lombok/MapStruct 注解处理器。

### 编码规范要点
- 命名：类名大驼峰、方法小驼峰、常量全大写；禁止拼音与中英混拼。
- 异常与日志：业务异常带错误码；系统异常兜底；禁止吞异常；日志不含敏感信息。
- SQL：基础字段齐全；utf8mb4/InnoDB；高频字段索引；禁止模板占位符泄露。
- 前端：字典/图片/操作列按钮/样式层次/可访问性均有明确约定。
