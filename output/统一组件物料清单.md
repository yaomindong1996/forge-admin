# 统一组件物料清单（表单 × 列表设计器取合集）

> 配套文档：《低代码设计器统一改造完整方案》第 8 节的物料全集落地  
> 来源：`FIELD_COMPONENT_PALETTE_GROUPS`（表单字段目录，33 个）+ `listPageBlockCatalog`（列表区块目录，约 60 项）+ `pageWidgetCatalog`（页面挂件目录，20 个），三处取并集去重  
> 日期：2026-09-02  
> 用途：component-spec 注册表的建表输入——每个组件一行，作为 P1 物料协议阶段的实现清单

## 使用说明

- **scope**：F = 表单设计器可用；L = 列表设计器可用。统一后按 component-spec.scope 声明，物料同源、面板按 scope 过滤。
- **别名**：存量 schema 里的历史类型名，进 component-spec 的 aliases 做兼容。
- **通用属性**（所有组件共有，不在各表重复列出）：
  - 基础：组件 id、名称/标题（label）、宽度 span（/24 栅格）、隐藏（visibility.hidden）
  - 样式：背景色、边框、圆角、内边距、自定义 class
  - 交互：显隐条件（表达式规则）、联动规则、事件规则
  - 打印：hidden（打印隐藏）、breakAvoid（不跨页截断）——见完整方案第 9.4 节
- **数据源**：标注该组件支持的数据源类型（对应 DataSourceSpec 七类：static / dict / managed / remote / context / relation / builtin）。
- **容器**：标注"容器"的组件可嵌套子组件（maxDepth=4）。

## 7. 汇总与缺口统计

**组件总数（去重后）：95 个**

| 分类      | 数量 | scope  |
| ------- | -- | ------ |
| 字段组件    | 33 | F      |
| 布局容器    | 10 | F+L    |
| 业务区块    | 12 | F+L 为主 |
| 页面与内容区块 | 16 | L 为主   |
| 媒体区块    | 4  | L      |
| 页面挂件    | 20 | F+L    |

**当前缺口（统一时必须补齐的差异）**：

1. **挂件数据绑定不对称**：markdown/qrcode/rich-text 等 20 个挂件在表单侧有 dataBinding 配置，列表侧仅 15 种区块（stats-strip/tag-list 等）有——统一后**全部挂件两边同权配置**；
2. **字段组件在列表侧无独立入口**：33 个字段组件只出现在表单设计器；列表侧需要时应通过"AiForm 区块/表单资产"承载，不直接铺字段（保持列表页=区块堆叠的心智）；
3. **布局容器反向缺口**：spacer/space/box 布局列表侧有、表单侧无；table 表格布局表单侧有、列表侧无——统一后全部进 scope: F+L；
4. **button 与 action-button、title 与 section-divider 等同义组件**：合并为统一类型 + aliases 兼容存量；
5. **transfer 双重身份**：表单侧是字段、列表侧是挂件——保留一个组件，scope 声明 F+L，字段属性与展示属性并存。

**这份清单就是 P1 物料协议阶段的建表输入**：95 个组件逐一登记 component-spec（type/scope/aliases/propsSchema/container/layout/print/数据源声明），登记完成即得到统一组件库的完整数据源。
