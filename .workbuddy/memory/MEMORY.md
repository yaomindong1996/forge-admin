## 1. 账号与渠道现状
- **头条：账号没有权重问题**（0917 推翻"新号冷启动"诊断）。同号同天同 300 字：数字反差型 **7981 展现/1330 阅读=16.7%**；反常识型 319/15=4.7%，差 25 倍
- **【0918 定论】长文停掉，只发微头条**。微头条 13.4% vs 长文 0.67%，**差 20 倍**。26 篇长文没量的变量就是"长文本身"（微头条正文直铺决策成本低；长文只有标题+缩略图）。长文要发必须配封面，一周 ≤1 篇
- **【0918 定论】一次只发一条，间隔 ≥6h**。单发 7981 vs 同发 528，差 15 倍。账号单时间窗推荐配额有限
- **【0921 定案·推翻 0920 结论】头条天花板已测出：初始池子几百到一千，7981 是一次性红利**。五次单发展现排序 **7981 / 1050 / 528 / 319 / 280，中位数约 500**。7981 = "全新钩子+全新题材+账号刚验证出数字反差型"三因素同时满足的**内容新鲜度红利**，不可复制
  - 0920 的"题材大众可感知度决定天花板"**已被反证推翻**：第 12 条正是按该原则重写的最强大众后果（安全恐惧"密码能一直猜"），结果 **280**，比技术细节型的第 9 条（1050）差 3 倍
  - 第 12 条失败真因＝两变量叠加：①**同一 bug 连写三遍**（6/9/12 条都是账号锁定死代码）→ 系统判重复，528→1050→280 递减；②**首行没数字**（陈述句开头，数字藏第 4 行）→ 点击率 16%→10.7%
  - **定位：从"主攻"降为"日常维护"**。每天 1 条、写完就发、不再复盘，精力占比降到 10%，主战场转掘金。三条硬纪律：**①绝不连续两天同题材（一个技术点只写一条）②首行必须纯中文数字 ③单条、间隔 24h+**
- 发布纪律：发后 2h 内自己补评论 / 所有评论必回 / 记录发布时间测时段。**评论数权重高于点击率**（决定能否进下一级流量池）
- **评论数+点赞数至今一次没记录**（0921 仍是最大数据缺口）
- **掘金**：唯一有正反馈的渠道，有阅读但赞少。系列连载是点赞主要来源
- 演示站可从外部抓取（curl 200 / agent-browser 截图成功），需要素材可直接截图

## 2. 头条写作规则
### 🔥 已验证钩子公式（数字反差型，最高优先级）
1. **第一行必须是纯中文数字，绝不能出现代码符号**（`@Async`/英文类名一律后置）— 第 1 条赢、第 2 条输的**决定性差异**；第 12 条破例 → 点击率掉到 10.7%
2. 数字后紧跟"只干一件事 / 只有 X 行"的极端聚焦
3. 中段必须有「你以为是 A，实际是 B」的反差
4. 后果翻译成**钱/隐私/安全/时间**（"扣了3次款" > "接口慢"）。**【0921 修正】只影响点击率，不影响天花板**——真正的天花板变量是题材新鲜度
5. 结尾必须提问

### 标题
- 30 字内，**禁用圈内黑话**（DHH / Harness / Elicitation 曾致点击率仅 2%）
- 范式：新闻事件名 + 数字 + 后果；大白话 + 具体能力描述
- **踩坑警示型 + 项目名**是用户认可的组合，其余类型不带项目名

### 结构公式
真实故事开头（数字反差/冲突）→ 痛点共鸣 → 拆解 → 算账对比表 → 客观说不足（5 条）→ 反思 → 互动（扣1/扣2）→ 项目地址

### 去 AI 味 8 条（最重要方法论）
开头直接进冲突 / 每段 3-4 句绝不超 5 句 / 口语词（哥们、那天、你猜怎么着）/ 具体数字代替形容词 / 真实踩坑经历开头 / 不用"首先其次最后"改"第一层第二层" / 结尾不升华用提问 / 适度自嘲。**禁用**：赋能、闭环、抓手、沉淀、致力于、旨在

### 已扑街方向（避坑）
故事人物叙事（"同事要离职"）→ 零流量被判职场情感文 / 纯情怀 / 纯观点 / 偏商业 / 源码拆解或介绍性头条文（0826 MCP、0830 横评、0903 项目介绍）/ **每写 5-8 篇必须切赛道**（0921 实证：3 条同题材就触发）

## 3. 掘金写作规则
### 结构公式
动机故事（踩坑起因）→ 设计原则（3-5 个）→ ASCII 全景图 → 核心接口（完整代码）→ 注册中心（fail-fast）→ 模型层 → 真实实现拆解（贴 60-100 行）→ 实战接入（4 步）→ 踩坑（4-5 个）→ 可带走的 N 条诀窍 → 总结 + 下一篇预告

### "有人看没人赞"对策四件套
① 开头玄学 Bug 钩子 ② 坑表四列（坑/现象/根因/解法）③ "可带走的 N 条诀窍"独立小节 ④ 结尾明确求赞 + 赌局式互动。**系列文必须兑现上一篇预告并预告下一篇**。字数 4500-5500（含代码）。标签：`#低代码` `#Spring Boot` `#Java` `#架构设计` `#企业开发`

### 🔥 掘金标题规则（0919 诊断，最高优先级）
- **症状拆两层**：展现→阅读 卡在**标题**；阅读→点赞 卡在**正文没给可带走的东西**。改标题救不了点赞
- **标题模板疲劳是阅读少主因**：「XXX行源码拆解 + N个坑」连用 6 次 → 老读者跳过；**"行数"对读者零收益**且占标题最贵位置；缺可检索技术锚点
- **新三段式 = 具体故障现象 + 技术关键词 + 反直觉结论**（去掉行数）
- **点赞少根因**：读者感受是"他踩坑了，我知道了"——**知道了≠能用了**。赞的本质是收藏
- **0919 结构改版**：①开篇 4 句钩子 + **TL;DR 六条结论清单**（结论从结尾挪到开头，适配扫读）②每坑统一「现象→源码→为什么→怎么改」四段 ③独立「可带走 N 条诀窍」+ 接入实战可复制代码 ④求赞先给联想场景

### 通用可复用硬核事实
- **MyBatis-Plus 3.5.7**；`MybatisPlusConfig` 用 `List<InnerInterceptor>` 注入
- 拦截器顺序是**隐式契约**：都无 `@Order`，靠 `@AutoConfigureOrder` 数字（datascope HIGHEST_PRECEDENCE 先 / tenant +10 后），无顺序断言测试
- `CountOnePaginationInnerInterceptor` 把 `COUNT(*)` 改 `COUNT(1)`，为让两个解析器都能解析深嵌套 SQL
- `_mpCount`/`_COUNT` 是分页 count 后缀；数据权限需剥离后缀才匹配配置
- `TenantContextHolder` = TTL + 保存恢复（可嵌套）；`DataScopeContextHolder` = 普通 ThreadLocal + clear（嵌套覆盖、线程池不传）
- crypto：FPC1 密文格式 `{算法}:{keyId}:{密文}` 五态；`@Desensitize` 8 种策略；四级放行 + 算法三级优先级 + `DecryptedHttpInputMessage` 偷换 body 流
- 操作日志三快照 before/after/diff（V1.0.14 迁移）；`sys_login_log` + 账号锁定
- plugin-ai：`PermissionEngine` 63 行三态判决（工具名含 delete/submit/commit 触发人工审批）；`AiModelInvocationLog` 记 token + 调用时单价快照（按"分"存）

### ⚠️ 待修真实缺陷（17 个，均未修复）
> 完整源码细节见 output/ 下对应掘金文，此处只留索引
1. **【高危】账号锁定密码错误场景完全失效**：`UsernamePasswordAuthStrategy.doAuthenticate` 的 `if (loginUser == null)` 是死代码（认证失败抛异常不返回 null）；`recordLoginFailure(null,...)` 首行即 throw。**暴力破解不会被锁**
2. 死常量 `LOGIN_LOCK_KEY_PREFIX`（只有声明+delete，从无写入）；真正锁定走 `StpUtil.disable()`
3. 计数窗口 15min < 锁定窗口 30min → 解锁后攻击者重获完整 4 次机会
4. 安全开关 fail-open：`loginLockService` 是 `@Autowired(required=false)`，缺失时静默失效无日志
5. "还剩 N 次机会" → 用户名枚举漏洞
6. idempotent `extractToken()` 把 `getRequestAttributes()` 强转成 `RequestContextHolder` → 必然 CCE 被吞 → **TOKEN_REQUIRED 100% 抛异常**
7. **【高危】excel `@Async` 三重叠加失效**（自调用 + protected + 不在接口 → JDK 代理上没这方法）→ 异步导出实为同步
8. idempotent STRICT 的 `annotation.expire()` 是死变量，锁租期固定 5s 且 Redisson 不启 watchdog
9. `cleanupExpiredTasks()` 无调度 → 临时文件 + taskStore 永不释放
10. `downloadFile` 用 `Files.readAllBytes` → 大文件 OOM
11. `dataCount` 死字段（有 getter 无 setter）+ `MockHttpServletResponse` 死类
12. websocket `@Async` 依赖外部 starter（自己无 `@EnableAsync`，靠 api-config/excel/flow 碰巧开启）
13. websocket 无总开关（无 `@ConditionalOnProperty`，引 jar 即开 `/ws` + SockJS）
14. websocket 内存 Broker 无多实例支持 → 推送静默丢失
15. **【高危】config 自动刷新从未生效**：`checkAndRefresh()` 的 `@Scheduled` 是注释状态，而示例类注释谎称"30秒内自动刷新"
16. `ConfigRefreshEvent` 从未发布（发布行注释）→ 无法监听配置变更
17. config 刷新是单机的，多实例只刷被调用那台
