## 第三轮：数据源配置分析 + 表单/列表"两个维度"问题

- 产出第三份文档：`output/组件数据源配置现状分析与统一数据源模型.md`
- 数据源现状：**4 套并行模型**——A 字段 optionSource(STATIC/CURRENT_CHILDREN/REMOTE，无 method/params)、B transfer 专用 dataSourceType(有 method/paramsText 但无 CURRENT_CHILDREN)、C 挂件 dataBinding(static/context/remote，编辑器 UI 两边各写一遍)、D CRUD 接口组(listApi 等 get@ 语法)
- 关键缺口：表单"受管远程选项"实际是手填字符串，enabledApiConfigs(API配置中心)只有列表侧按钮动作用上了；两设计器可绑数据的组件集合不同(dataBindablePageWidgetKeys ≠ localDataBindableBlockTypes，列表侧挂件 markdown/qrcode/rich-text 不能配数据源)；AiFormItem shouldSuppressDesignerRemoteOptions 在设计器预览刻意不加载远程选项→预览下拉为空
- 运行时其实很全(AiFormItem resolveOptionSource 支持 7 类源)，缺的是配置面统一→方案：DataSourceSpec 七类源(static/dict/managed/remote/context/relation/builtin) + DataSourceEditor 通用编辑器作为属性面板引擎首个试点；remote 一律带受管 API 选择器+手工双模式
- "表单在弹窗/列表是页面"问题：用户直觉对(宿主形态不同)，但要纠正为**包含关系非平行关系**(列表编辑弹窗渲染的就是表单资产，代码注释已确认)；分层：内核层(统一)→宿主层(画布参数差异：表单加弹窗/抽屉/整页三档宽度切换，列表整页)→资产层(表单资产被页面引用)
- 累计 5 个待拍板决策：①流式画布 ②右栏Tab ③maxDepth=4 ④DataSourceSpec 统一 ⑤表单宿主宽度切换
